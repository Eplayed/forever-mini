## 二、契约与实现要点

- **hash 路由**（`createWebHashHistory`）：旧站是纯文件部署，history 模式要托管方配 rewrite；迁移期两套页面混着跳，少一个部署前提就少一类线上事故。
- **linkFor / linkForQ 契约**：带 query 的旧站文件链接必须走 `linkForQ` 返回**嵌套** `{to:{path,query}}`——平铺 `{to, query}` 经 `v-bind` 会把 query 掉进 fallthrough 属性**静默丢失**。全库扫描 7 处命中（RaidsPage、ClassesPage×2、ChooserPage、search.js、nav.js×2）全部为正确嵌套写法，无残留。
- **锚点**：hash 模式下 `#` 被路由占用，站内锚点改 click 拦截 + `preventDefault` + `scrollIntoView`（有意差异，见第五节）。
- **内容页只留标题与数据**：`app/src/lib/prov.js` 的 `SHOW_PROV` 总闸等效旧站 `data-page` 总闸——分级徽标 / 来源按钮 / 覆盖率条只在溯源页渲染，对拍正文比对兜住。

## 三、两个真 bug（对拍抓出）

1. **DungeonsPage 35 张地下城卡静默不渲染**：computed `listBands` 产出的对象字段是 `rows`，模板 `v-for` 却读 `band.cards`（undefined，v-for 对 undefined 静默渲染 0 张）。对拍证据：`.loot-i` 旧 1003 / 新 0、img 旧 1186 / 新 1、正文缺怒焰裂谷 + 领主大厅两座卡面 14 行；playwright 探针实况 `dcards=3`（只剩团本 3 张卡，`raidCards` 是独立 computed）而 bands=5 带正确计数。修复 `band.cards` → `band.rows`，修复后 `dcards=38、looti=1003、imgs=1185`。
2. **RaidsPage 开放日期漏「日」字**：对拍文本 diff 抓出 `12 月 09 开放` vs 旧站 `12 月 09 日 开放`，`raidDate` computed 补回 `+ ' 日'`。
3. **副本页卡片头补齐**（同轮）：旧站 `decoratePageHead()` 会把副本页 H1 包进 `.cdhead.big` + `.hicon`（blackrock-depths.webp），新站漏 → 表现为 img 差 1 + 缺 `big/cdhead/hicon` 三个同类名。照 WorldPage 先例补等价结构（图片路径走 JS 常量，防 Vite 静态解析 public 路径）。
