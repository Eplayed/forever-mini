## 一、动手前先量数据，量完改变了做法

`world.json` 里 362 条稀有分布在 41 个区域：

| 查的事 | 结果 | 决定了什么 |
| --- | --- | --- |
| 同一区域内 `mapFile` 是不是只有一种 | 41 个区域全部最多一种 | 一区域一张图成立，不用处理"一个区域两张图" |
| 每条稀有有没有 `mark` 坐标 | 362 条全有，缺 0 | 点位能全部按数据摆 |
| 有多少条**没有** `mapFile` | **73 条** | 这 73 条**不标在图上**，只进列表 |
| 一个区域最多几条 | 33（贫瘠之地） | 点位会密，所以右边那张编号列表不能省 |

那 73 条的坐标是不是同一张图的空间，从数据里确认不了，所以**不猜位置**：
它们只出现在列表里，序号列画一条横杠。这条口径写进组件注释，
并且有一条断言钉着（"多标 0 个／应标 289 个／实标 289 个"）——以后谁把没图的也标上去，门禁会红。

## 二、改了什么

- 新增 `RareMap.vue`：一个区域 = 一张地图 + N 个编号点位 + 一个浮层 + 右边一张编号列表。
- `WorldPage.vue` 的「稀有精英」面板换成它；**每条稀有各带一张同样区域图**那套卡（`.rarecard`）
  和"掉落与坐标"小抽屉一起撤掉，掉落清单整个搬进浮层。
- `coordTxt` 从 `WorldPage` 提到 `lib/fmt.js`（改名 `coordText`），页面与组件共用一份，
  并补了 3 个单测（两个都有 / 缺一个 / 两个都没有）。
- 样式全部写在只由新站加载的 `board.css`，旧站那 19 页不受影响。

**签名动作**：点位平时 `opacity:.55 + blur(.6px)`（虚），悬停/聚焦/点住才实体（去模糊、放大 1.3、填金）；
浮层用点位同一套百分比定位 + 四个方向的翻转，不量 DOM；点位与列表共用序号、双向高亮。

**两个刻意的取舍**：① 浮层 `pointer-events:none` —— 它会盖住自己那颗点位，
能收指针的话鼠标一移上去就触发 mouseleave、浮层闪断；代价是里面的字不能选不能滚，
所以掉落同时写在右边列表那一行，不只活在浮层里。② 手机上点位命中区只给到 34px，
做不到 44px —— 贫瘠之地一张图 33 根针，44px 的命中区会互相压住；
手机上真正的主入口是下面那张列表（行高 60px）。

## 三、踩到的三条，都是"只有看图/只有量一遍才发现"

1. **开浮层会让整排点位往下跳。** 窄屏浮层改成"挂在图下面"之后，它是点位所在那个盒子的子节点，
   一撑高，点位按父盒高度的百分比摆 → 8 个点全体下移。
   修法是加一层 `.zcanvas` 只装地图与点位，浮层做成它的**兄弟节点**：撑高的是外层 `.zbig`，
   点位参照的那层永远等于图高。桌面靠 `position:absolute` 不占位，本来没这问题，是手机这一改暴露的。
2. **门禁自己写错一次**：`click()` 与"查浮层"写在同一个 `evaluate` 里 ——
   Vue 的 DOM 更新是异步的，同一次同步执行里永远查不到，那条断言假红。拆成两次 evaluate 加一次等待。
3. **判据本身也会骗人**：跳位最初用 `getBoundingClientRect` 量，结果"8 个点里 1 个动了"——
   动的那颗正是被点中的那颗，它有 `transform:scale(1.3)`，rect 自己涨 3px。
   改成 `offsetLeft/offsetTop`（只看布局、不吃 transform）才是我要的那个意思。

## 五、没验到的 / 要你定的

1. **真浏览器手点没做。** 悬停实体、点住、ESC、列表反向点亮，这四条都是无头断言量的，
   手感（浮层出现得快不快、点位在密的地方好不好点）要你在浏览器里试。
2. **点位密度最高那张是贫瘠之地 33 个**，本轮只逐位核对了泽风岛（8 个）那一组的悬停与浮层内容，
   没专门给 33 个的那张拍图。要是那张太挤，退路有两条：给点位加"只显示当前筛选/搜索命中"的开关，
   或者按等级分档再切图。
3. **图书馆书籍与睡袋营地那两块还是"每条一张小图"的老结构**（同一个 `ZoneMap` 组件）。
   这轮只按你说的改了稀有精英。要不要一起换成一张图标多点，等你定。
4. 浮层里的掉落**不能选字、不能滚动**（`pointer-events:none` 的代价）。要能选，
   就得改成"移进浮层不关"的延时方案，那是另一套逻辑，本轮没做。
