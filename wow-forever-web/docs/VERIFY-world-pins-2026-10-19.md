## 三、本轮发现并修掉的四个问题

1. **`.zband` 两列把卡片里的地图挤成 0 宽**。区域卡只有 258px，右列固定 330px 之下左列 `minmax(0,1fr)` 收成 0，
   图和点位一起消失。加 `.zband.compact { grid-template-columns: minmax(0,1fr) }`，紧凑态单列。
   这条是**实拍才发现的**——DOM 断言里点位数量是对的，宽度是 0。
2. **只换查询参数不切面板**：`#/world?t=zones → ?t=books` 不换组件实例，而 `tab` 只在 `setup` 时读过一次
   `route.query`。首页搜索跳进来（`?t=rares&q=…`）就撞这条。补 `watch(() => [route.query.t, route.query.q], applyQuery)`。
   新增断言：先 goto `?t=zones`，再用 `page.goto` 只改查询参数到 `?t=books`，必须真的切过去。
3. **`<template>` 与根元素之间写注释 = 多根组件**。ZoneCard 上方那段注释让 `wrapper.classes()` 返回空数组，
   测试里"根节点必须有 .zcard / 必须有 .lk"那两条假绿（`emitted('open')` 那些仍然过，所以只看到类名断言红才知道）。
   注释挪进根 div 里面。
4. **门禁自己的老毛病又犯了一次**：`click()` 与"查结果"写在同一个 `evaluate` 里，Vue 更新是异步的，
   永远查不到点开的那一层。拆成两次 evaluate 加等待。这条 10-15 就记过一次，本轮探针阶段先撞上、改完才进门禁。

## 四、验证方法上的一条口径

点位"跳位"这条判据用 `offsetLeft / offsetTop`，不用 `getBoundingClientRect`——
被点中那颗有 `scale(1.3)`，rect 会自己涨 3px，那是设计要的放大不是跳位（上一轮误报过一次）。
反向验过：人为把画布撑高 120px，8 个点全部被这条抓到。

## 五、还有哪里没验

- **点位落在图上的位置对不对，没有任何自动手段能验**。断言只保证"页面画的这个点的 left/top 等于这条数据里的
  坐标百分比"，也就是**渲染忠实于数据**；至于数据那对百分比本身是不是这张小图的坐标系，要进游戏看一眼才知道
  （这就是 `docs/DATA-MAP-EXPORT-2026-10-19.md` 第一条那一分钟自查）。这一条是本轮交付最大的未知，
  写清楚：**329 个点位的相对位置一致，绝对正确性未证**。
- 8 张缺图的区域卡只验了"画成空态、不裂图、点位仍进列表"，没验过图补上之后的样子。
- 73 条无 mapId 的稀有按"不猜位置"只进列表，**这个决定本身没被验过**：它们是不是真属于那 40 条所在区域的图，
  要等区域 → 地图号对照表。
- 区域卡里三种点位混在一张图上，最密那张（贫瘠之地 33 个稀有 + 别的）在小卡里会不会糊成一团，
  我只能给出实拍（`docs/screenshots/check-2026-10-19/app-world-zones-m.png`），**密度是否可接受要站主用眼睛判**。
- 触屏上的"点一下钉住 / 再点收掉"在桌面 Chrome 里用 mouse click 代验，真机上 tap 与 hover 的差别没验。

## 一处实现决定

`merge-world.js` 里这一层是**补位不是覆盖**：只填前三层（地图 paint / 稀有与书籍分组自带 id / rareRegions）
都查不到的那些。补上的每条带 `mapIdFrom:'xr-zonemap'` 和第二条出处（哪个插件、哪一天抽的），
坐标本身没换，仍是 GI 那份——补的是"这组坐标挂在哪张图上"，不是坐标。
`mapIdFrom` 这个键只在真由 XR 补的那 73 条上出现，其余 289 条不挂 null 键，
免得读数据的人分不清"没来源"和"来源是站内那三层"。

## 顺手修掉三条写死的数

门禁里有三处把"73 条""41 张图"抄进了注释与断言（`bands == 41` 是断言，不是注释）。
条目一变它们就是假绿或假红，全部改成运行时从 `world.json` / `art.json` 现算。
这已经是同一类错在这一条线上第三次犯（前两次：导航说明里的 36 只稀有、体检报告里的 964 条）。

## 这一轮没验到的

- **那 40 条新点位的绝对位置对不对**，仍然建立在"mark 是区域图上的百分比"这个判断上。
  这一轮多了一层互证（XR 自述坐标口径 + 31 条地图号一致），但两份插件的坐标可能同出一个上游，
  算互证不算独立两源。进游戏那一眼还是没做。
- 33 条补了地图号却没图可标的，界面上仍是"只进列表"，**没验过图补上之后它们落在哪、对不对**。
- 旧站 `world.html` 读同一份数据，也跟着多标了点——实测 :8817 稀有面板
  **362 张卡 / 329 个点 / 每张卡最多 1 个点 / 33 处走"没切图"兜底**。
  旧站是"一条稀有各带一张自己的小图"，一张图上永远只有一个点，所以新密度这条不成立，
  已经实测掉了（我原本担心"点会不会叠在一起"，那是新站的形态，不是旧站的）。
  旧站界面一行没改，这是数据流下来的结果。
