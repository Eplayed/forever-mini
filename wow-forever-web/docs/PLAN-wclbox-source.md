# 无限数据库（wowforever.wclbox.com）接入评估与落地顺序（wow-planner + wow-data · 2026-10-08）

状态：**三件事已拍板（2026-10-09）**，见文末"决策结果"。P1 地下城已落地；P2 专业 / 任务、P3 世界地图、P4 首页动态与排行待做。

## 一、这个站是什么（2026-10-08 实测）

- 站名：新手盒子 · 魔兽世界无限数据库，`https://wowforever.wclbox.com/`，中文站（有 English 切换）。
- 自述口径（首页原文）：**"天赋、法术、物品、地下城和整张世界地图，都直接从无限测试版客户端读出，再逐条与经典旧世对照。"**
- SEO 描述里明确含"职业改动、天赋、法术、物品、专业配方、**地下城掉落**与**世界地图**"。
- 脚本可访问，服务端渲染：`curl` 首页 200 / 97.9 KB，`/renwu` 200 / 102 KB，`/fuben/hall-of-thanes` 200 / 92.4 KB；HTML 里直接能看到物品链接（`/wupin/274289` 矮人的篝火）与 BOSS 锚点（`#durgen-dirgehammer`、`#faldrim-anvilmar`、`#loot`、`#quests`），**不需要浏览器就能取数**。页面带 schema.org JSON-LD。
- 全站 267 张图都在它自己域名下（例：`/jiemian/custom/classes/warrior-<hash>.webp`），即它把客户端界面素材转存了自己托管。

## 三、接入它必须先定的一件事：数据分级

我们现在的分级是 L0 官方中文已核 / L1 仅官方英文 / L2 待实测 / L3 缺数据，红线写的是"非官方来源不得进正文"。这个站的中文名来自**客户端解包**——它比任何机翻和转载都接近游戏内实际显示的名字，但它仍然是第三方，我们无法独立验证它的解包有没有错、有没有改字。

建议加一档，不推翻现有规则：

- **L1.5 客户端解包中文名**：来源写清是本站解包转述；界面显示"客户端解包"而不是"已官方核实"。
- 与官方中文稿**一致** → 升 L0，两个来源都留着。
- 与官方中文稿**冲突** → 两个都留（现行规则不变），并把冲突记进 `conflicts`。
- 只有它一家有、官方中文稿从没提过的条目 → 停在 L1.5，**不升**。
- 它的**描述文案、攻略文字、BiS 结论、排行**一律不搬（红线）；只搬名称、ID、图标文件名、等级区间、掉落归属这类事实性标识符。掉落**仍然不写百分比**。

## 四、素材边界（图标可以，原画要点头）

- **56 图标**：走已建好的 `tools/fetch-icons.py`，只从暴雪官方 CDN 取，本地留存，禁止热链。今天实测的边界：新技能图标 CDN 有（`ability_hunter_pathfinding` 200），新物品图标 CDN 没有（`inv_camelot_camping_welcomingcampfire` 403），天裔种族图标两边都没有 → 继续自绘。
- **客户端原画**（职业天赋背景图 `/jiemian/custom/classes/*.webp`、副本载入图、世界地图底图）：这些是暴雪游戏美术，目前**只有第三方站托管的副本**，官方 CDN 不提供。要用就等于把游戏原画放进我们仓库并公开展示。现行红线是"不许用真实游戏原画或第三方站图片"，且素材要避开商标词。**这一条必须你点头，并沿用 `img/icons/manifest.json` 那种"整目录删掉即可回退"的下线方案。**

## 五、建议的落地顺序（每期一个可验收的产出）

1. **P1 地下城改造**（价值最高、风险最低）：35 本名单 + 等级区间 + 新本标记 + 每本 BOSS 名单与掉落归属（物品名 + ID + 图标键），BOSS/掉落从"0 条"变成有内容，全部标 L1.5 并带来源链接。副本图要不要用取决于第四节。
2. **P2 专业 + 任务**：十二专业与新配方、按地区的任务列表。这两块是纯结构化列表，最适合"复刻"，且不碰攻略文案。
3. **P3 世界地图**：3 块新区域 + 稀有/书籍/睡袋。依赖原画决策；不用原画的话可以做成"区域列表 + 文字坐标"，但价值打折。
4. **P4 首页与角色**：首页不做新闻流，改成**本站数据变更日志**（由数据文件生成"今天新增了什么、还缺什么"），既满足"有东西在更新"又不碰红线；角色页只做种族/传承/30 级成长，**不做排行榜**（红线：不做强度排行）。
5. 全程：每期跑 `build-data` + `site-check` + `audit-translations`，来源页与抓取时间写进 `provenance`，新增来源类型 `datamine_cn`（客户端解包）并纳入域名一致性卡口。

## 六、需要用户拍的三件事

1. 是否新增 **L1.5 客户端解包中文名** 这一档，让 wclbox 从"人工参照"升级成可入库源？（不点头就只能继续当线索，BOSS/掉落/专业/任务都进不了正文。）
2. 是否允许把**客户端原画**（职业背景图 / 副本载入图 / 世界地图底图）转存进仓库并展示？（现行红线是不允许。）
3. 首页"最新动态"和"角色/排行榜"这两个撞红线的，是**改红线**还是**按第五节的替代方案做**（变更日志 + 不做排行）？

## 七、决策结果（2026-10-09 用户拍板）

1. **数据分级**：客户端解包中文名**直接算 L0**，不另立 L1.5。落地时保留两条机器可验证的护栏——① `datamine_cn` 来源必须带 `url` + 抓取日期，界面"来源"能点开看到是哪个站转述的；② `tools/audit-translations.py` 把 `datamine_cn` 纳入逐字回查，26 条"结构问题"清零、命中 287 → 320。
2. **客户端原画**：**网页与小程序都用**。已转存 9 张职业背景图 + 5 张副本载入图到 `src/img/art/`（manifest 记来源与抓取日期，整目录删除即回退自绘）。小程序侧注意：这些图**不能打进主包**，要走 OSS `wow/{env}/v1/`，而 OSS 上传链路还没建 → 小程序用图排在 P4 之后。
3. **红线**：更新动态与职业排行**只在网页放开，小程序仍不做**。已改写 `AGENTS.md` 第五节。

一处没有跟着升到 L0：**掉落归属**。上游自己写明"谁掉落什么取自经典旧世的开放数据库，暴雪说过无限服重做过掉落"——这不是客户端解包出来的事实，所以掉落保持 L2 待实测，并加了"掉落标 L0 直接构建失败""正文出现百分比直接失败"两条卡口。
