## 四、三个可落地的版本（工作量与前置都写清）

### A 「按部位查装备」——纯事实，不越线，今天就能开工

选等级段 + 部位 + 护甲类型，列该段位所有装备：图标、名称、装等、需要等级、品质、属性行、与经典对照状态。
**页面不对"哪件最好"作任何判断**，所以不碰 BiS 结论那条线。
数据全现成（上表那些字段），改动量：一个新数据视图 + 一个路由 + 断言 + 实拍，约一轮。
缺点：它不是站主要的那个"配装页"，更像物品库的部位切片——**物品库已经有了**，价值有限。

### B 「本站整理的部位推荐」——有"推荐"，但依据是我们自己算得出来的

每个部位按**写得出依据的规则**排序，例如：同一等级段内按装等降序 → 同装等按品质 → 有掉落来源的排前面。
页面顶部固定一句"这是本站按装等与可得性排的，不是强度排行，也不是官方或模拟计算结论"（沿用排行那条口径）。
"装备可以替换"这一条能实现：同一部位并列前 N 件，点开设替代，**依据是数而不是人脑判断**。
**前置：必须先解开放项 18**（把 wclbox 的 srcNpc/srcZone 落进成品），否则"来源"列 92.7% 是空的，
推荐也退化成"装等最高就是最好"——那是玩家一眼能看穿的假推荐。
工作量：开放项 18（数据 + 抽屉改造）约一轮，配装页本身约一轮。

### C 「照参考站做 38 套 + 3D + 模拟器」——要站主同时改三条，且 3D 仍做不出来

需要站主明确写：① 允许取第三方 BiS 名单（等于撤销红线第 1 条里"BiS 结论"那半句）；
② 放开配装模拟器；③ 定 3D 素材来源（客户端解包模型怎么拿、能不能存我们仓库、走不走 OSS）。
①②是决定，③是**没有可行路径**——除非站主那台装客户端的机器上能导出模型并且他承担版权风险，
否则我只能做 **2D 纸娃娃**：10 个部位槽 + 真实物品图标（97% 有本地图）+ 点槽位换装备。
纸娃娃能覆盖"装备可以替换"这个交互，只是没有旋转的人物。
