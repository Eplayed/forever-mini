## 一、这一阶段要解决的问题

站内现在有 18 个旧页面 + 20 个新页面，但**各板块的"资料厚度"不一致**：物品库刚做完全量（20,528 件有详情），
副本有 396 条任务，专业有 1,990 条配方；而技能只有 86 条、成就一条没有、稀有只有 36 条、
套装/猎人宠物/降级施法/团队增益这些参考站明摆着有的东西我们一页都没有。

开服前玩家要来查，**查到什么取决于板块是否补齐，不取决于页面漂不漂亮**。
所以这一阶段的产品目标只有一句话：**把"源里有事实数据、红线内可入库"的板块全部做到有内容、有出处、可验收**，
然后站主按这份 PRD 的数字逐页过一遍，签字放行小程序。

## 二、北极星与验收口径

**北极星（本阶段唯一主指标）：对齐度 = 已补齐的 P0 板块数 ÷ P0 板块总数，目标 12/12 = 100%。**

辅助指标（每条都在页面上有读数，站主验收时逐条对数）：

| 指标 | 现在 | 目标 | 怎么算 |
| --- | --- | --- | --- |
| 物品详情覆盖 | 20,528 / 21,077 = **97.4%** | 维持 ≥95% | `items-detail.json` ÷ 名录 |
| 技能/法术条目 | **86** | **≥420** | 成品条数，逐职业九系齐全 |
| 成就条目 | **0** | **≥211** | 成品条数 ÷ 源侧自报数 |
| 稀有怪条目 | **36** | **≥338** | 两家合起来的去重数；两源重合的那 12 只逐字比对，其余按单源 L1 |
| 副本任务 | 396 条 / 30 座 | 维持，缺的显示"没有副本任务" | 已定 |
| 可核验率（L0 占比） | 366 / 369 = **99.2%**（发布口径条目） | ≥95% | `scale.json` 的 `pubCoverage` |
| 门禁 | 整站 **664/664** | 只增不减，新增板块每条都要有断言 | `site-check.py` |

**验收怎么算过**（站主做一次就行，不用天天对代码）：
① 我出一份《板块对账表》——每行"板块 / 源侧条数 / 站内条数 / 差多少 / 差的为什么不能补"；
② 你在浏览器按导航逐页走一遍（约 20 分钟），每页只看三件事：有没有内容、数字对不对、点"来源"能不能看出是谁给的；
③ 差值必须逐条有解释，**不接受"漏了"**。

## 四、"以插件为准"这句怎么落地（需要你确认，见 §六 Q1）

你说"数据源根据插件的数据来确定"。这句话有两种读法，**结论差别很大**，我不替你选：

- **读法 A（选题以插件为准）**：哪些板块值得做、做到什么颗粒度，看插件里有哪些表
  （`spells` / `achievements` / `rares` / `tier` / `DungeonQuestData` / `Data_QuestDB`）。
  取值顺序仍按"谁最新谁优先"。**这条与上一轮已上线的物品层级不冲突**，也是我建议的默认。
- **读法 B（取值也以插件为准）**：属性/卖价/数值优先用 GI/XR 的值，wclbox 只兜底。
  这条会把 10-16 刚上线的层级反过来——而实测证据是：GI 停在 beta 69876（10-03）、XR 停在 09-20，
  wclbox 是 **1.60.1.70374**；同一件装备两边数值确实不同（硬根法杖 44-67/每秒 16.8/+8 精神
  对旧稿 36-54/每秒 13.6/+9 精神+20 法术强度）。**按 B 就等于把旧 build 的数当权威发给玩家。**

**2026-10-16 站主已答：选 B（取值也以插件为准）**。上一句"按 A"是本轮开工前的默认，现作废。
反转后的实测代价写在这是为了以后不靠记忆吵架：属性件数**不变**（19,605 件，因为只有插件两份都没有
的 5,974 件才落到解包兜底，含无限新增 1,374 件），但**11,250 件的显示值换回插件那套**，其中与当前 build 数值签名真的不同的 **1,701 件**已进 `meta.conflicts` 留档；卖价同样反转（XR 12,433 件优先，wclbox 兜 3,033 件）。
取值顺序现为 **GI（Beta 实测转述，build 69913/69876）> XR（社区稿，09-20）> wclbox（当前解包，70374）**。

原默认（未采纳）：**按 A**，数值一律以"当前测试版客户端解包（wclbox 转述）"为第一优先级，
插件源用来 **① 决定该做什么板块 ② 补 wclbox 没有的字段（成就、法术、坐标、出处）③ 当交叉核对的第二把尺**。
若你要 B，物品线要重跑一次合并（脚本已参数化，成本一轮），我按你的选择改本 PRD 的结论。
