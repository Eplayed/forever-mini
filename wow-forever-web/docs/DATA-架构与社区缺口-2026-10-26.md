# 数据架构、来源与社区资料缺口（2026-10-26）

**本轮角色：wow-data。状态：已定（本地结构、当日可核数量、来源边界）；待核（社区条目级差集与新增专题字段的可信度）。交接给：wow-pm。**

## 一、先说结论与比较范围

本站是**文件型静态资料库**，不是在线数据库服务。`app/data/` 是网页和小程序的唯一成品基底；`app/data/upstream/` 是可重抓的来源快照，页面不直接读它。今日按 `wow-forever-web/app/data/`、`tools/refresh.sh`、`tools/data-status.py`、`tools/data-recon.py` 和新手盒子公开页面/API 对照。社区比较以 [新手盒子](https://wowforever.wclbox.com/) 为主，另把 [wowclassicforever.info](https://wowclassicforever.info/) 与仓库已有的 Wowhead Forever、GI/XR 插件快照当交叉证据；**网页栏目数不等于游戏事实数，也不等于本站应该全部复制**。

截至今日，对方公开物品 API 报客户端 `1.60.1.70532`、21,421 件、构建日 2026-10-26；本站名录仍是 10-22 的 21,296 件，差 **125 件**。10-24 曾逐 ID 核实当时对方独有 125、本站独有 0；10-26 **只复核总数，未重做全量 ID 差集**，所以不把旧差集当今日永远不变的名单。本站的世界与改动清单已在 10-26 刷至 `70532`，改动 967 条与对方当日公开 JSON **逐 ID、名称、改动类别一致**；不能再沿用 10-24 “有六处不同”的旧结论。

## 二、现有数据流与目录职责

```text
官方中文公告 ───────────────────────┐
新手盒子等客户端解包转述 ───────────┤
GI / XR 插件、Wowhead、Wago DB2 ──┼─→ 抓取/抽取 → app/data/upstream/*.json
本站本机客户端导出 ─────────────────┘                 ↓ 逐字段选源、保留分歧
                                           tools/merge-*.{js,py}
                                                     ↓
                                  app/data/*.json、talents/、talent-text/
                                                     ↓
                     build-data.js / audit-translations.py / build-icon-map.py
                        ↙                                     ↘
        app/public/data → Vite dist（网页）        export-mini.js → OSS 批次 + 小程序快照
```

当前 `app/data/` 顶层 32 份 JSON、`upstream/` 58 份快照（其中 wclbox 24、两家天赋站各 9、GI 6、XR 6，另有 Wowhead/DB2/客户端导出）；图像另在 `app/img/`，由 `manifest.json` 和 `art.json` 登记。`scale.json` 是派生规模/逐板块版本表，`search.json` 是派生搜索索引，`icons.json` 与 `icon-gaps.json` 是图标映射/缺口登记。`releases.json` 和 `guide.json` 属于本站人工内容，不是外部原料。构建副本 `app/public/`、`app/dist/`、小程序 OSS 批次都不能当编辑源。

**主键/关系现状：** 物品名录用物品 ID，`items-detail.json` 用相同 ID 作字典键；配方、BiS、掉落通过物品 ID 关联。天赋节点与法术/改动有自己的 ID/职业键。副本用 slug，`dungeon-quests.json` 按副本 slug 分组，**396 行任务没有一行保存 quest ID**，目前只能靠名称等弱键对账；这是将来接全域任务库的第一道结构问题。素材通过 `iconKey` 或 `art.json` 路径索引，不从第三方热链。

## 三、来源优先级与可信度

| 来源 | 当前主要用途 | 不可越过的边界 |
| --- | --- | --- |
| 国服官方中文页 | 种族、职业技能四态、术语、正式口径 | 逐字核中文名；未发布的圣骑士深度解析不能猜。 |
| 本机客户端导出 | 客户端原画/少量原始数据的本地证据 | 有文件与版本不等于中文名已获官方核实。 |
| GI / XR 无限服插件 | GI 稀有、成就、物品属性/出处；XR 物品卖价、专业配方来源、任务/地图交叉证据 | 最新插件明确给出的物品属性优先：GI 属性、XR 卖价、GI 出处；两份插件可能同源，不自动当独立互证，也不自动升 L0。 |
| 新手盒子 | 物品名录/详情、法术、副本、世界、改动、传承、BiS 与公开专题 | 一般只取名称/ID/等级/坐标/图标文件名/归属等事实字段；不搬描述或攻略。BiS 名单仅按已批准的窄例外，整体 L1。 |
| fengshen / nieyi | 九职业天赋格位双源对齐 | 中文译名分歧双存，不能仅凭“两家一样”升官方档。 |
| Wowhead Forever / Wago DB2 | 英文名、ID、排队人数/区间、副本任务交叉核对 | Wowhead 不能给国服中文；Wago 是客户端表转述，不等于暴雪官方中文页。 |
| 官方 CDN / 合规留存素材 | 常规图标、经批准的客户端原画和插件地图 | 禁热链；原画与示意图分开标 `origin`，逐图 manifest 与整目录回退。 |

外部来源版本、本站核对日期和成品生成日期必须分开看。`scale.dataVersions` 今日只登记 **7 个板块**（世界、传承、排队表、改动、物品名录、素材、配装），按 7 天提示/14 天拦红；**天赋、法术、物品详情、专业、副本任务、成就尚未进入这张逐板块过期表**。`data-status.py` 今日还报三份原料超过 14 天未重抓：`wclbox-dungeon-meta.json`、`wclbox-dungeons.json`、`wclbox-professions.json`，均为 10-11 快照。`refresh.sh` 有 world/changes/prof/dungeons/bis/legacy/talents/official/art/icons 场景，**没有 items、items-detail、spells、dungeon-quests、achievements 的同级一键刷新场景**；这几条线更容易只改一次就停住。

## 五、给 wow-pm 的数据侧交接

1. **已定、可直接派数据审计：** 物品名录的 125 净差先用公开 API 现读 ID 集合，出新增/移除/字段变动清单；只合已核事实，不触插件优先的属性。对方公开接口只读、免登录，文档限每 IP **5 次/秒**、列表上限每页 100，按限流和来源引用执行。
2. **待核后再定范围：** 全域任务先取 20 条样本（新区、职业、新本、经典区各覆盖），确认 quest ID、阵营、前置、奖励 ID 的取得方式及独立回查来源；本站原有 396 行任务先补稳定 ID 对照方案。猎人宠物先分“经典数据/无限新增/源站意译”，PvP 先分可核客户端字段与未实测规则。是否做页面由 wow-pm 决定。
3. **维护债优先收口：** 将未纳入 `scale.dataVersions` 的大板块补入逐板块版本/核对日；补 `items` 等缺失的可复跑刷新场景；修 `data-recon.py` 的旧解释。`data-status.py` 已报的三份超期原料应重抓，**不能只把日期改成今天**。
4. **明确不做的数据：** 掉落百分比、自算 DPS/强度、循环提示、第三方攻略正文/描述、无出处宏/WA、未核中文机翻名。素材缺图按现有 manifest/占位规则处理。

本轮只审计与写交接文档，未改业务 JSON、页面或小程序。外部参照：[新手盒子任务](https://wowforever.wclbox.com/renwu)、[猎人宠物](https://wowforever.wclbox.com/lieren-chongwu)、[PvP 军衔](https://wowforever.wclbox.com/junxian)、[专业](https://wowforever.wclbox.com/zhuanye)、[公开物品 API](https://wowforever.wclbox.com/api/open/v1/docs)、[第二天赋站](https://wowclassicforever.info/)；每条线上数字以 2026-10-26 访问结果为准。
