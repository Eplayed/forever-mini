## 二、这一轮真正改掉的四个解析毛病（不修就是 21,077 件脏数据）

1. **两块对照 tooltip 扫成一串**。每件物品页面是 `.wp-pair` 下两个 `.wp-tip`（经典怀旧服 1.15.9.70003 /
   无限测试版 1.60.1.70374），试采版按可见文本行位置取数，把两边并成一条列表——
   评估文档里"双方都有属性的 106 件行集 100% 不一致"就是这个造成的，不是数值全改了。
   现在按 `.wp-label` 切边：无限侧整条留，经典侧只留 `wp-del` 标出的改动行，
   无限侧改了什么记在 `foreverDiff`。
2. **名称取行错位**（争战手套那类取到「›」）。这份不取名，名称一律以 `items.json` 名录为准。
3. **来源那一节是 `<p class="wp-drops">` 不是 div**，写错标签后一条都没取到——
   跑到 1,600 件才发现（`有来源 0`），全量重跑，那 17 分钟作废。修好后 11,447 件有 `srcNpc`、11,260 件带 `srcZone`。
4. **上游自报状态是五种不是四种**：`wp-status-held`（客户端保留了这件的数据行但没有属性，
   页面这时显示经典侧提示框）。它和 `missing` 一样不能当无限的数值用，
   记录里打 `tipIsClassic`，合并层两类一律排除。实测 1,334 missing + 610 held = 1,944，
   与名称索引的 `missing: 1944` 正好对上。

## 四、差点把有用的东西改没了（内容倒退，本轮内修掉）

按客户端自己的分类把 `.wp-flavor` 丢掉之后，抽样发现**图样/秘典/公式/设计图这类件的教益句
（"教你学会制作鬼纹腰带。"）也在同一个斜体框里**：参考站标成风味句、插件源整句带引号抄回，
两头一扣，1,197 件的详情只剩"需要工程学 (125)"这一行——比 2026-10-14 那版还少一句关键话。
所以按内容分家：**教益句（教你 / 学会 / 可启动）单独进 `use` 字段、单独成段、单独标来源**，
纯风味句（"相信我，她会明白的。"）仍然丢。成品里 1,207 件带教益句，整行引号的文案 0 条。
这一版 `use` 只能按 实测 → 社区稿 补（本轮快照没带这层）；抓取脚本已改成下一轮按 build 重抓时
自己从解包里带上 `use`，那时合并层就换成解包优先——这条记在开放项里。

## 六、门禁加了什么

`tools/build-data.js`（数据层）：`stFrom` 允许 `wclbox`、新增 `sellFrom` / `useFrom` 白名单；
`use` 必须是不带引号的一句话；**整行被引号包住的风味句直接构建失败**（句中引号放行——
"使用：为角色解锁“炼金师”头衔"这类是功能文本，一刀切会误删）；
名录标「无限中没有」却按无限解包取属性 → 失败；`meta.counts` 的
`total / st / sell / stWb / use` 五项与实际逐条对数；旧版两份源的成品会明确报"没跑 W2-3 全量"。

`tools/site-check.py`（页面层，+11 条）：三态徽标各自抽一件真打开核对文字与行数；
三份来源在页面上都还有人看得见；`meta.pageNote` 确实渲染进抽屉；无限中没有的件不冒充无限解包（数据层 + 页面层各一条）；
教益句按数据原样显示且标明来源；成品里 0 行整句引号（并区分"句中引号"允许）；
反向钉住旧说法"两份客户端数据"不再出现在正文。
