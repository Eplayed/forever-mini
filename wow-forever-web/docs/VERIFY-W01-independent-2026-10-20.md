## 必须修正一：图标检查仍会误放行（P2）

位置：tools/build-icon-map.py:59–64、192–196；app/src/lib/glyph.js:50–51。

临时目录隔离夹具：本地有 valid_icon.jpg，icon-gaps.keys=[]；每次仅放一个成品字段。没有修改真实资料或图片。

| 成品 iconKey | 当前 check_gaps 返回 | 应当 |
| --- | --- | --- |
| valid_icon | 0 | 0 |
| valid_icon. | 0 | 非0 |
| valid_icon.jpg | 0 | 非0 |
| bad/key | 0，同时打印非法键 | 非0 |

原因有两层：扫描器先去后缀/尾点，把本应非法的 iconKey 当成合法；渲染器却直接编码原键并追加 .jpg，两者并不一致。其次 bad 数组仅打印，不参与返回码。于是这次刚修掉的尾点问题仍可能再次绕过这道门禁。

修法：明确字段语义。成品 iconKey 必须是可直接供渲染器使用的规范键，不能在校验端悄悄修正；icon 文件名字段允许现有生成器认可的文件名归一规则，二者分开处理，不能把合法文件名全部误杀。非法非空 iconKey 必须让 --check 失败并给文件/字段位置。生成模式也应先校验再写，遇到非法键失败且不产出半套登记。保留缺图集合精确双向比较，不扩白名单、不修改渲染器掩盖坏数据。

## 必须修正二：截图子流程失败仍返回成功（P2）

位置：tools/route-smoke.py:run / take_shots / shot。

源码确认：shot捕获异常后只追加“没拍成”字符串；run只依据路由fails返回退出码。--only-shots跳过路由后仍打印“路由26条”，即使截图失败也可能rc0。黑暗启发检查只生成文本，ok:false也未成为失败条件。此项为代码审阅发现，本轮没有人为制造浏览器崩溃。

修法：路由与截图分别累计 executed/failed；请求 --shots 或 --only-shots 时，要求的截图失败、关键图标解码失败、目标行不存在都让最终退出非0。继续拍其他场景是对的，但最后不能抹掉失败。--only-shots明确写路由未执行；桌面与375分别断言。无截图参数时保持普通路由冒烟行为。加可隔离的失败注入测试（模拟截图异常、断言失败、全部成功），不要在真实资料中制造缺图。
