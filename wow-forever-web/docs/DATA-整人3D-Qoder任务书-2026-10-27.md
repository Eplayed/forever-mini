## 可直接复制的提示词

你在一台 Windows 电脑上执行一次**只读客户端、只导出两个人物模型**的验证。请把自己当成数据核验员：每个“成功”都要有可回看的文件或截图，缺证据就写“未验证”。完成后把结果包留给另一台 Mac 复核，**不要继续批量导 38 套、不要改网站代码、不要发布或上传游戏模型**。

### 背景与本轮唯一问题

客户端路径是 `C:\GAME\World of Warcraft\_forever_\`，属于《魔兽世界：无限》Forever 测试客户端。我们已有配装推荐的逐槽物品 ID，想做**整套装备穿在人物身上的、预先导出的可旋转 GLB**。旧调查只找到部分装备的独立 `.m2`，这不能说明胸甲、裤子等身体贴图不能渲染。请检验现成工具能否从这个客户端正确生成带装备的整人 GLB。

优先试官方开源工具 [Kruithne/wow.export](https://github.com/Kruithne/wow.export)。其 [CHANGELOG](https://github.com/Kruithne/wow.export/blob/main/CHANGELOG.md) 已记：0.2.4 支持角色 GLB 导出、0.2.7 支持在角色上预览和导出装备、0.2.8 支持替换装备、0.2.9 修过装备渲染顺序。请使用 **0.2.9 或更新版**；如果本机未装，从项目官方入口取得，并记录实际版本与下载 URL。它支持常规 Retail/Classic，不保证能识别这个 Forever 分支，**不要把工具功能声明当成本机实测结果**。

### 工作边界

1. 对 `_forever_` 只读；不要修改游戏目录、配置、热更文件或 listfile。输出一律写到其同级：`C:\GAME\World of Warcraft\ziliao-export\character-probe-2026-10-27\run-YYYYMMDD-HHMMSS\`。如果父目录不存在可新建；不要在 `_forever_` 下建输出。
2. 不要导全客户端、全量 DB2、全部 M2/BLP，也不要抓对标网站的 GLB。第一轮最多导出 **A/B 两份整人 GLB、四张正背面截图、日志和小型清单**。
3. 不要上传到公网、OSS、GitHub 或资料站，也不要改变本站 `app/img/models/` 的 `self-generated` 门禁。这一轮仅做私下核验，公开下发另有项目规则 #104，尚未决定。
4. 不要为完成任务猜物品 ID、猜 DB2 列序或用“看起来相近”的替代装备。工具若使用在线 CDN 回退，请记录是否发生；不能悄悄把别的 build 的资产算作这份客户端的证据。

### 执行顺序

**第 1 步：记录环境并开客户端。** 记 Windows 时间、wow.export 版本、工具实际选中的本地路径、工具显示的产品/build/语言。预期历史 build 为 `1.60.1.70532`，若电脑已更新，以实际值为准并明确标“与原调查 build 不同”。先尝试选择 `_forever_`；若工具 UI 要求安装根目录，按提示选 `C:\GAME\World of Warcraft\`，但最后必须确认实际读取的是 `_forever_`。若无法识别客户端或卡在解码/加密/DB2 错误，保存完整原始日志与截图，标 `BLOCKED_CLIENT`，**停手**，不要自行扩表或切到 Retail 模型冒充成功。

**第 2 步：固定人物。** 在 Characters 里选**人类男性战士**。固定皮肤、脸、发型、发色、体型、站姿，记录工具给出的所有自定义编号；如 UI 只显示文字/滑杆，就截图并保存角色配置文件（若工具支持）。前后两次导出必须使用**同一个人物设置、同一个镜头角度、同一套除胸甲外的装备**。

**第 3 步：按 ID 穿本站战士 PvE 联盟套的可见装备。** 不需要装项链、戒指和饰品，因为它们不直接显示在人物身上。逐项搜索、装备并登记结果：

| 槽位 | item ID |
| --- | ---: |
| 头 | 7915 |
| 肩 | 2278 |
| 背/披风 | 14593 |
| 胸 A | 1488 |
| 手腕 | 4438 |
| 手 | 3341 |
| 腰 | 250556 |
| 腿 | 250523 |
| 脚 | 4464 |
| 主手 | 280604 |
| 远程 | 9456 |

对每一格登记 `requestedItemId / 工具实际选中ID / 显示名称 / 是否找到 / 是否在角色身上可见 / 错误`。只按 ID 判，不按中文名近似匹配。若非胸甲的某件找不到，记录并在 A/B 都保持该格同样空缺，仍可测胸甲，但最后只能报“胸甲链通过，整套未通过”。若胸甲 1488 本身找不到或无外观，停在 `BLOCKED_CHEST_A`。

**第 4 步：导出 A。** 穿胸甲 **1488**，保存同视角 `A-front.png`、转到背面后 `A-back.png`，再导出带贴图的整人 `A-chest-1488.glb`。若工具能保存角色预设，一并保存。记录预览中胸甲、裤子、鞋、肩、武器、披风有无白块、漏贴图、浮空或错位。

**第 5 步：只换胸甲，导出 B。** 用同套备选中的胸甲 **2870** 替换 1488，其他设置一律不动。若 2870 在客户端不可用，可改用 **250518**，但在文件名和记录中写真实替代 ID。保存同视角 `B-front.png`、`B-back.png`、`B-chest-<真实ID>.glb`。如果两件胸甲都不可用，记录 `BLOCKED_CHEST_B`，不要找第三件任意胸甲凑数。

**第 6 步：检验导出的不是“裸人”或坏 GLB。** 请先在 wow.export 预览里对比 A/B：**胸口的纹理或轮廓必须明显随胸甲 ID 改变**，其他部位保持一致。再用本机已有的独立 GLB 查看器打开两份（例如已安装的 Blender；不要为了此项安装来源不明的工具），确认人物、贴图、肩和武器都在，并从正反面各截图。若没有独立查看器，照实记 `EXPORT_VISUAL_NOT_VERIFIED`，把两份 GLB 交给 Mac 复核，不能自报完全成功。文件字节不同不算视觉验证；工具预览正确但导出 GLB 缺装备也算失败。

**第 7 步：做可复核结果包。** 在同一输出目录保存：

```text
README.md                 本轮结论、失败/未验项、工具操作经过
RESULT.json               结构化环境、逐槽物品、A/B 判定和文件清单
item-resolution.csv       每格 requested ID、actual ID、找到/可见/异常
A-front.png
A-back.png
B-front.png
B-back.png
A-chest-1488.glb           若导出成功
B-chest-2870.glb           或 B-chest-250518.glb，按真实 ID 命名
viewer-*.png              若独立 GLB 查看器可用
tool.log                  工具日志或错误原文；没有日志写明
character-preset.*        工具能保存时才有
```

`RESULT.json` 至少写：`status`（`PASS` / `PARTIAL` / `FAIL` / `BLOCKED_CLIENT` / `BLOCKED_CHEST_A` / `BLOCKED_CHEST_B`）、`clientPath`、`clientBuild`、`clientLocale`、`toolName`、`toolVersion`、`sourceMode`（本地/在线回退/不明）、`character`（种族性别和外观设置）、`equipmentA`、`equipmentB`、`observedChestChange`、`unchangedParts`、`missingParts`、`exportVisualVerified`、`files`（交付文件的相对路径、字节数、SHA-256；**不要把 RESULT.json 自己列进哈希清单**）。可用 PowerShell `Get-FileHash -Algorithm SHA256 <文件>` 逐个算哈希。最后把输出目录压成一个 ZIP，并**对 ZIP 本身**算 SHA-256；把 ZIP 路径、字节数和哈希写在 ZIP **外面同级**的 `PACKAGE.txt`，避免文件把自身哈希写进自身造成循环。不要把整个客户端或工具安装目录打包。

### 判定与汇报格式

- `PASS`：本地 Forever 客户端能加载；A/B 两件胸甲均按 item ID 找到；整人 GLB 都能离线独立打开；正反面胸部确实变，其他装备稳定；全套列出的可见格均正确显示。只代表此人物和这两件胸甲，不代表 38 套都通过。
- `PARTIAL`：胸甲 A/B 的视觉变化和导出已证实，但其他格缺件、独立 GLB 未验、或发生在线资产回退。逐项写清。
- `FAIL`：工具可加载，但换胸甲后预览或导出外观不变、GLB 坏、贴图/附件严重错误。附原图与日志。
- `BLOCKED_*`：在加载客户端或找胸甲环节就停住。写完整错误和最后完成的步骤。

结束时只回答：**状态、客户端 build、wow.export 版本、A/B 胸甲实际 ID、四格关键观察（胸部是否变化/附件是否稳定/GLB 是否独立可开/是否在线回退）、ZIP 完整路径+字节数+SHA-256**。不要把“工具理论支持”写成“本客户端已经通过”。我拿到 ZIP 后会独立验哈希、GLB 结构和截图，再决定是否需要补 DB2 或扩大到第二套。
