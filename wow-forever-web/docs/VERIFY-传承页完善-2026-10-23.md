## 三、引擎的判定与反例（`legacy-plan.spec.js` 32 条）

| 规则 | 实现 | 反例（都有对应单测） |
| --- | --- | --- |
| 本树门槛 | 加点时"这一棵已投点数 ≥ `treePointsRequired`"，不含正在加的那一点 | 0 点想点 5 门槛格 → 拒；投满 5 点后 → 放行 |
| 前置 | 前置那格必须 ≥1 点 | 投满 10 点但没点前置 → 仍拒，且**点名要点哪一格**（不说"前置不满足"这种术语） |
| 层数上限 | `maxRank` | 点满后再加 → "已经点满 N 层" |
| 每角色上限 | `launchSpendingCap` | 到 16 点后任何格子都拒，并说要先退点 |
| 退点保护 | 先试算再检查所有还点着的格子 | 退掉前置的最后一点 → 拦住并点名是哪一格还点着；**不静默清掉别的点** |
| 整棵清空 | 同树点一起走 | 清空后 `cascadeBlockers` 必须为空（不留悬空） |
| 方案码 | `v1:<slug>.<层数>,…`，只装格子 | 未知格子 / 超层数（按上限收并说明）/ 版本号不对（整串不认）/ 垃圾串不炸 |
| 个人记录不进链接 | 编码只遍历 `ctx.perks` | 单测遍历全部 66 个挑战编号，断言它们**一个都不出现在链接里** |
| 勾选迁移 | 只认数据里真有的编号 | 本机存着已不存在的编号 → 丢掉并回报，不把完成状态错给别的条目 |
| 奖励轨 | 门槛是点数 | 0 点时四档"还差"等于各自 `at`；999 点时全 `reached` |
| 5×5 网格 | 收掉全空的排与列，编号仍用客户端真实值 | 三棵树都算一遍；收掉的排/列必须真的没有任何内容 |

## 四、界面上一个有意的决定：5×5 收成 4×4 显示

客户端 70532 把三棵树排成 5×5，**第 4 排与第 4 列整条是空的**。照原样摆会在每棵树中间留一条空带（实拍很难看），把坐标压回 4×4 又要改数据。定的做法是：

- **显示层收掉全空的排与列**，格子数从 25 变 16；
- **排号仍印客户端真实排号**（第1排/第2排/第3排/**第5排**），详情里"位置：第 N 排第 M 列"也用真实坐标；
- 数据一个字节没改。

这样玩家看到的是紧凑的树，但坐标与客户端对得上，不会以为"第 4 排不存在"。

## 五、改了 4 条既有判据——逐条交代为什么不是"把红的改成绿"

| 判据 | 原来 | 现在 | 理由 |
| --- | --- | --- | --- |
| 格子数 | `cells == rows × cols`（25） | `cells == 可见排 × 可见列`（16），可见性由数据算 | 页面有意收掉空行空列（第四节）。**判据仍从数据现算**，不是把 16 抄进去 |
| 图例 | `legend == 3` | 查图例文字里是否说清"专长/投满/线/没公开"四种标记 | 3 是抄死的设计常量；加了门槛与连线两条说明是这轮的有意变化 |
| 挑战行数 | "66 行一条不少" | "六组 65 行 + 单列 1 条，且单列那条的编号不在六组里" | 常规/特殊分账是上一轮数据交付的口径，页面按它落地；行数判据跟着改成两组分别数 |
| 375 列数 | `== 4`（我上一轮刚从 5 改成"数据列数"） | `== 数据算出的可见列数` | 同第一条，收掉空列后可见列是 4 |

另外**补了一条 375 判据**：`window.innerWidth` 必须仍是 375。原因是这轮第一版把特殊记录那张表直接铺在卡片里，`.board` 在窄屏有 `min-width:640px`，把布局视口顶到 **674**——而"整页不横溢"那条断言算的是 `scrollWidth - innerWidth`，视口被顶宽时它自己还是 0，**假绿**。这是同一把尺子第二次抓到这个坑（第一次是配装页的 `.pz-two`）。现在页面不顶宽、判据也盯住了 `innerWidth`。

## 七、没验到的，别当验过了

1. **剪贴板**：无头浏览器里 `navigator.clipboard.writeText` 走的是回落分支。链接生成与地址栏内容验过（`?plan=` 里只有方案码），**"复制成功"那句提示要人手点一次**。
2. **真机触摸**：375 是 Chrome 移动端仿真的量法（含 `is_mobile`）。长按、惯性滚动、iOS 上的 44px 手感没测。
3. **`＋ / －` 的键盘操作**：按钮是原生 `<button>`，Tab 得到、回车能触发（设计系统那节 `[20]` 的焦点可见判据覆盖整站），但**没有专门给规划器写过键盘用例**。
4. **旧站那 19 页**：`legacy.html` 仍按客户端 5×5 原样摆（旧站冻结，没动它）。它现在会在中间留一条空带——这是**已知且刻意不管**的，要处理得先解"旧站冻结"这条。
5. **视觉规范**：图例那两种新标记（门槛角标、连线）是我按现有令牌拼的，没走 UI 规范评审。**UI.md 该补的那一节留给 wow-ui**（本轮没写 UI.md，避免代它定规格）。
6. 方案名冲突、同名覆盖、删除后 activeName 的回落这些路径做了实现但没有单测（页面里表现为：同名会覆盖并提示"已存到…"）。
