# 参考站布局对比与整合方案（wow-planner · 2026-10-09）

第四个参考站出现：`https://jjwow.cn/`（耿哥工具箱 / 耿哥资料站）。这一份把四家摆在一起比，
只回答一个问题：**哪些是他们的壳值得学，哪些是我们的红线不能跟**。
落地批次见文末，未点头的不做。

## 一、四家是谁

| 站 | 定位 | 数据口径 | 对我们的价值 |
| --- | --- | --- | --- |
| `wowclassicforever.info`（WCF） | 英文无限服资料站 | 自己做客户端解析 + 载入图 | 素材源（副本载入图、职业背景）；英文命名对照 |
| `wowforever.wclbox.com`（新手盒子） | 中文无限数据库 | 客户端解包转述，另有 `/_shuju/<发布号>/*.json` 静态接口 | **我们全线数据的实际来源**（副本 / 专业 / 世界 / 改动清单） |
| `foreverchanges.pro` | 英文改动对照站 | 客户端解包 + 逐条 Classic vs Forever 对照 | 改动与传承的原始出处（下面两家都是它的下游） |
| `jjwow.cn`（耿哥） | 中文资料站 | 自述 `src: foreverchanges.pro/zh-cn/...（2026-09-29 采集）`，数据以 `assets/data/wf-*.js` 加载 | **布局最值得学**；数据是 foreverchanges 的二手转述，且已停更 10 天 |

关键一条：**jjwow 的数据不是它自己挖的**，它每个数据文件头部都写明了来自 foreverchanges.pro。
所以"接 jjwow 的数据"实质是接 foreverchanges 的中文改写，中间多一层人工翻译，
比我们现在的 `datamine_cn`（wclbox 直转客户端）更远一层。

## 二、布局层面值得学的（三家各一处）

1. **首页 hero 里放全站搜索**（jjwow、wclbox 都有，WCF 也有）。我们 14 页**一个搜索框都没有**，
   只能进某一页再用页内筛选。这是最大的一处体验缺口，且不需要任何新数据——
   词条、天赋、法术、副本、区域、稀有、书籍、配方全在我们 `src/data/` 里。
2. **上线倒计时做到秒**（jjwow 首页右上 `26:11:48:22`）。我们现在是"26 天 11 时"，
   倒计时是这类站首页的第一情绪点，值得做足。
3. **首页直接给一棵天赋树看**（jjwow 首页右侧是真渲染的三系树缩略，不是文字卡）。
   我们首页只有"473 天赋节点"这种数字。这条要改的是渲染复用，工作量比前两条大，排第二批。
4. **种族页顶部用阵营背景原画**（jjwow 用暴风城/奥格瑞玛背景压暗）。属于客户端原画，
   沿用 `fetch-art.py` 的 manifest + 整目录下线方案即可，但**要不要再加一批游戏美术进仓库得点头**。

## 三、内容层面缺的两块（不是布局问题）

| 模块 | 参考站有什么 | 我们有什么 | 判断 |
| --- | --- | --- | --- |
| **传承（legacy perks）** | 65 个挑战 / 每角色 16 点 / 21 专长（6 个未公开）/ 4 外观奖励，带树结构与前置连线，还有专长规划器 | **已补（2026-10-10）**：`legacy.html` 三棵树 27 个槽位（6 格画成"未公开"）、65 项挑战每条带待实测、4 档进度奖励、专长详情带上限与前置。**没有**专长规划器（要存个人加点，类目不允许），**没有**每层效果说明（别人转述的客户端文本，红线不复制） | 数据源不用点头：无限数据库其实有 `/chuancheng`（`/_shuju/<发布号>/legacy.json`），先前那次"没有接口"的判断是错的——它把接口挂在发布号下面，得先从页面 HTML 里现读发布号。取不到的那 6 格留空标未公开，不猜 |
| **种族天赋的改动状态** | 每条标 新增 / 未改动 / 已改动，并列出"Forever 中已移除"的（如人类：外交、锤类武器专精） | 只有官方公告里现存的 40 条整句，没有"新增/移除"这层 | 与我们已接的天赋 `changeState` 同类。接的话只取状态标记与名称，句子仍用我们自己的官方整句 |

## 四、明确不跟的（三家都有，我们不做）

| 他们的板块 | 为什么不做 |
| --- | --- |
| BIS 装 / 毕业装推荐（jjwow、WCF） | 红线：不做强度排行与配装结论；且我们没有战斗数据，抄别人结论等于把他人判断当事实 |
| 一键宏（jjwow） | 红线：宏与循环提示不做 |
| 指南正文 / 阅读量最高指南（jjwow） | 红线：不做攻略正文 |
| 插件下载 / 抖音引流 / 小程序引流卡（jjwow 首页整排） | 我们是资料站不是工具箱；首页放引流卡会把定位稀释掉 |
| 补丁说明按日 + 增强/削弱计数（jjwow `patch-notes.html`） | 内容本身是好东西，但它逐条带工具提示前后文本与"我在游戏里发现的"这类作者判断；要做只能等官方中文蓝帖原文 |

## 五、竞品提醒（运营侧）

jjwow 已经上线**微信小程序「耿哥工具箱」**，功能覆盖物品查询、毕业装推荐、专业配方库——
和我们的小程序规划正面撞。它是个人主体还是企业主体、有没有备案都未知，
但"别人已经把无限服资料做成小程序"这件事会影响我们的差异化定位，建议交给 wow-ops 看一眼再定小程序的功能边界。

## 六、落地批次

- **第一批（不需要新数据、不碰红线）：已完成（2026-10-09）** — 全站搜索索引 + 首页搜索框与分组跳转；倒计时到秒。
  落地清单：
  - `tools/build-data.js` 从已校验的数据派生 `src/data/search.json`（4206 条 / 16 类：职业、种族、天赋、
    客户端改动、术语、技能四态、副本、首领、区域、稀有、书籍、睡袋与营地、专业、配方、采集点、种族特长）。
    每条只有 `[类型, 名称, 归属, 跳转参数, 分级]`——**不收任何描述句子**，名字或副标题写成句子会被卡口拦下。
  - 首页 hero 一个搜索框：输入即按板块分组出结果，每组先列 5 条，组头那条"进去看全部"直接带着词跳页。
  - 十个板块页都接住了深链：`world.html?t=rares&q=…`、`dungeons.html?d=…`（替你把那座本的速览点开）、
    `talent.html?c=…&q=…`（描边高亮那一格）、`professions.html?p=…&q=…`、`updates.html?c=…&w=…&q=…`（滚到改动表）、
    `races.html?q=…` / `?r=horde-orc`、`glossary.html?q=…`、`skills.html?q=…`。
  - 倒计时到秒：顶栏与首页同一读数，每秒走一次；上线日期仍只有 `meta.json.launch` 一处真相，
    旧站 `app.js` 的 `LAUNCH` 与新站 `fmt.js` 的 `LAUNCH_AT` 由卡口对齐，改一处漏改会直接构建失败。
  - 新站（Vue）同步接完：`lib/search.js` + `components/SiteSearch.vue` + `lib/countdown.js`，
    纯逻辑 9 条 + 组件 6 条单测，新旧两站对拍无差异。
- **第二批：已完成（2026-10-09）** — 首页放只读真树预览；种族页两条阵营带铺城市原画。
  - 首页那张卡现在是**一棵能看的真树**：系 tab + 7×4 网格 + 状态计数，右边九职业切换，点格子进计算器并描边高亮那一格（`talent.html?c=&tree=&q=`）。数据走派生件 `src/data/talent-preview.json`（473 个节点、28 KB），首页不拉九份完整天赋文件。
  - 阵营原画：联盟=暴风城英雄谷、部落=奥格瑞玛正门，`fetch-art.py --what factions` 转存，`art.json` 新增 `factionCities` 桶；压暗 + 渐变 + `pointer-events:none`，取不到整层不渲染。两张都人眼确认过画的是什么。
  - 新站同步 `lib/preview.js` + `TalentPreview.vue`，单测 58 → 67；断言 358 → 370；两栈对拍零差异。
- **第三批：已完成（2026-10-10）** — 传承模块。
  - **数据源不用点头**：先前"无限数据库没有这个接口"的判断是错的，它有 `/chuancheng`，
    结构化数据在 `/_shuju/<发布号>/legacy.json`（发布号要从页面 HTML 现读，写死会过期）。
    于是全站第一次出现"整块内容只有一家源"——按红线只用它的**名称、坐标、上限、点数、物品编号**，
    专长每层效果说明、常见问题、领取说明**在抓取脚本里就删掉**，仓库里不留转述句子，
    `build-data.js` 再走一遍成品 JSON 兜底（出现任何句子字段直接构建失败）。
  - 界面：三棵树按客户端坐标摆 4×4 格子，具名 21 格 + 未公开 6 格（虚线 + `?` + 文字）+ 空格画出来占位；
    桌面"树在左、详情在右"并排，点一格右侧出上限/位置/前置/解包日期与可点开的来源，没点时右侧是空态说明。
    65 项挑战分六组列成表，**每条一个"待实测"徽标**（不只在页顶写一句），可按名称/条件/归属筛，筛不到给能照着改的空态。
  - 搜索索引多两类（传承专长、传承挑战），共 18 类 4292 条；从搜索带专长名跳进来会直接落到它所在的树并展开详情，
    同时不把下面的挑战筛选抢掉（这条是第一版实测踩出来的，有断言盯着）。
  - 没做的：专长规划器（要存个人加点，类目与红线都不允许）、每层效果数值（等官方中文或游戏内实测）、
    点数分配建议（攻略性质）。都写进页面的「这一页没有的」。
- **第四批（要点头定口径）**：种族天赋的新增/改动/移除状态。

状态：**第一、二、三批已定并落文件**；第四批（种族天赋角标）要点头定口径。

### 落地时要守的三条

1. 不改功能与路由：搜索、9 个板块页的深链、天赋预览点格子进计算器，全部保持；
2. 不引新素材：职业圆图标与天赋图标用仓库里已有的本地文件，缺图的仍走自绘块；
3. 每个模块的数字一律从 `scale.json` 现读，设计稿里写死的数在实现时必须换成数据。
