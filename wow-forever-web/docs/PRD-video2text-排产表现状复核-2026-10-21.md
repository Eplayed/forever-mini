# video2text 排产表现状复核：线索入口与发布优先级

日期：2026-10-21。仅只读核查 video2text 当前工作区及近期提交；未修改外仓代码、生产数据或排产状态。

## 结论

排产表可以作为操作者每天进入内容流程的**第一屏：发现/筛选候选线索**。当前实现更准确地说是“11 个预设选题的排期与素材匹配面板”：先有 `schedule.html` 的题目、日期与搜索词，再实时查素材库，不能把它称为“自动从全库发现所有新题”。用户点“采用”后，才从候选线索进入单篇素材选择与整理任务。

红色“今天就发”目前只是**排期优先级信号**，不是图文攻略已具备发布质量的证明。它没有检查玩家问题、独立贡献、稿件事实、文字质量、关键帧解释作用与使用依据。应在产品文案上与“内容已可发布”明确分开；后续流程为：排产表看线索 → 定一个玩家问题 → 采用并核查素材 → 审文字攻略稿 → 选真实关键帧 → 免费预览 → 正式生成 → 人工发布。

## 发现的三个边界与待修点

1. **发布紧迫度和内容就绪度混同（产品口径）。** `plan_brief.build()` 的红色只要求“到期、未登记发布、按标题/作者等过滤后有新料”；没有检查转写的事实是否可靠、攻略是否能照做或图片能否使用。UI 的“今天就发”容易被当成质量放行。建议改为“今天优先处理”，并另显“内容审核未完成/已通过”，不把时间信号直接称为发布许可。
2. **“今天已发一篇则其余红色降级”的实现与文案不一致。** `build()` 只在第二条起设置 `demoted` 说明，未修改 `verdict` 和 `label`；页面仍把这些卡画红、写“今天就发”。如果今天已有一篇、另有一个红槽，该唯一红槽甚至不会有 `demoted` 提示。当前 UI 走查没有覆盖这种数据反例。需要一个小型定点回归检验 1 个及多个红槽、当天发过 1 篇的情形。
3. **交付完整性与视觉覆盖。** `web/static/schedule.html`、`src/plan_tasks.py`、排产相关测试仍是未跟踪文件；颜色脚本在已提交，但页面里引入它的 `<script>` 两行还在未跟踪页面中，干净检出未必能看到完整排产入口。另 `schedule-brief.js` 给色条写的是 `.item.vb-red` 等选择器，而卡片实际为 `.card`；状态标签会着色，但整卡左侧色条规则不匹配。现有走查只核色块背景，没有核卡片色条。以上只记录，未擅自改外仓。

“48h”当前按 `published_at` 的**日期**与 `today-2 days` 比较，不读小时；实际是日历日窗口，不是精确 48 小时。若用作强发布判据，需明确表述或改成时间戳计算。

## 与后续图文流程的衔接

排产表第一步应产出一个**候选线索**（题目/玩家疑问/候选素材/时效），而非直接产出“可发任务”。进入下一步前仍需人工确认玩家问题与独立增量；按“采用”只锁定材料快照，不代表材料事实通过。现有 `PRD-video2text-原创增量改造-2026-10-21.md` 的文字稿前置审核、真实关键帧解释作用审核仍应放在正式出攻略页之前。排产颜色和这套审核状态应该分栏表达。

另有一份 `PLAN-video2text-改造后工作流-2026-10-21.md` 在“写稿与做图”处仍写“优先自绘图或自己实际操作的截图”。这与站主本轮明确的攻略页主路径——**使用素材视频真实关键帧，不重画配图**——不一致。后续 Qoder 实现该主路径应以已经修订的 `PRD-video2text-原创增量改造-2026-10-21.md` 为准；规划文件这处需由其责任方同步修正，不能让两份交接给出相反指令。
