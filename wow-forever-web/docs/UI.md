# 《无限》中文资料站 UI 设计规范 v1

依据：参考站 `wowclassicforever.info` 三页实拍（`docs/reference/wcf-home.png`、`wcf-talent.png`、`wcf-dungeons.png`）+ PRD v1.0。
实现约束：纯静态 HTML/CSS/JS，不引框架、不引 Web 字体、不引图标库；离线可跑。

---

## 一、从参考站提取的设计语言

参考站值得继承的三点，和两点必须改的地方：

**继承**
1. **暗色 + 暖金**：近黑底叠一层极淡的棕橙径向光晕，主强调色是琥珀金，读起来像游戏内 UI 而不是普通网页。
2. **三系并列的天赋版式**：一屏三列，每列自带列头（系图标 + 系名 + 解锁提示 + 单列清空），节点是 5 列网格 + 层级虚线分隔 + 依赖连线 + 右下角点数角标。这套版式信息密度高且玩家熟悉，照搬结构不照搬素材。
3. **底部工具条**：等级滑杆、复制方案、路线展示、重置、三系分布统计，全部一行解决，不弹层。

**必须改**
1. 参考站全大写小型衬线体（`WOW FOREVER WARRIOR TALENT CALCULATOR`）在中文里不成立 → 中文用系统无衬线，英文/数字保留等宽，标题靠字重与字距拉开层级，不靠小型大写。
2. 参考站没有"这条数据可不可信"的视觉表达 → 本站把 **完整度徽标（L0/L1/L2/L3）做成一等公民**，这是产品差异点，不是装饰。

## 二、设计令牌（落在 `src/css/app.css` 的 `:root`）

### 2.1 颜色（写进 `src/css/app.css` 的 `:root`）

| 令牌 | 值 | 用途 |
|------|-----|------|
| `--bg` | `#0e1013` | 页面底 |
| `--bg-glow` | `radial-gradient(1200px 600px at 50% -10%, rgba(120,72,32,.28), transparent 70%)` | 顶部暖光 |
| `--panel` | `#171a1f` | 卡片/面板 |
| `--panel-2` | `#1e222a` | 次级面板、输入框 |
| `--line` | `#2b3038` | 描边、分隔 |
| `--txt` | `#e7e9ee` | 正文 |
| `--txt-dim` | `#98a1af` | 次要文字 |
| `--gold` | `#e0a96d` | 主强调：标题、可点、选中边框 |
| `--gold-deep` | `#b8813f` | 强调按下态 |
| `--blue` | `#6fa8ff` | 链接、英文副名 |
| `--ok` | `#4caf72` | 通用「正向」图形色（2026-10-10 起**不再当 L0 文字色**） |
| `--warn` | `#d9a13b` | 通用提醒图形色（**不再当 L2 文字色**：它与品牌金同族，会互相误读） |
| `--lead` | `#7f8ea8` | 中性引导色 |
| `--bad` | `#c9564a` | 错误 / 冲突的**图形**态（小字禁用，见下第 2 条） |
| `--txt-alert` | `#ff9b8f` | 警示文字（`--bad` 的文本态，深色底上对比度才够） |
| `--txt-caution` | `#f0c67e` | 提醒文字（`--warn` 的文本态） |

**警示与提醒文字一律用 `--txt-alert` / `--txt-caution`（工具类 `.alert` / `.caution`），不许在 JS 里写死 `#ff9b8f` 这类色值**；边框与色块仍用 `--bad` / `--warn`。

**2026-10-10 全站改版加的两条硬规矩**（读题、色板与实测见 `DESIGN-REFRESH-2026-10-10.md`）：

1. **一个色相只服务一条语义轴。** 分级是有序量，改走「明度阶梯 + 形状 + 文字」；阵营与物品品质是游戏原生的分类，才用色相；
   琥珀金从此**只表示交互与品牌**（当前页 / 链接 / 焦点 / 选中格），任何数据状态都不许借它——
   `site-check` 第 20 节读徽标的计算色，等于 `--gold` 就红。
2. **小字对比度不达 AA 就换文本态色。** `#c9564a` 在砚面 `#171a1f` 上实测只有 **4.08:1**（AA 要 4.5:1），
   所以 `.conf`（译名分歧那两行小字）改用 `--txt-alert`，实测 8.59:1；
   对比度由脚本逐页取「文字色 + 沿祖先找到的第一个不透明背景」现算，不再靠人眼估。

职业代表色（`js/glyph.js` 的 `CLASS_COLOR`）是**游戏内职业名颜色的事实性标识**，不属于主题令牌：改动必须与游戏内一致，不随配色方案漂移。战士 `#c79c6e`、圣骑士 `#f5c7e9`、猎人 `#aad372`、潜行者 `#fff468`、牧师 `#ffffff`、萨满祭司 `#2ed6b1`、法师 `#69ccf0`、术士 `#8788ee`、德鲁伊 `#ff7c0a`。

三系列头背景各自微调色相（暖橙 / 冷蓝 / 紫），只改 `background` 的 6–8% 透明度叠加，不改文字色，保证三列可辨但不花。

### 2.2 完整度徽标（全站统一，不可自创样式）

| 级别 | 文案 | 徽标形状（`::before`） | 文字色（明度阶梯） | 来源轨 |
|------|------|------|------|------|
| L0 | 已官方核实 | 实心方块 | `--lv0` `#cfe8dd` | 实线轨 |
| L1 | 仅官方英文 | 左半填充 | `--lv1` `#a9b8c6` | 上半实、下半空 |
| L2 | 待实测 | 空心圆 | `--lv2` `#9aa3ae` | 空心描边 |
| L3 | 缺数据 | 斜纹方块 | `--lv3` `#8b93a1` | 低对比斜纹 |

形状与文字同时出现，所以灰度打印、色觉障碍、或只扫图标不看字，都还读得出是哪一级。
`site-check` 第 20 节逐页取四种徽标 `::before` 的计算值比对，四者必须互不相同；
同一节还查「页面声明了分级或来源，卡片就一定有轨」——反过来，**没定级的卡不许有轨**，
问答页 / 溯源页 / 排行页没有分级数据，所以那几页确实一条轨都没有。

规则：**任何展示位只要有 L2/L3 字段，页面顶部必须挂一条黄/灰横幅说明"本站基于测试服数据，正式服上线后重核"**，不允许静默呈现。

### 2.3 字体与字号

```
--font-cn : -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif
--font-mono: ui-monospace, "SFMono-Regular", Menlo, Consolas, monospace
```

2026-10-10 改版后按**角色**分工（辨识度全靠这三档落差，不下载任何字体）：

| 角色 | 规格 | 用在哪 | 为什么这样定 |
|------|------|--------|--------------|
| 展示 | `clamp(28px, 4.4vw, 42px)` / 700 / 行高 1.18 / 字距 0 | 每页唯一 H1（`.pt` 与天赋页 `.title`） | 原来 H1 只有 17px，和区块标题几乎分不开，页面没有"进门感"；中文不加负字距（会挤），靠字号与字重拉开 |
| 区块标题 | 20px / 650 / 行高 1.3 | 卡片 h2 | 与正文要一眼分层，又不抢 H1 |
| 正文 | 16px / 400 / 行高 1.75 | 说明段 | 中英混排要的是行高，不是字号 |
| **元数据** | 等宽 11.5px / 500 / `letter-spacing:.09em` / `tabular-nums` / 拉丁与数字大写 | 级别徽标、核对日期、物品编号、坐标、条数、板块眉标（工具类 `.mline`） | 这站一半信息是"元数据"（哪来的、几时核的、第几级），给它一套自己的字形，读者一眼分得清"内容"和"关于内容的话" |

数字一律 `tabular-nums`，倒计时跳动不推挤版面；中文不做 `uppercase`（无效），大写只对拉丁与数字生效。

### 2.4 间距与圆角

4 倍数体系：`4 / 8 / 12 / 16 / 24 / 32`；圆角 `6`（控件）、`8`（卡片）、`4`（徽标）；节点格 `46×46`（桌面）/ `40×40`（移动）。

### 2.5 图标格（列表与词条统一）

`.liw` 是一个叠层方块：**底层永远画自绘占位块**（`Glyph.talentTile`，按名称种子取色 + 首字），**上层在有官方图标时盖一张本地转存的 jpg**（`img/icons/<key>.jpg`，`onerror` 时把图隐掉，占位块自然露出，不留空白）。桌面 26px，词条内 18px。

图标键不手抄：`src/data/icons.json` 由 `tools/build-icon-map.py` 从 `talents/*.json` 派生，键是 `classId|中文名`——按名字查会串（兽人的被动「坚韧」和牧师的「坚韧」是两回事），必须带职业。查得到图才显示图：215 条词条里 111 条有，其余是基础技能与种族特长，**我们没有它们的可信图标来源，就用占位块，不拿别的图凑数**。页面顶部固定一句说明：能显出图案的是本地转存的官方天赋图标，字母块是自绘占位。

种族与阵营方块另算：`Glyph.raceTile` 按阵营取色相（部落暖红 / 联盟冷蓝），同阵营内按种子浮动，一律自绘——新种族图标能不能从官方 CDN 取到尚未证实，红线也不允许热链第三方图片。

### 2.6 客户端原画（职业背景 / 副本横幅）

`.liw.t`（34px）、`.tbg`（天赋页 132px 背景条）、`.dbn2`（副本横幅 96px）三处都是同一套做法：**自绘版永远先画，本地转存的原画盖在上面，`onerror` 把图隐掉就露出自绘版**，所以删掉 `src/img/art/` 整目录只是回到"看起来朴素"，不会出现破图或空洞。

每张盖了原画的图右上角固定一枚 `.dbn2-mark` 标注，写清是"客户端原画 · 本地转存"还是"示意图 · 非游戏原画"——**读者必须能一眼分辨哪张是真图**，这条由 `site-check` 第 4 节断言，不许只靠自觉。

---

### 2.7 签名元素：来源轨（2026-10-10）

每张内容卡左缘一条 3px 竖轨，**轨的填充程度 = 这张卡最弱那条数据的分级**（实心 / 半填 / 空心 / 斜纹），
卡头的等宽元数据行写同一级的文字。它不是装饰：扫一眼轨的"实心程度"，就知道这一页有多少东西是核过的。

- 级别只从页面**已经渲染出来的事实**现读：卡里的分级徽标 + 卡里的来源类型标签
  （官方中文 / 官方英文 / 客户端解包按既定口径支撑 L0，第三方转述属 L2），两处都有取更弱的那个。
  不在渲染器里另写一份 level，免得两说。
- 「本站说明 / 本站承诺」不是数据来源，不参与定级；**图例里那排徽标数的是全站分布，也不参与**
  （否则首页汇总卡会被标成「缺数据」——这个坑是实拍发现的）。
- 卡里既没徽标也没来源就**不上轨**：没定级就别装作定了级。
- 两份实现（旧站 `src/js/app.js` 的 `applyRails`、新站 `app/src/lib/rails.js`）由 `app-parity --strict` 逐页对拍，
  纯函数另有 6 条 vitest 用例。

### 2.8 动效（三处，CSS-only，可关）

| 位置 | 触发 | 时长与缓动 | 只动 |
|------|------|-----------|------|
| 卡片进入 | 首次渲染 | 240ms `cubic-bezier(.16,1,.3,1)`，`opacity` + `translateY(6px)`，前 5 张错峰 40ms | transform / opacity |
| 来源轨填充 | 首次渲染 | 220ms，`scaleY()` | transform |
| 交互反馈 | hover / active | 140ms，边框色 + `translateY(-1px)` | 不动任何布局属性 |

`@media (prefers-reduced-motion: reduce)` 下三处全部归零，但**保留最终态**（动画关掉不等于内容藏起来）。
倒计时每秒只改文本节点，不加动效——它本来就在动。键盘焦点从此必须有 2px 金色外环（`outline-offset:2px`），
原来 `:focus` 把 outline 关掉只留边框变色，键盘用户看不见落在哪。

## 三、页面结构

### 3.1 全局骨架

```
[顶栏 · 第一行] 站名（点它回首页） ·························· 上线倒计时 chip（天 + HH:MM:SS）
[顶栏 · 第二行] 两级常驻导航：首页 ｜ 天赋 计算器 ｜ 职业 玩法问答·技能书 ｜ 种族 总览·特长 ｜
                世界 区域与稀有·副本·系统规则 ｜ 专业 配方 ｜ 工具 速查·时间表·动态·排行·溯源
[内容区] max-width 1180，居中
[底栏] 非官方声明 + 数据来源版本（build 号 + 核对日期） + 覆盖率摘要
```

**导航是两级常驻的，没有下拉、没有汉堡**（2026-10-09 改版）：一级名字只当分组标签用（`<b class="ngt">`，不可点），
15 个二级入口全部平铺露出，页面说明收进 `title` 悬停提示。桌面一行放得下（1180 容器实测 39px 高，顶栏合计 82px）；
375px 下第二行改成**一条可横滑的导航带**（`overflow-x:auto` + 右侧渐隐遮罩 + `scroll-snap`），
当前页那一项在加载后自动滚到中间，链接 `min-height:44px`，顶栏合计 94px。
倒计时用等宽数字，秒每秒刷一次（读数与首页那块同源）。

### 3.2 首页（2026-10-09 重排）

参考站的首页就是它的招牌工具（打开即是战士天赋树 + 一排职业图标 + "WHERE TO NEXT"），我们照这个口径重排：
**首页先给工具，再给目录，最后给口径**，不做宣传页。

```
[hero] 站名 + 一句话定位 | 覆盖率条（四段，宽度按真实计数）+ 四个分级读数 + 数据基线一行
       右侧：上线倒计时大数字 + 选职业问答 CTA
[真树预览卡] 左：系 tab（武器/狂暴/防护 + 各自天赋数）+ 只读 7×4 网格 + 状态计数
              右：九职业切换（按钮，选中那格描金）+ 口径说明 + 进完整计算器的 CTA
[还要去哪] 最新动态 / 排行 / 上线时间表 / 溯源 / 系统规则 / 技能书 / 还没有数据的
[模块卡 ×6] 天赋模拟器 · 区域与稀有 · 副本手册 · 专业与配方 · 种族组合 · 术语速查
            每卡：一句"这里回答什么问题" + 三个规模数字 + 一个分级徽标 + 一句口径边界
[底部两栏] 官方口径里的时间点（timeline 最近 4 条，带分级） | 这一站刻意不做的（5 条带理由）
```

规则：
- **首页所有数字一律来自 `src/data/scale.json`**（由 `tools/build-data.js` 校验时算出并写出），
  页面里不许手抄常量——2026-10-09 之前首页写着"11 条词条 / 9 座新副本"这种早就过期的数，就是这么来的。
- 覆盖率条与页脚那条是**两个口径**：首页 = 全站 842 条（含天赋节点与世界线），页脚 = 词条覆盖率（不含天赋节点）。
  两个都必须在页面上写明范围，不许让数字互相看着打脸。
- "最新动态"槽位不放新闻流（红线），放**官方公告里写过的时间点**，并标分级；缺数据的那条直接显示"择期"。
- 模块卡的口径边界（掉落不写百分比、冲级路线不做、刷新计时不猜）摆在卡底，不藏进溯源页。
- 职业九格即使数据不足也照常显示，靠徽标说明缺口。
- **首页那棵树是只读预览**（2026-10-09 第二批）：数据来自派生件 `src/data/talent-preview.json`（一条节点只有 `[行, 列, 名称, 图标键, 上限, 改动状态]`，28 KB），**不在首页拉九份 43 KB 的完整天赋文件**。格子本身是链接，点下去进计算器并带着 `?c=&tree=&q=` 把那一格描边；预览不判前置、不判门槛，也不显示点数——加点仍然是计算器的事。默认看 `classes.json` 里的第一个职业，两栈必须同一个起点。

### 3.3 天赋计算器（核心页）

```
[职业条] 9 个职业方块，选中态金边
[面板头] 职业图标 · 剩余点数框 · 「XX 天赋」标题 · 搜索 · 已选/总数
[三系并列] 列头：系图标 + 系名(中英) + 解锁提示 + CLEAR
           网格：5 列 × N 层，层间虚线，依赖用 SVG 连线
           节点：图标位 + 右下点数角标 + 左上黄点(L2) + 悬停出 tooltip
[工具条] 等级滑杆 | 复制方案 | 显示路线 | 重置 | 三系分布 0/0/0 · 需求等级
[溯源条] 本树数据来源类型 + build 号 + 核对日期（一行，灰字）
```

节点四态：`可用`（正常）、`已点`（金边 + 角标 >0）、`锁定`（降饱和 + 禁用，tooltip 说明缺什么）、`缺数据`（斜纹底）。

移动端：三系改为 Tab 切换，单系全宽 5 列网格；工具条换行，滑杆占满。

Tooltip 内容顺序：中文名 → 英文名 → 已点/上限 → 效果描述（有则显示，L2 加黄点）→ 来源与核对日期。

### 3.3b 天赋页的树状视图（2026-10-09 改版）

三系并排，每系一张 **7 行 × 4 列** 的 CSS 网格（这就是客户端里的真实结构，之前按"经典 10×5"判断把挖掘源的坐标当成排版坐标，是误判）。格子内容：官方图标（本地转存，取不到露自绘块）+ 名称 + 已点/上限。

四类角标各占一角，互不遮挡：左上黄点 = 名称待实测，右上绿点 = 名称与官网中文逐字一致，右上红三角 = 两源译名冲突，**左下菱形 = 与经典旧世的差异**（绿=新增、黄=改动、蓝=换层、灰=未变）。菱形颜色之外还有图例行与 `title` 文字，不单靠颜色承载信息。

前置连线是渲染完量出格子中心再注入一层 `.tlines` SVG（CSS 网格没法用纯 CSS 画跨格连线），`pointer-events:none`，不抢点击。

层级点数门槛按第 2 层起 5 / 10 / 15 / 20 / 25 / 30 累计解锁，这条现在由 `rules.tierUnlockCost` 驱动，页面上不再写"门槛未核实"。

### 3.4 技能书页

### 3.5 副本手册页

### 3.9 选职业问答页

### 3.17 全站搜索与倒计时（2026-10-09 参考站整合第一批）

- 入口只有一个，放在首页 hero 标题段下面（`.gsearch`）：`input#gs` + 示例词行（`.gsex > button.gsx`）+ 结果层（`#gres`）。
  输入框 `min-height:44px`，示例词桌面 32px、375px 下 44px；结果层绝对定位浮在示例词行下方，点框外收起。
- 索引是 `src/data/search.json`，由 `tools/build-data.js` 从已校验的数据派生，**懒加载**（第一次输入才拉，230 KB / gzip 34 KB）。
  一条 = `[类型, 名称, 归属副标题, 跳转附加参数, 分级]`，只收名称与归属：
  名称或副标题写成句子（>40 / >44 字）卡口直接失败，第三方转述的原文句子一律不进。
- 结果按板块分组，顺序固定：职业 → 种族 → 天赋 → 客户端改动 → 术语 → 技能四态 → 副本 → 首领 → 区域 → 稀有 → 书籍 →
  睡袋与营地 → 专业 → 配方 → 采集点 → 种族特长。同名排最前，其次前缀、再次包含；同分按板块顺序、再按名字长度，**结果顺序可复现**。
- 每组先列 5 条，组头那条写"这一类共 N 条，进去看全部 →"，跳过去带着同一个词由那一页自己的筛选器接手；
  单条结果跳过去也必须已经筛好（`?q=` 预填 + 该切板块的切板块、该开抽屉的开抽屉、该高亮的描边）。
- 分级只在非 L0 时出现，且**除颜色外一定带文字**（`.lv` 里写"待实测/缺数据/仅官方英文"）。搜不到时直说"索引里没有"，
  并写明本站按官方中文原名收录、别名与英文请进对应页面搜——不做模糊猜测，也不机翻。
- 倒计时：`#cdD`（天）+ `#cdT`（`HH:MM:SS`，等宽 + `tabular-nums`，跳动时不左右晃），顶栏 `#lchip` 同一读数，
  每 1 秒刷一次，只改文本不重排页面。日期取 `LAUNCH` 常量，`build-data.js` 卡它与 `meta.json.launch`、
  新站 `fmt.js` 的 `LAUNCH_AT` 三处一致。

### 3.18 文案红线：页面上不许出现维护者的话（2026-10-09 立）

判断标准只有一句：**这句话是在跟用户解释我们的工程进度，还是在回答玩家的问题。** 前者删或改写，后者留。

| 不许出现 | 改成 |
| --- | --- |
| 上游（玩家不知道是谁） | 写清主体：客户端解包 / 参考站 / 官方 |
| mapId、areaId、slug、`*.json`、`tools/xxx.py` | 地图编号；文件名与脚本名一律不上页面 |
| 口径、结构化、字段、本轮、未解析 | 说法 / 依据；能列成表的数据；这一版还没有 |
| 卡口、构建、断言、校验脚本 | 发布前的检查 |
| 提交标题原样（`fix:` `feat:`） | 网页上的「本站更新」读 `src/data/releases.json`（人工写、带真实提交号可回查）；git 那份自动生成在 `docs/CHANGELOG-DEV.md`，不进页面 |
| 数据加载失败时打印 `e.message` 与 shell 命令 | 一句"刷新一下试试"；只有 `file://` 打开时才给本地服务命令 |
| 「本页跑在 Vue 3 上，未迁的页面仍在旧站」 | 删。没迁的地址直接跳到有内容的那一页 |

两道闸拦同一份词表 `tools/copy-banned.json`：`build-data.js` 扫 `src/data/**.json` 的字符串值（含渲染用的
`meta.coordinateNote` / `notCollected`），`site-check.py` 第 18 节扫 14 页 + 来源展开后 + 新站两页**渲染出来的文字**。
词表大小写敏感——之前用 `i`  flag 时 `DOM` 命中了 `martyrdom`、`NaN` 命中了 `penance`，全是误报。
"大口径秘银步枪"这类物品名靠 `strip` 白名单放行，**不靠给词表加豁免**。

### 3.19 传承页（2026-10-10 参考站整合第三批）

页面 `legacy.html`，数据 `src/data/legacy.json`。这一页的设计目标是**把"客户端里有什么"讲清楚，
同时把"我们抄了什么"这条线摆在最显眼处**——它是全站红线最容易踩的一页。

- 结构顺序：标题段（规则三句话：每挑战 1 点 / 首发上限 16 点 / 第一个角色 25 级开放）→ 四个规模数
  （`.stats .stat`，全部读 `meta.counts`，不写死）→ 三棵树的切换条（`.picks [data-t]`）→
  树卡 `#ltree` → 详情 `#ldet` → 挑战筛选框 + 六组挑战表 `#lch` → 进度奖励表 → 「这一页没有的」+ 来源。
- **格子按客户端坐标摆，不重排**：每棵 4×4=16 格全画，三种状态各有独立写法——
  具名格 `.lslot`（图标 + 层数上限 + 中文名）、未公开格 `.lslot.unk`（虚线 + `?` + **文字"未公开"**，
  `title` 写"这一格客户端里有，但官方还没公布是什么"）、空格 `.lslot.none`（`aria-hidden`，只占位不加 tab 键）。
  断言卡的是 `具名 + 未公开 + 空 = 行×列`，谁手滑把空格省了立刻红。
- 详情卡是**页面上唯一讲一个专长的地方**，只许写：名字、层数上限、所属树、第几排第几列、前置、解包日期、分级徽标、来源。
  每层效果说明一律不写，卡口用**长度**兜底：`.src` 以外的详情正文 ≤200 字，超了就当抄了说明。
- 徽标口径：专长与树 `L0`（客户端解包的中文名，2026-10-08 决策算已核实）、
  挑战与进度奖励 `L2`（没进游戏一项项打过）。徽标一律 `D.pill()`，**除颜色外带文字**，
  65 条挑战每条一个"待实测"，不许只在页顶用一句说明代替逐条标注。
- 深链：`?t=<treeId>` 切树（不认识的值退回第一棵，不留空白页）；从首页搜索带**专长名**跳进来时
  直接切到它所在的树并展开详情，同时**把挑战筛选框留空**——只认全等匹配，避免"搜挑战时命中一个同名的专长"
  把下面的筛选抢掉（这个抢法是第一版实测出来的，`site-check` 有专门一条盯着）。
- 树的切换与格子点击都只改 `#ltree` / `#ldet` 两个容器（`repaint()`），不整页重渲染，输入框焦点不丢。
- 挑战分组卡是 `.lchgrp`，**不要图省事套别处的 `.lgrp`**——那是一条 `display:flex` 的"分组标题行"，
  套到装表格的卡片上会把表格挤成 487px 靠右摆；图标一律用全站统一的 `iconCell`（26px 格），
  别自己写 `<img class="ico">`（没有约束会按原图 56px 渲染，行高从 41px 撑到 110px）。
- 素材：56 个图标键里 55 个本地已有，`inv_tabard_legacyc60_b_01`（奖励披风）官方 CDN 回 403，
  已登记 `icon-gaps.json`，界面退回自绘块，不拿第三方站的图凑。

**卡片背景图规矩**：只用 `src/img/art/` 里已转存的本地原画，且**图必须和这块内容对得上**——
天赋卡用当前选中职业的背景（换职业跟着换）、副本卡用第一座无限新增本的载入图、区域卡用该区域小地图、

不拿别的板块的图凑数。层叠沿用种族页那套已验证写法：`.bgart` 绝对定位 `z-index:0` + 上压渐变 +

③ `.cta` 没有基础样式，同一张卡里两个 CTA 会挤成一句（"…17 条本站更新）→资料完整度排行全表 →"），

## 四b、新站（Vue 3 + Vite）的视觉与交互约束（2026-10-09 起）

2026-10-09 用户决策把表现层迁到 Vue 3 + Vite，**按页迁移、两栈并存**，`src/data/*.json` 仍是唯一数据基底。
本节只写新站必须守住的视觉与交互约束，工程约束在 `wow-forever-web/AGENTS.md`。

- **共用同一份样式文件**：`app/src/main.js` 直接 import `../../src/css/app.css`。迁移期设计令牌、
  组件状态、断点只有一处定义，否则"新旧两站对拍"变成比谁更像谁。全量迁完再拆 scoped style。
- **DOM 钩子不许改名**：`#top / #main / #foot / #toast`、`.card .band .pick .pill .liw .zmap .zmark`
  这些类名与 `data-t / data-z / data-r / data-zone` 属性，是 283 条断言与对拍脚本找元素的依据。
  组件化只改实现，不改对外可见的结构。
- **每迁一页必须过 `tools/app-parity.py --strict`**：结构计数、类名集合、正文文本行、链接、图片
  与旧站逐条比。差异要么归零，要么进脚本里的 `INTENTIONAL` 白名单并写明理由
  （目前只有一条：缺图不再渲染 `<img>`，省掉 9 个 404 请求，可见结果一致）。
- 仍然不引 UI 组件库、不引 Web 字体、不引图标库；素材一律本地文件、不热链。
- **不拼 HTML 字符串**：搜索高亮改成 `hlParts()` 拆片段 + `<mark>` 渲染，来源列表、正文一律走模板插值。
  旧站 691 行字符串拼接里有两类隐患：数据里出现 `<` 就是注入面，`&` 出现两次就是显示错字。
- 数据驱动的尺寸（覆盖率条宽度、小地图标记点 left/top）允许 `:style`，这是几何值不是样式风格；
  其余新增内联 `style=` 仍算欠账。
- 缺图/缺数据的回退要**在渲染前决定**，不靠 `onerror` 兜：新站 `IconCell` / `ZoneMap` 直接不渲染坏图，
  既没有失败请求也没有中间态类名。

## 七、设计走查清单（量化，可复查）

方法吸收自通用设计走查规则（ClawHub 上的 `design-review`，只取判据不引它的代码——那三个脚本查的是 React/TSX，我们是原生三件套）。**每一条都有对应断言在 `tools/site-check.py` 第 6 节，跑不过就不算做完。**

### 7.1 硬性判据

| 判据 | 标准 | 为什么 |
| --- | --- | --- |
| 每屏一个 H1 | `h1` 数量必须等于 1 | 屏幕阅读器靠它跳读；两个标题抢焦点等于没有标题 |
| 触屏点击目标 | 375px 下所有可点元素最小边 ≥ 44px | 手机上"能点到"优先于"省地方"；内边距算命中区 |
| 控件可读名 | 不允许有既无文字又无 `aria-label` 的可点元素 | 图标控件没名字，读屏用户只能瞎点 |
| 图片有 alt | 装饰图 `alt=""`，信息图必须有文字替代 | 天赋图标是装饰（旁边有中文名），所以统一 `alt=""` |
| 数字对齐 | 点数、覆盖率、区间用等宽 + `font-variant-numeric: tabular-nums` | 数字不对齐时，表格读数会看串行 |
| 层级靠排版不靠颜色 | 用字重与字号拉开层级，颜色只标状态 | 颜色单独承载信息，色弱用户和黑白打印都会丢信息 |
| 间距表达分组 | 先加空白再考虑边框；嵌套卡片多半是分组失败 | "tight inside, loose outside" |
| 文字对比度 | 逐页取「计算色 + 沿祖先第一个不透明背景」现算：正文 ≥4.5:1，≥24px 或 ≥18.66px 且 700 字重 ≥3:1 | 2026-10-10 加。人眼估不出 4.08 和 4.5 的差别，只有算出来才会去改 |
| 一个色相只服务一条语义轴 | 分级徽标的计算色不得等于 `--gold`；四种级别的徽标形状必须互不相同 | 琥珀金曾同时是品牌色与「待实测」色，选中格与"这条没核实"在页面上长一个样 |
| 声明了分级就要有轨 | 卡里出现分级徽标或数据类来源标签，该卡必须有 `data-lv` 与来源轨；反之没定级的卡不许有轨 | 轨是这站的签名元素，也是"哪部分可信"的入口；给没定级的卡硬加一条轨等于编造状态 |
| 动效可关 | `prefers-reduced-motion: reduce` 下卡片与轨道的动画时长 <5ms，且内容 opacity 回到 1 | 关掉动效不等于藏内容 |
| 键盘焦点可见 | Tab 到任意可点元素，`outline-width` ≥2px 且样式非 none | 原来 `:focus` 把 outline 关掉只留边框变色，键盘用户看不见落在哪 |
| 裸色值只减不增 | 组件规则里的 `#rrggbb` 数量对基线（2026-10-10 为 15 处）只降不升 | 令牌层一旦被绕过，配色就再也管不住 |
