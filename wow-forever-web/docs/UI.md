# 《无限》中文资料站 UI 设计规范 v1

依据：参考站 `wowclassicforever.info` 三页实拍（`docs/reference/wcf-home.png`、`wcf-talent.png`、`wcf-dungeons.png`）+ PRD v1.0。
实现约束：纯静态 HTML/CSS/JS，不引框架、不引 Web 字体、不引图标库；离线可跑。

---

## 一、从参考站提取的设计语言

参考站值得继承的三点，和两点必须改的地方：

**继承**
1. **暗色 + 暖金**：近黑底叠一层极淡的棕橙径向光晕，主强调色是琥珀金，读起来像游戏内 UI 而不是普通网页。
2. **三系并列的天赋版式**：一屏三列，每列自带列头（系图标 + 系名 + 解锁提示 + 单列清空），节点是 5 列网格 + 层级虚线分隔 + 依赖连线 + 右下角点数角标。这套版式信息密度高且玩家熟悉，照搬结构不照搬素材。
3. **底部工具条**：等级滑杆、复制方案、路线展示、重置、三系分布统计，全部一行解决，不弹层。

**必须改**
1. 参考站全大写小型衬线体（`WOW FOREVER WARRIOR TALENT CALCULATOR`）在中文里不成立 → 中文用系统无衬线，英文/数字保留等宽，标题靠字重与字距拉开层级，不靠小型大写。
2. 参考站没有"这条数据可不可信"的视觉表达 → 本站把 **完整度徽标（L0/L1/L2/L3）做成一等公民**，这是产品差异点，不是装饰。

## 二、设计令牌（写进 `src/css/tokens.css`）

### 2.1 颜色

| 令牌 | 值 | 用途 |
|------|-----|------|
| `--bg` | `#0e1013` | 页面底 |
| `--bg-glow` | `radial-gradient(1200px 600px at 50% -10%, rgba(120,72,32,.28), transparent 70%)` | 顶部暖光 |
| `--panel` | `#171a1f` | 卡片/面板 |
| `--panel-2` | `#1e222a` | 次级面板、输入框 |
| `--line` | `#2b3038` | 描边、分隔 |
| `--txt` | `#e7e9ee` | 正文 |
| `--txt-dim` | `#98a1af` | 次要文字 |
| `--gold` | `#e0a96d` | 主强调：标题、可点、选中边框 |
| `--gold-deep` | `#b8813f` | 强调按下态 |
| `--blue` | `#6fa8ff` | 链接、英文副名 |
| `--ok` | `#4caf72` | L0 已官方核实 |
| `--warn` | `#d9a13b` | L2 待实测 |
| `--lead` | `#7f8ea8` | L3 仅线索 |
| `--bad` | `#c9564a` | L3 缺失 / 冲突 / 错误 |

三系列头背景各自微调色相（暖橙 / 冷蓝 / 紫），只改 `background` 的 6–8% 透明度叠加，不改文字色，保证三列可辨但不花。

### 2.2 完整度徽标（全站统一，不可自创样式）

| 级别 | 文案 | 视觉 |
|------|------|------|
| L0 | 已官方核实 | 绿边 + 绿字，实心点 |
| L1 | 仅官方英文 | 蓝边蓝字 |
| L2 | 待实测 | 黄边黄字，节点右上角黄点 |
| L3 | 缺数据 | 灰边 + 斜纹底，节点整体降饱和 |

规则：**任何展示位只要有 L2/L3 字段，页面顶部必须挂一条黄/灰横幅说明"本站基于测试服数据，正式服上线后重核"**，不允许静默呈现。

### 2.3 字体与字号

```
--font-cn : -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif
--font-mono: ui-monospace, "SFMono-Regular", Menlo, Consolas, monospace
```

| 用途 | 字号/字重 | 备注 |
|------|----------|------|
| 页标题 | 20 / 600，字距 .5px | 中文 |
| 区块标题 | 15 / 600 | |
| 正文 | 14 / 400，行高 1.65 | |
| 次要 | 12 / 400，`--txt-dim` | |
| 数字/英文代号 | 13 / 500，等宽 | 点数、等级、build 号 |

### 2.4 间距与圆角

4 倍数体系：`4 / 8 / 12 / 16 / 24 / 32`；圆角 `6`（控件）、`8`（卡片）、`4`（徽标）；节点格 `46×46`（桌面）/ `40×40`（移动）。

## 三、页面结构

### 3.1 全局骨架

```
[顶栏] 站名 · 主导航（天赋/技能/副本/术语/溯源） · 上线倒计时 chip
[内容区] max-width 1180，居中
[底栏] 非官方声明 + 数据口径（build 号 + 核对日期） + 覆盖率摘要
```

顶栏在移动端折叠成汉堡；倒计时 chip 用等宽数字，`11-05` 前显示剩余天/时。

### 3.2 首页

1. 一句话定位 + 覆盖率总览条（L0/L1/L2/L3 四段横向堆叠条，鼠标悬停显示计数）；
2. 职业九宫格卡片：图标位 + 中文职业名 + 英文名 + 该职业数据完整度徽标 + 已收录天赋数；**数据不足的职业照常显示，用徽标说明缺口**；
3. 快捷入口：副本手册、术语速查、溯源页；
4. 搜索框（全站，回车进结果页）。

### 3.3 天赋计算器（核心页）

```
[职业条] 9 个职业方块，选中态金边
[面板头] 职业图标 · 剩余点数框 · 「XX 天赋」标题 · 搜索 · 已选/总数
[三系并列] 列头：系图标 + 系名(中英) + 解锁提示 + CLEAR
           网格：5 列 × N 层，层间虚线，依赖用 SVG 连线
           节点：图标位 + 右下点数角标 + 左上黄点(L2) + 悬停出 tooltip
[工具条] 等级滑杆 | 复制方案 | 显示路线 | 重置 | 三系分布 0/0/0 · 需求等级
[溯源条] 本树数据来源类型 + build 号 + 核对日期（一行，灰字）
```

节点四态：`可用`（正常）、`已点`（金边 + 角标 >0）、`锁定`（降饱和 + 禁用，tooltip 说明缺什么）、`缺数据`（斜纹底）。

移动端：三系改为 Tab 切换，单系全宽 5 列网格；工具条换行，滑杆占满。

Tooltip 内容顺序：中文名 → 英文名 → 已点/上限 → 效果描述（有则显示，L2 加黄点）→ 来源与核对日期。

### 3.4 技能书页

左侧职业/专精筛选，右侧表格化列表：中文名（主）、英文名（次，等宽）、类型（主动/被动/宠物）、来源徽标、复制按钮。顶部搜索实时过滤，命中片段高亮。

### 3.5 副本手册页

列表按"新本 / 经典本 / 团本"分组，卡片显示中英文名、等级区间、BOSS 数（无则显示"待实测"）、状态徽标。详情抽屉四段：路线、BOSS 与技能、掉落、来源与冲突记录。**冲突记录必须显式展示**（如 领主大厅 / 诸王大厅 并列），这是本站与"看起来完整"的站点的区别。

### 3.6 术语速查页

顶部搜索 + 分类筛选（技能/天赋/装备/副本/BOSS/系统/地名）+ 词条流式标签，点击复制。分组按职业。空结果显示"暂无官方中文名，已保留英文"。

### 3.7 溯源页

覆盖率总表（按模块 × L0-L3）、未证实清单（编号列表）、来源站点清单（标注"人工参照，禁止搬数据"）、数据口径时间线（build 号 → 日期）。

## 四、交互与状态

| 场景 | 规格 |
|------|------|
| 加载 | 分片 JSON 加载中显示骨架条，不显示 spinner 遮挡内容 |
| 加载失败 | 面板内错误态 + 「重试」按钮，保留已加载部分 |
| 空结果 | 明确文案"没有匹配条目"，给一个放宽搜索的按钮 |
| 复制成功 | 右上角 toast，1.8 s 自动消失，文案含被复制内容前 12 字 |
| 本地存储不可用 | 顶栏灰条提示"仅本次有效"，分享链接仍可用 |
| 方案与数据版本不符 | toast 警告 + 按可识别部分还原，丢弃项列在 tooltip |
| 点击反馈 | 节点 `transform: translateY(1px)` + 边框高亮，120 ms |
| 动效 | 只用 `transition`，时长 120–180 ms，`ease-out`；不做入场动画 |

无障碍：节点可 `Tab` 聚焦、`Enter` 加点、`Backspace` 减点；徽标除颜色外必须有文字，不靠颜色单独承载信息；对比度正文 ≥ 4.5:1。

## 五、文件结构

```
src/
  index.html  talent.html  skills.html  dungeons.html  glossary.html  provenance.html
  css/tokens.css  base.css  components.css  pages.css
  js/store.js  talent.js  render.js  search.js  main.js
  data/*.json  data/talents/*.json  data/dungeons/*.json
tools/build-data.js   # 校验 + 覆盖率 + 分片，不达标退出码非 0
```

命名：中文界面上的职业/技能/天赋一律用官方中文名，英文原名并列显示，**不做机翻兜底**。

## 六、运行与校验

```bash
cd src && python3 -m http.server 8812      # 访问 http://127.0.0.1:8812（不能用 file:// 直接打开）
node tools/build-data.js                    # 数据校验 + 覆盖率，不通过退出码非 0
```

当前状态：六页可跑。天赋引擎已用**真实数据**验证通过（加点、点数上限、前置拦截、级联减点、总点数封顶、分享编码往返、本地持久化），另留一棵标明"非游戏数据"的演示树做回归。

数据现状：

- **词条 215 条官方中文名**：猎人 62、德鲁伊 61、战士 38、牧师 18、装备 3、种族技能 33。
- **天赋节点 470 个，九职业齐全**：含名称、所属系、点数上限、66 条已解析前置。来源是第三方数据挖掘（上游标称 build `b1eb593d9cd26007`，采集于 2026-09-13），**全部标 L2 待实测**；其中 89 条名称与官网中文用词完全一致，用作质量交叉验证。
- **刻意未采用**：第三方站的行列坐标。它的九职业都是 4 行 × 7 列，与经典三系 51 点的 10 行 × 5 列不符，判定为排版坐标而非游戏层级，用错会直接误导加点；另外未复制其中文天赋描述文本。
- **仍然缺**：游戏内真实层级与列位、英文原名、完整前置链（470 个节点只有 66 条带前置）、以及圣骑士/萨满/法师/术士/潜行者五职业的官方中文稿。

因此天赋页在层级未核实前用**列表模式**渲染（按系分组、显示上限与前置），不画成看起来权威的天赋树；等客户端或实测数据到位后再切回网格布局。
