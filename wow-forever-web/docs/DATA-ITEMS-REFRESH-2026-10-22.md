## 二、这 2,496 件"有改动→没有变化"是谁的判断，我们信到什么程度

**是参考站自己重算了与经典旧世的对照，不是我们改的口径。** 它页面顶部现在写
"当前版本 1.60.1.70450 Beta"，`_shuju` 那份 meta 里 `classicBuild` 是 `1.15.9.70003`——
我判断它换了对照基准或修了自己的 diff 逻辑，**但它页面上没有留下任何一句说明，我无法验证**。

按站主"以最新数据为准、历史留档不删"那条既有决定跟了。三件事必须记清楚：

1. **这是单源的一次重算**。我们这边没有第二个东西能仲裁"某件装备到底改没改过"——
   客户端侧的文本是韩文（见 `DATA-WINDOWS-RUN2-2026-10-22.md`），对不了属性。
2. **旧值没有丢**：10-13 那份快照整份留在 `upstream/` 的 git 历史里，
   逐件差值清单我这次算的时候落在 `/tmp/items-delta.json`（临时件，不进库；
   要长期留就把这份文档第一节的两张表当记录）。
3. **如果它以后翻回去，我们这边会再次整体翻转**。所以这条是**可回退的跟随**，
   不是我们独立确认过的事实；界面上这一格仍然只是"参考站说它跟经典旧世比有没有变"。

## 三、下架那 9 件：查过参考站现在也是 404，不是抓取漏了

## 七、补记：图标那条我说过一个数，更正

发版前我把"问号变真图"这件事按新旧两份成品逐 id 复算了一遍，**我前面口头讲的"34 件"不准**，
准确的数是：

| 项 | 数 |
| --- | --- |
| 旧成品里挂 `inv_misc_questionmark` 占位的 | **40 件** |
| 这次上游名录给了真图标名的（＝真的从问号变真图） | **36 件** |
| 上游自己也只给到问号的 | 4 件 |
| 新成品里挂问号的总数 | **26 件**（＝旧的 4 件 ＋ 这次新增 228 件里上游直接给问号的 22 件） |

**30 张**那个数指的是**这次从官方 CDN 下载并落盘的图标文件数**（`fetch-icons.py` 实测 200），
两件事不是一回事，之前混在一句话里说了。36 件变真图、30 张新文件、缺图登记 1→2，
这三个数各自成立。

顺带一条新发现的口径问题：**上游对拿不到图标的物品，填的就是 `inv_misc_questionmark` 这个真图标名**，
所以它进我们库里会显示成一个问号图，而 `build-icon-map.py` 认为"这个文件本地有"，
**不计入缺图登记**——也就是说"上游其实不知道这件长什么样"这件事，在缺图统计里是隐形的。
本轮不改统计口径（改了要和 `icon-gaps` 那套断言一起动），先记在这里。

## 八、门禁

第一次全跑 **918 / 920**，两条红的**都是门禁判据自己错**，不是页面坏：

1. 配装页那排属性合计芯片用 `v-show`——值为 0 的一格只是 CSS 隐藏、**节点还在 DOM 里**，
   判据用 `innerText` 全读，于是界面凭空多出一个空的「精神」。改成按 `offsetParent` 过滤可见节点。
2. 物品库「测试服有」那一格：名录重算后它从 **82 条掉到 3 条**，而页脚那句"共 N 件"在 `.pager` 里、
   `.pager` 是 `v-if="pages > 1"`——**不足一页时分页条整条不渲染**，判据读到空串。
   改成分两种情况判：不足一页就比行数并要求没有分页条，超过一页才读页脚。

两处都加注释写明"是判据错不是页面错"，改完重跑受影响的两段 **110 / 110 全过**。
最终全量重跑（因为 `releases.json` 与 `scale.json` 在第一次全跑之后又变了）：**920 / 920 全过，rc=0**。
