# 物品详情三源评估（wclbox 试采 200 件，方案 B 评估步）

日期：2026-10-15 出结论（试采当晚跑完）。样本与方法：从全名录 21,077 件按等步长抽 200 件
（`upstream/wclbox-items-detail-sample.json`，全部成功、无一失败、无封禁迹象，礼貌间隔 0.5s），
逐件抓 wclbox 物品详情页（SSR 可见文本解析），与现有 `items-detail.json`（GI beta 解包 69876 +
XR 社区稿）逐件对照。工具：`tools/scrape-wclbox-items-detail.py`。

## 1. 覆盖对比（同 200 件上）

| 字段 | wclbox 详情 | 现有（GI+XR） | wclbox 净增量 |
| --- | --- | --- | --- |
| 属性行 st | 120 | 130（其中 XR 兜底 116） | **+14** |
| 卖价 sell | 144 | 124 | **+26** |
| 来源 NPC srcNpc | 110 | ——（GI 是"本·首领"串，字段口径不同） | —— |

样本里 40% 是无属性的消费/杂项（st 天然为空），wclbox 的 sell 144/200 其余为无售价任务物品等。

## 2. 关键发现：现有数据多数是旧 build 的数值

双方都有属性的 106 件里，行集 100% 不一致——大头是格式差异，但**实质数值差异确凿**：

- 硬根法杖（1317）：wclbox 44-67 伤害 / 每秒 16.8 / **+8 精神** vs GI+XR 36-54 / 每秒 13.6 / **+9 精神 +20 法术强度**
- 大使之靴（2033）：护甲 59 / **+4 敏捷 +4 耐力** vs 62 / **+3 敏捷 +5 耐力 +4 精神**
- 卖价不一致 7/118（35银 vs 42银18铜 等）

根因：站内现有 st 主要来自 XR（12,317 条，数据 2026-09-20）与 GI（beta 69876，10-03），
而 wclbox 详情是**当前 build 1.60.1.70338**——数值随 build 改过，站内线上展示的是旧数值。
（试采解析器当时 build 号正则只抓三段，已修为四段；行集对比含格式噪声，结论只取数值差异部分。）

## 3. 结论

1. **wclbox 详情全量抓值得做**：它不是"第三源"，而是当前 build 的**权威转述**——应升为属性/卖价的
   第一优先级，重排为 **wclbox（70338）> GI loot 实测（69913）> XR（09-20）**；GI 实测值不废弃，
   它与解包值的差异本身就是"版本间改动"的证据，留在 conflicts 里交代。
2. **全量成本可接受**：21,077 页 × ~0.6s ≈ 4-6 小时，后台一晚跑完；试采 200 件零失败，
   解析器已就绪（`--count` 去掉即全量）。
3. **动作**：全量抓取 → `upstream/wclbox-items-detail.json` → `merge-items-detail.py` 加最高优先级
   源 → 重跑 build-data/门禁 → 抽屉 stFrom 徽标补"wclbox 当前版"。
4. **待站主拍板**：今晚就后台跑全量，还是等 11-05 开服后再抓一次到位（build 还会动）。
   ——建议：**现在跑一轮垫底，开服后按 build 号增量重抓**；管线是幂等的，重跑即更新。

## 5. 全量执行记录（2026-10-16，站主拍板"现在跑一轮垫底"）

站主 2026-10-15 一句话派活"W2-3 wclbox 采集全量数据"，按本节第 3 条的建议执行：当天后台跑全量，
开服后按 build 号增量重抓。**没有直接扩数量就开跑**——先把试采那版解析器拿去对页面结构，
发现四个会在 21,077 件上变成脏数据的问题，全部修完才开跑（第 1、2 两条正是本节 §2 那个
"行集 100% 不一致"的真因）：

| # | 试采版的毛病 | 全量版怎么改 |
| --- | --- | --- |
| 1 | 按"可见文本行的位置"取属性，而页面每件是**两块对照 tooltip**（`.wp-pair` 下两个 `.wp-tip`：经典怀旧服 1.15.9.70003 / 无限测试版 1.60.1.70374），两边扫成一串 | 按 `.wp-label` 切边：无限侧整条留，经典侧只留被 `wp-del` 标出的改动行；行级 `wp-add`/`wp-del` 就是页面自己标的差异，一并留档 |
| 2 | 名称按行位置取，28/200 错位（争战手套那类取到「›」） | 这份**不取名**，名称一律以 `items.json` 名录为准 |
| 3 | 属性行里混进 tooltip 的**风味引句**（`.wp-flavor`，例："血色十字军领袖之剑"） | 抓取阶段按类名丢掉；合并层再对三份源统一剔"整行被引号包住的"那一类；`build-data.js` 加同一条闸 |
| 4 | 把来源那一节当 `<div>` 匹配，实际是 `<p class="wp-drops">` → 一条都没取到（第一版跑完 1,600 件才暴露，全量重跑，那 17 分钟作废） | 按 `<p>` 取，拆出 `srcNpc` + `srcZone` |

另一处是上游自己变了：**页面自报状态不是四种而是五种**，多出 `wp-status-held`
（"客户端保留了这件的数据行，却没有属性——属性由服务器在游戏中下发，在有人记录下来之前，
下面显示的是经典怀旧服的提示框"）。它和 `missing` 一样，**摆的是经典侧的数**，
所以合并层把 `missing` / `held` 两类一律排除在"按无限解包取属性"之外（记录里带 `tipIsClassic`），
并在页面上钉了一条断言：名录标"无限中没有"的件不许挂"无限测试版 · 客户端解包"的标。

### 5.1 实测成本与产出

- 21,077 件逐页，单线程 + 逐件 0.5s，**216.6 分钟跑完，0 件失败、0 件封禁迹象**（1.62 件/秒）。
  试采估的"4-6 小时"是按未压缩页面算的；加了 `Accept-Encoding: gzip` 后单页 76 KB → 15 KB，
  既省对方带宽也省本机时间。产物 `src/data/upstream/wclbox-items-detail.json` 7.7 MB。
- 上游 build 已从评估时的 70338 走到 **1.60.1.70374**（对照客户端 1.15.9.70003）。
- 快照自报状态分布与名称索引**逐类对平**：不变 7,678 / 有改动 6,102 / 无限新增 5,346 /
  无限中没有 1,334 + 保留但没属性 610 = 1,944 / 重建 7（索引那 7 件详情页没给状态）。
  这条对照是白捡的：说明两次抓取（10-13 的索引、10-16 的详情）跨 build 仍然自洽。
- 字段覆盖：属性 17,223 / 卖价 13,208 / 来源 NPC 11,447（其中带区域 11,260）。

### 5.2 合并后的成品（层级按 §3 重排）

`tools/merge-items-detail.py` 现在是 **wclbox（当前 beta 解包）> GI（Beta 实测转述）> XR（社区稿）**：

| | 旧成品（两份源） | 新成品（三份源） |
| --- | --- | --- |
| 有详情的件 | 14,066（66.7%） | **20,528（97.4%）** |
| 属性 | 13,673（GI 1,370 / XR 12,303） | **19,605（解包 17,223 / 实测 880 / 社区稿 1,502）** |
| 卖价 | 12,433（只有 XR） | **15,466（解包 13,208 / 社区稿 2,258）** |
| 出处 | 1,501（只有 GI） | 1,501（不变） |

差异不再用"整串相等"判（那会把写法差异算成版本差异），改成两把尺子分开数：
**归一后完全相同 0 计入、数值签名相同但文字不同 8,458 件对（`formatOnly`）、数字真对不上 2,487 件对（进 `conflicts`）**——
后者才是"版本之间改过数值"的证据，GI 与 XR 之间的旧差异照原样留着。
另有 **1,763 行"整行被引号包住"的句子**（GI 126 / XR 1,637，10-14 那批直接混在属性里）——
按 §5.4 分家后：**1,207 件收成教益句进 `use`，448 行纯风味句丢掉**，句中才带引号的 6 行功能文本原样留。

### 5.4 差点把有用的东西改没了：教益句与风味句在同一个框里

按参考站自己的分类把 `.wp-flavor` 丢掉之后，抽样发现**图样/秘典/公式/设计图这类件的教益句
（"教你学会制作鬼纹腰带。"）也在同一个斜体框里**：参考站把它标成风味句，插件源则整句带引号抄回。
两头一扣，合并后 **1,197 件**只剩"需要工程学 (125)"这种行——比 2026-10-14 那版还少一句关键话。
这类件的名字本身就说明"教你学会制作X"是它唯一有用的信息。

处理：合并层按**内容**分家而不是按引号分家——

- 教益句（含 `教你 / 学会 / 可启动`）剥掉引号，单独立 `use` 字段 + `useFrom`，页面上"学会 / 启动"自成一段；
  成品里 1,207 件带上。本轮 `use` 只能按 GI > XR 补（快照没带这层），抓取脚本已改成下一轮按 build
  重抓时自己从解包侧带上，那时 `useFrom` 会出现 `wclbox`。
- 纯风味句（"相信我，她会明白的。"）丢，本轮 448 行。
- 句中才出现引号的（"使用：为角色解锁“炼金师”头衔"）原样留在属性里，6 行——一刀切引号会把这些真信息删掉。
- `build-data.js` 的闸跟着收窄成"**整行**被引号包住才算风味句"，否则这 6 行会误报。

### 5.6 决策改口（2026-10-16，站主）

本文 §3 那句"wclbox 应升为属性/卖价第一优先级"**已被推翻**：站主同日在阶段 PRD 的 Q1 上选 B——**取值也以插件为准**。`merge-items-detail.py` 已反转成 GI > XR > wclbox 并重出成品。
实测后果（不是估计）：属性件数 19,605 不变，5,974 件仍由当前解包兜底（含无限新增 1,374 件）；11,250 件显示值换回插件那套，其中与当前 build 数值签名不同 1,701 件全部留在 `meta.conflicts`。**开服后如果数值继续漂，这一档差异会变大**——真要改回 A，只要把合并脚本的顺序换回去重跑一轮，上游三份快照都没动。
