# 客户端里有什么 · 2026-10-21 实测（wow-data）

站主给了新事实并开了访问：**本机有无限服客户端**（Windows 在 `192.168.0.105`，共享账号可读），
`C:\GAME\World of Warcraft\_forever_`，插件也更新过。这一份是**连上去实际读到的东西**，不是推测。

一句话结论：**有，而且比预期多。** 分三层——
① **插件层现在就能用**：XR 从我们用的 66 版跳到 **75 版**，而且我们以前只用了它 37 个数据文件里的 **1 个**；
② **美术层在 CASC 归档里，能读但要解码**：`Data\` 64 GB 我列得动（740 个 `.idx`），但要一个 CASC 读取器才能取文件；
③ **有两条红线正好撞上来了**，见第四节，不取。

**注意这是作者自报的实测结论，本站不跟着进游戏，按 L1 单源留档，不升 L0。**

已把这三个插件从客户端**原样拷到仓库外**：`.scratch/wow-client-2026-10-21/`（79 MB，含 Media）。
没覆盖旧的 66 版快照，两条来源分开记，插件本体不进 git（红线：不分发插件本体）。

## 三、第二层：美术层在 CASC 里，能读但要解码

四类缺口（区域底图 9、首领头像 82、载入图 2、图标 161 键）的原始文件都在
`Data\{indices,data,config}` 这套 CASC 归档里，**不是散文件**——`Interface\` 下只有插件自带的图。
这也解释了上一轮"插件 157 个图片文件按九个地图号 0 命中"：GI/DF 的区域地图是调
`WorldMapFrame.SetMapID` / `SetTexture(Interface\WorldMap\…)` **现渲染**的。

SMB 这边我列得动归档（`Data/data` 740 个 `.idx` 能读），所以取文件有两条路：

| 路 | 要什么 | 代价与风险 |
| --- | --- | --- |
| **B1 · Windows 上跑只读 CASC 导出器**（CASCView / TactExplorer / Marisa 一类） | 在那台机器上装一个工具，按清单导出 PNG/TGA/CSV | 最快最稳；工具是第三方，**只用只读导出，不装任何改客户端/注入/自动化的东西** |
| **B2 · 我这边写一个 CASC 读取器**（走 SMB 读归档） | 装一个 CASC 解析依赖（如 npm 上的纯 TS 实现），自己解 EKey→文件→BLP/TEX 转 PNG | 不用碰那台机器，但是**一个真正的工程**（命名表/编码表/稀疏与补丁编码 + BLP 解码），几小时起，且要能验证解出来的图是对的 |

**要导什么我已经列成机器可读清单**：`docs/data-base/client-2026-10-21/export-manifest.json`
（9 个 mapId、82 只首领按本分组、2 张载入图、161 个图标键含按文件分布、想要的 DB2 表名）。
头像那 82 个建议**先解出 `Data_BossModel.lua` 的 displayId 再导**，否则只能按名字猜贴图，容易配错脸——
我们现在的原则就是"宁可不配，不配错脸"。
