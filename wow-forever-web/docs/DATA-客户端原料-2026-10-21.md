# 客户端能给我们什么 · 2026-10-21（wow-data）

站主给了一条新事实：**本机有无限服游戏客户端**，`C:\GAME\World of Warcraft\_forever_`，插件也更新了。
这一份写清三件事：**我实际访问到了什么**、**客户端里哪些东西是我们缺的**、**要拿到它需要谁做哪一步**。

结论一句话：**客户端确实能补上我们挂着的四类缺口（区域底图 9、首领头像 82、载入图 2、图标 161 键），
但它不是"拷文件夹"就能用的——美术与数据表都在 CASC 归档里，必须先在 Windows 上做一次只读导出。**

---

## 一、我这边的实际访问情况（可复现，不是猜）

那台 Windows 在局域网里能碰到，共享也列得出来，但**读不了游戏那个共享**：

| 探到的 | 结果 |
| --- | --- |
| `192.168.0.105` 的 445 / 139 端口 | 开 |
| `smbutil view -g //192.168.0.105` | 列出四个共享：`ADMIN$`、`World of Warcraft`、`Users`、`D$` |
| 挂 `Users` 共享（访客） | **能读**（只有 `Default`、`duowan/yy`，游戏不在这里） |
| 挂 `World of Warcraft` 共享（访客） | **Permission denied** —— 共享 ACL 不给匿名读 |
| 挂 `D$` | 失败（同样受限） |
| 本机 BOOTCAMP 分区 | 挂了看了，**没有游戏**（只有系统与雷顿/Steam 相关文件） |

所以现在卡的不是"有没有客户端"，是**我拿不到读权限**。三条解法任选一条，见第四节。

---

## 二、为什么不能直接拷：客户端的存储方式

`_forever_` 目录里能直接看见的通常是 `Interface\AddOns\`（插件）、`Logs\`、`Data\`、`_Version.txt` 这几样。
**我们要的东西全在 `Data\` 里的 CASC 归档中**（几千个 `.index` / `.manifest` / 编码块），不是散文件：

| 我们缺的 | 在客户端里的真实位置 | 能不能直接拷 |
| --- | --- | --- |
| 161 个物品/专业图标 | CASC 里的 `Interface/Icons/*.blp` | ✗ 要导出并转格式 |
| 9 张区域底图 | CASC 里的 `Textures/Maps/*`（`.tex`/`.blp`） | ✗ 同上 |
| 82 只首领头像 | CASC 里的 `Interface/CharacterScreen` / `Textures` 相关 | ✗ 同上 |
| 2 张团本载入图 | CASC 里的 `Interface/GLues/Loadings/*` | ✗ 同上 |
| 插件数据（GI/XR/DF） | `Interface\AddOns\*\*.lua` | ✓ **这个能直接拷** |
| 客户端 build 号 | `_Version.txt` / `Versions.txt` | ✓ 能直接拷 |
| 数据表（名字/等级/掉落归属） | CASC 里的 `DBFilesClient/*.db2` | ✗ 要导出成 CSV |

**这一条也解释了为什么以前"插件目录搜 157 个图片文件、九个地图号 0 命中"**：GI/DF 的区域地图是调游戏
`WorldMapFrame.SetMapID` / `SetTexture(Interface\WorldMap\…)` **现渲染**的，不随包带图。图在客户端本体里，不在插件里。

## 三、拿到之后能结算什么（按值不值当排）

1. **数据表最值当**（体积小、一次性、能把 `待实测` 变成一手值）：
   `ItemSparse` / `ItemIcon` / `Spell` / `MapArea` / `MapDiff` / `AreaTable` / `PlayerClass` / `PlayerRace` / `CreatureDisplayInfo`。
   我们现在对外 695 条词条的分级是 **L0 366 / L1 326 / L2 1 / L3 2**（`scale.json`）——
   大头是 **L1：326 条只有单一来源、多数是第三方站或插件自报**。
   有了 DB2，这些里属于"客户端里就写着、我们只能引第三方转述"的那部分能变成**客户端一手 + build 号**，
   不再依赖参考站自报（按 `datamine_cn` 那条例外处理，仍要带来源与抓取日期）。
   顺带把 `meta.dataBaseline.build` 从"第三方转述的 1.60.1.70338"换成**我们自己读到的版本号**。
2. **161 个图标**：物品库里 159 个键是无限新增装备，官方 CDN 拿不到，客户端里几乎一定有自己的图标文件。
   这是**覆盖率最直观的一跳**——物品库 21,077 件里那 161 个字母块换成真图。
3. **9 张区域底图**：世界页那九个区现在走"无图紧凑态"（只有地图编号 + 点位清单）。拿到图就能画点位。
4. **82 只首领头像 + 2 张载入图**：锦上添花，优先级最低（副本页没脸也能读，我们已给自绘块）。

## 四、要谁做哪一步（三条路，任选一条就够开工）

**A 路 · 最省事，今天就能做**：在 Windows 上把 `Interface\AddOns` 整个文件夹 + `_Version.txt`/`Versions.txt`
拷到一个我能读的地方（比如放进 `Users` 那个共享里，或者干脆拷到 BOOTCAMP 分区）。
→ 我拿它做**插件数据再同步**（A03），并给 `dataBaseline` 换成一手 build 号。这条路**不需要任何导出工具**。

**B 路 · 解锁图标与地图（推荐）**：在 Windows 上装一个**只读**的 CASC 浏览器/导出器
（常见的是 CASCView、TactExplorer、Marisa 这类，选一个能"按文件名列出并导出为 PNG/TGA/CSV"的就行），
按我这份清单导出：`docs/data-base/client-2026-10-21/export-manifest.json`
（161 个图标键、9 个 mapId、82 只首领按本分组、2 张载入图，都列好了）。
导出结果丢进同一个共享目录，我接手转 webp、进 manifest、跑卡口。

**C 路 · 给我读权限**：把 `World of Warcraft` 那个共享的 ACL 加上 `Everyone` 只读，
或者给我一个能登录的 Windows 用户名/密码（我不会存进仓库，只挂本机）。
→ 之后 A、B 两路我都能自己推进去，包括先替你确认哪些路径真有文件。

**要提醒的两点**：
- 别为了导数据去装任何**改客户端/注入/自动化**的东西，也别把账号密码写进任何会进 git 的文件。
  我们只做只读导出，这条按红线走。
- 从客户端导出来的图与表**仍然要逐张核**：客户端里有图不等于图对得上我们要的那个区；
  无限新增的那几座（河林 2548、辛德拉 2652）没有经典旧世参照，拿到也只能自证，核不上就继续留无图态。

## 五、我这边接手后会做什么（不用你再想）

1. 素材进 `src/img/`（图标进 `img/icons/`、区域图进 `img/art/maps/`、头像进 `img/art/bosses/`），
   每张在对应 `manifest.json` 记 **来源 = 客户端导出 + build 号 + 日期 + 哈希**；
   这四类目录都保留"整目录删除即回退到自绘/无图态"的下线方案。
2. 图标补上后跑 `build-icon-map.py` 重算缺图登记，`--check` 必须仍然双向一致
   （引用 − 本地 = 登记），漏登记/过期/死条目都会红。
3. 数据表结算的字段走既有合并链（`merge-*.py` → 成品 → `build-data.js` 卡口），
   **不自动升 L0**：客户端一手值我们按 `datamine_cn` 那条例外处理，带 url/来源与抓取日期。
4. 跑针对性回归（世界页 / 物品库 / 副本详情 / 种族页 + 375 实拍），改了界面才跑整站；
   然后重打包 `release-package.py` + `deploy-gh-pages.py --push` 发一次。
