## 交付

`video2text/scripts/agent/prepare_guide_release.py` 已落地，提交 `e0c471b`、`78c9699`，只新增一份隔离的出包脚本，不改共享工作台、生产库、出图模板，也不触碰平台账号。它读取现有 `output/poster/<id>/manifest.json`，第一次运行生成逐项人工审稿 JSON；只有复跑通过，才在**全新目录**输出 `copy_text.txt`、按页码的 PNG 和含原 manifest/审稿文件哈希的 `release_receipt.json`。成品变动会使旧审稿记录失效；现有发布包不会被覆盖。工具仅给“人工待发布”文件，不替号主登录、勾原创或发布。

### 实际操作顺序

1. 打开本机 [排产表](http://127.0.0.1:15801/static/schedule.html) 选一题。排产表的颜色是线索优先级，不是内容质量。当天第一候选 `odur` 是**时光服奥杜尔**，与 Forever 线不同，必须排除；现有 Forever 槽位多为未来节点且 `official` 空，不能仅凭颜色强行发。2026-10-21 的两篇[官方新消息：九座新地下城](https://wow.blizzard.cn/news/24301455/index.html)、[团队副本概览](https://wow.blizzard.cn/news/24303009/)可作为**新增候选线索**，先由内容角色挑一个具体玩家问题并核本站数据；不把官方表格照搬成自己的原创攻略。
2. 在排产任务中采用素材、确定玩家问题和本站新增贡献；转写只当研究输入。按 [改造后工作流](PLAN-video2text-改造后工作流-2026-10-21.md) 先审文字和来源，再选有解释作用且有使用依据的真实关键帧，之后预览和正式出图。若只有资讯事实，稿件身份写“资料整理/速查”，不要硬叫亲测攻略。
3. 在 `video2text` 仓库根运行一次（把 `<id>` 换成新成品号）：

   ```bash
   /usr/local/bin/python3 scripts/agent/prepare_guide_release.py \
     --manifest output/poster/<id>/manifest.json \
     --review output/发布准备/<id>-review.json \
     --out output/发布准备/<id>-release-v1
   ```

   首次退出 1 是正常行为：它只创建审稿表，不会出包。核完整文字稿、最终配文、事实风险与警告、每页图片解释作用和使用依据、头条文章/微头条体裁、AI 声明和原创判断，逐项填表；这些都是人工判断，不能批量勾 true。
4. 填完后执行同一命令。退出 0 才会出现 `copy_text.txt`、有序 PNG 与回执；退出 2 表示仍是草稿，按逐条报错返回改稿/核源/撤图。最终仍由号主在头条后台查看实际编辑框、手动上传和发布。**声明原创不默认勾选**，按成品及[头条原创规则](https://baike.toutiao.com/detail/242/243/0?enter_from=left_navigation)逐篇判断。发出后按现有运营台账登记与 72 小时回填。
