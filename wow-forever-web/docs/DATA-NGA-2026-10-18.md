### 更正（同日二次复测，2026-10-18 下午）

我第一次写的是"板块全量列表与正文**必须登录**"。**正文那条成立，列表那条说满了**，更正如下：

- 同一台机器、同一个真 Chrome、同一条 `thread.php?fid=510569`：**第一次导航渲染出完整板块**（390 个 `read.php` 链接、六个子版：精华区 / 蓝贴&内容更新专区 / 九个职业版 / 公会招募 / 无限服插件讨论区 / 剧情讨论合集，分页 1–6）；**过一会儿再导航同一条 URL，直接返回「访客不能直接访问」**。
- 差异出在浏览器多了一个 **`bbsmisccookies`** cookie——它不在服务端 `Set-Cookie` 里，是**页面 JS 生成的**。所以纯 curl 只带 `ngaPassportUid=guest…` 两步握手**打不开**（实测 403），在已渲染页面里用 `fetch` 打 `read.php` / `thread.php?page=3` **也 403**。
- 结论改写成可执行的口径：**板块网页端在访客态是"要执行 JS 且随时可能拒"的，不稳定**，不能排进无人值守的每日任务；要稳定全量就得登录（代价见第四节）。**当天真正稳的只有 App 的 `subject/hot`**——同一天我打了 6 次以上，除分页参数那几次外全部 `code=0`、32 条。
- 这条更正要留着：下一轮如果有人发现"网页列表忽然能抓了"，别按能抓设计产线，先复测三次再说。

## 二、三个会咬人的坑（都当场撞过）

1. **热帖接口没有下一页，而且加参数不是报错、是清空。**
   `page=2`、`row=60`、`rows=60`、`n=60`、`np=60`、`tpage=2`、`order_by=...` —— 任何一个塞进去，返回都是 `code=0` 但 **0 条**。看着像"接口挂了/被限流"，实际是这个动作不支持这些参数。**32 条就是上限，取完就取完了。**脚本里把这几个参数列成了 `PAGE_PARAMS_ARE_POISON`，不要"顺手加个分页试试"。
2. **服务端缓存 1 小时。** 响应顶层 `expire_at` 距当次运行正好约 60 分钟；两次连续请求 tid 集合完全一致。所以"每天更新"跑 1 次和跑 24 次拿到的东西差别不大，**跑得更密只是白打接口**。
3. **本机（这台 Intel Mac）TLS 链里有自签证书。** 装了零信任代理（进程里能看到 `aTrustAgent`），`urllib` 默认校验直接 `CERTIFICATE_VERIFY_FAILED`。脚本的处理方式是**默认严格、失败时提示**，要放开必须显式 `NGA_INSECURE=1`（会打一行警告）。**换到没有这类代理的机器上跑，就不该带这个环境变量。**

## 四、要全量和正文的代价（不是"再写点代码"能解决的）

**正文必须登录；全量列表要执行 JS 且随时可能被拒**（见第一节更正）。要稳定的全量+正文，只有两条路，都不轻：

| 路子 | 怎么做 | 代价 |
| --- | --- | --- |
| 复用已登录的真 Chrome + 页内 fetch | 跟你 wowhead 那条线跑通的方式一样（只有已登录真 Chrome 进得去） | **人工依赖**：会话过期就得重新登录，不适合无人值守的"每天自动"；且这是**用你个人账号的授权换机器访问** |
| 存 cookie（`ngaPassportUid` + `ngaPassportCid`）跑脚本 | 社区那几个 NGA 工具（一键存贴、IP 爬虫）全是这个做法 | **账号风险归你**：NGA 能看到"同账号高频规律请求"，一天一次的定时特征很明显；cookie 会过期要人工续 |

我的建议：**不为了"全量"去上登录态**。理由见下一节——你要的东西不需要全量，而上了登录态，风险从"平台可能封 IP"变成"你的 NGA 账号可能被处理"，这两者不对等。

## 六、每天更新怎么落地（脚本已就绪，缺的只是调度）

```bash
cd <仓库>/wow-forever-web && python3 tools/scrape-nga-forever.py
# 想一天两次（早晚各一次，覆盖缓存周期）就各跑一遍，同日文件会被覆盖——
# 若真要留两份，改 --out-dir 传目录名，别改脚本里的日期命名规则
```

调度放在**目标机器**（现在这台已迁走）：macOS 用 launchd（`StartCalendarInterval`，每天 08:30 与 21:30 各一次），Linux 用 cron `30 8,21 * * *`。两条要注意：

1. **别在这台机器上排**。这台装了零信任代理，脚本得带 `NGA_INSECURE=1` 才能跑；带这个环境变量的无人值守任务是我不建议留的东西。
2. **失败要出声**。脚本对非 0 code、0 条、异常都返回退出码 1 并打印原因（含"访客政策可能又收紧了"这句提示）。调度里接一个失败通知，或至少让它写日志——这个接口是**非公开 App 接口**，社区文档（`wolfcon/NGA-API-Documents`）自己都注明"可能不全"，**随时可能改**，静默失败会让你以为板块今天没人发帖。

**没验到的**：① 板块当天新帖总量到底多少（访客态拿不到全量，所以"32 条覆盖率有多低"我给不出数）；② 11/5 开服当天这个热帖榜会不会被冲爆（当天热帖可能全是水帖，参考价值下降）；③ `subject/act=hot` 的排序权重（是回复数、还是时间衰减，服务端没暴露，我只能从样本反推它是"当天热度"）。这三条真要当结论用之前得复测。

### 两个当天撞出来的坑（都会让人误判成"被封了"）

1. **302 不是失败，是 NGA 在刷新会话 cookie。** PHPWind 用 302 跳转来更新 `lastvisit`/`lastpath`。第一版脚本没跟跳转、又用写死的 cookie 串，结果**前 27 帖成功、之后每一个都被当失败跳过**（75 条只落 27 条正文），看起来像被风控，其实是自己没 `-L`。
   修法：`curl -L --max-redirs 3` + `-b <登录cookie> -c ~/.nga/jar.txt`（jar 让服务端轮换的会话值能带回去）。改完一次跑 32/32 全成。
2. **`urllib` 要放开证书校验，`curl` 不要。** 本机零信任代理插自签证书，Python 的 certifi 不认、macOS 钥匙串认。所以脚本整体改成走 **curl 子进程**，`NGA_INSECURE` 那个开关作废（代码里已删）。无人值守任务里留一个"跳过 TLS 校验"是不可接受的。

### 判重逻辑错过一次，已修

第一版正文候选按"没见过的新帖"算，可抓失败的帖已经被记进 `seen`，**永远补不回来**——而脚本当时还打印"下次还会当新帖重试"，等于说了假话。现在正文候选按"没有 `threads/<tid>.json` 的"算，失败的下一次自动接着补。

### 无人值守怎么排的（以及一个绕不过去的系统限制）

`launchd` 直接指仓库里的脚本会报 **`Operation not permitted`**：macOS 的 TCC 不让 launchd 起的 bash 读 `~/Documents`。所以整套搬到 `~/.nga/`：

- 执行体 `~/.nga/nga-daily.sh`，脚本副本 `~/.nga/scrape-nga-forever.py`（**仓库那份是源，改了要重新 `cp`**）
- plist `tools/com.wowforever.nga-daily.plist` → 复制到 `~/Library/LaunchAgents/`，每天 **08:40 / 20:40** 各一次
- 数据与日志全在 `~/.nga/`：`data/board-<日期>.json`、`data/hot-<日期>.json`、`data/threads/<tid>.json`、`data/view.html`、`daily.log`
- 已实测跑通：手动 `launchctl kickstart` 触发，**退出码 0，列表 78 条、新抓正文 32 条，累计 108 条 / 92 条正文**
- 停止：`launchctl bootout gui/$(id -u)/com.wowforever.nga-daily`
- 注意：**电脑关机或睡眠时不会补跑**（错过的时点会在唤醒后合并成一次），这是"每天更新"的实际边界

## 附：7881 是什么（同日顺手实测，关系到"金币参考"那条红线）

站主问「7881 金币查询是什么网站，后期可以做金币参考但不做交易」。实测结论：

- **7881.com 是交易平台，不是行情查询站**。首页 `<title>` 自述"专业的网络游戏交易平台（游戏币交易、金币交易、账号交易、装备交易、道具交易、点卡点券交易、游戏租号，游戏代练、手游交易等）"；厂商 **南京锐扬软件科技有限公司**，ICP 证 苏ICP备2020050196号-2，苏公网安备 32010402001054号（抓取 2026-10-18）。首页里"魔兽"命中 45 次、"无限"41 次、"金币"43 次。
- **它确实给《无限》开了金币频道**：`魔兽世界无限 → search.7881.com/G6443-100001-0-0-0.html`、`无限（国服） → G6443-100001-G6443P001-0-0.html`（`100001` 是"买金币"这个 goodsType）。同系列还挂着 时光服 G6211、经典60 G6242、周年纪念 G5569、熊猫人之迷 G5656。
- **报价我这次没拿到，而且拿不到的原因是结构性的**：无限 / 时光服 / 经典60 三个频道页用 curl 取回来都是 65–74 KB 的**筛选器空壳**，正文里都是"抱歉，没有找到相关商品"，`￥` 出现 0 次。**时光服现实中明确有金币交易在跑**（uu898 实测过 1 元=56.5 金），所以这不是"没人挂单"，而是**商品列表由前端异步接口加载，静态抓取拿不到**。要价就得进一层找 XHR 或走浏览器。
- 因此红线定成"**只做游戏内金币数值，不做人民币↔金币行情**"（`AGENTS.md` 第五节网页端放开清单第 3 条）。三条理由：① 价源是金商挂单，展示它等于免费给 RMT 平台导流；② 暴雪 EULA 明令禁止线下买卖游戏币，这条会把站点的"个人非商业"性质进一步往外推；③ 游戏内数值（修理费、坐骑价、材料价、副本产出）我们自己的数据基底就能出，**不依赖别人、也不会每天变**。
