## 二、宠物页这一条链（新页 `#/pets`）

**数据**：`GearInsight_Forever/PetData.lua`（插件自述取自客户端 DB2 `1.60.1.70532`，wago.tools）
→ `tools/extract-gi-pets.py` → `app/data/upstream/gi-pets.json`
→ `tools/merge-pets.py` → `app/data/pets.json`。

- **18 个家族（1 个标无限新增：狐狸）+ 22 条宠物技能（10 条标新增）+ 两边 58 条连线**。
- 图标：PetData 里 `icon=` 是客户端贴图文件号，不是本站的图标键名。
  用 listfile 逐号翻成 `Interface/ICONS/<键>.blp` 的键名，**18/18 翻到**；
  本地缺的 8 张按既有那条路从官方 CDN 补（`tools/fetch-icons.py`，只允许 `render.worldofwarcraft.com`），
  **8 张全 200 命中**，现在 18/18 本地有图。翻不到的一律留 `null`，不猜键名。
- **一条描述都没取**：插件技能表里的 `dcn` / `den` 是成句文案（例 `dcn="对敌人造成81-99点伤害。"`），
  抽取阶段就丢，`build-data.js` 再钉一道（判据是句号/分号/逗号和"造成…点伤害"这类措辞，
  **不用感叹号**——正经技能名里有一条就叫「归我了！」，英文原文也是 `Mine!`，
  第一版拿 `！` 当句子判据把这条拦红了，那是判据写错，不是数据违规）。
- 分级一律 **L1**：一家第三方插件转述客户端，本站没逐行回客户端表、也没进游戏验。不许因为"看起来合理"升 L0。

**界面**：`app/src/pages/PetsPage.vue` + 纯函数 `app/src/lib/pets.js`（单测直接打这一份）。
两张表：家族（图标 / 中英文名 / 伤害·护甲·生命三项修正 / 会的技能）与技能（几级能学 / 最高到 / 等级数 / 冷却 / 耗能 / 哪些族会用）。
三个筛选项**都真生效**：搜索框（中英、大小写不敏感）、只看《无限》新加的、按家族筛。
家族行的技能条、技能行的家族条都是按钮——点了真筛，不是装饰。

**这一页刻意不做的**：它不是"哪只宠在哪个区域能抓"的名录——源里没有逐只的位置与驯服条件，
所以标题、卡头、搜索类型都写"家族 / 技能"，不写"宠物大全"那种会让人以为这里有坐标的话。
缺的那一层归 #40 继续挂着（wclbox 那 576 只那一档还没审过字段可核性）。

**搜索与入口**：新增两类 `pfam` / `psk` 进 `search.json`（全站索引 5348 条 / 23 类），
`KIND_ORDER` 同步补两类（漏了就是"条目在索引里但搜不出来"那个老毛病）；
首页那行"更多入口"补第三格「宠物家族 18 个」——数从 `scale.json` 现读，不手抄。

## 五之二、整站门禁这一格：跑不完，且**不是本轮引入的**

两次整站跑（第二次特意把已知会卡的 `[6a] 法术书与成就页` 排除掉）都死在 Playwright 的 30 秒截图超时上，
**但两次死在不同的节**：第一次 `[6a]`（`site-check.py:440` 那一处截图），第二次 `[21] 全站逐路由底线`
（`site-check.py:3413`）。也就是说这不是"某一页坏了"，是**这台机器现在给一次视口截图就要 24~30 秒**，
谁排在后面谁撞线。实测数据（单独起一个静态服务、只开一个页面）：

| 那一处截图 | 结果 |
| --- | --- |
| 默认参数 | **30.0 秒超时** |
| 关掉动画等帧 | 24.5 秒成功 |
| 只把超时抬到 120 秒 | 24.8 秒成功 |

我按这两条改过两处（`ctx_slow` 抬默认超时 + 那一处 `animations="disabled"`），**改完仍然超时，
于是把两处放宽都撤了**——放宽没解决问题，留着只会让下一个读这份门禁的人以为"超时已经修好了"。
这一格留给修门禁的人，判据就是上面那三行数：**要动的是"这张图非拍不可吗、能不能只拍视口一块"**，
不是再往上调几秒。

本轮自己那一节是干净的：`--only pets` **14/14 两次**，其余各节在崩之前累计 **165 条 PASS、0 条 FAIL**。
