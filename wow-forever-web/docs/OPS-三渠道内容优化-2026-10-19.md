# 头条、小红书与公众号内容优化建议

日期：2026-10-19。主角色：wow-ops。交接给：站主、video2text 内容角色。

**结论：继续用 video2text 生产图文攻略可行，当前优先修正数据复盘、渠道装配和素材证据。公众号继续从同一素材库选题，但成稿还要结合官方/原始来源、wow-forever 数据和真实操作。三个渠道共用可核对的事实材料，分别确定问题、表达形式和发布条件。**

本轮是运营建议与事实核对，未改外仓代码、skills、平台排期，未访问小红书后台或恢复其数据回填。

## 1. 先更正两条旧判断

### 小红书暂停的是回填，不能直接推出停止发笔记

上一轮《两项目分工澄清》依据 CHANGELOG 的简写“整条暂停”，对停止范围留了疑问。本轮读到原始 `2026-10-15-dev-两天复盘与未做清单.md` §六和 `docs/AGENT-HANDOFF.md` §五，明确写的是：**小红书整条回填暂停**，不自动打开/刷新/轮询创作者后台、不催截图、不跑回填脚本，除非用户明确要求此次录入。

因此：保留回填暂停，不能称为“账号已停更”。本轮不恢复任何自动化；用户问内容怎么优化，也不等于授权自动回填。

### 头条复盘算错了日均展现下降

读取外仓 `output/角色交接/2026-10-17-ops-头条阅读量归因与一手资讯源.md`，按其中公开于本机的表格重新计算：

| 指标 | 10-09～10-10（2天） | 10-11～10-15（5天） | 正确解释 |
| --- | --- | --- | --- |
| 日均展现 | 28,723÷2＝14,361.5 | 19,830÷5＝3,966 | 下降约72.38%，不是31% |
| 汇总点击率 | 2,523÷28,723＝8.78% | 985÷19,830＝4.97% | 同时下降；不能只归因平台，也不能只归因标题 |
| 日均阅读 | 1,261.5 | 197 | 下降约84.38% |

12篇样本的决策/争议组 9.06%、告知组 2.47%，实际是“总阅读÷总展现”的**加权点击率**；逐篇点击率均值分别约7.90%和3.06%。原文将其称“平均点击率”不够准确。

更重要的是：这些是**微头条历史小样本**，不是图文文章或小红书的效果证据；选题、日期、曝光规模也未控制，不能得出“清单没人看”“换个标题一定涨几倍”的因果结论。后续回填需按平台、体裁、观察时长分别比较。

## 2. 头条：保留攻略主线，优化读者任务与复盘

现有代码保留攻略/资讯/试错7:2:1，暂不凭这次小样本改成新的固定比例。优先做三件事：

1. **标题和开头说明读者要解决什么。** 从“某某任务一览”改为围绕明确任务组织，例如“第一次去哀嚎，出发前先核对哪些任务”。具体任务、奖励和顺序必须有证据，标题不能许诺正文没证明的收益或确定性。
2. **一篇只回答一个主要问题。** 开头先给结论/适用范围，再给操作或清单，最后解释限制。新闻稿要解释“这条变化影响谁、需要做什么”，不能只改写公告标题；无法证明影响时只准确转述。
3. **按体裁看效果。** 微头条看展现→点击→有效互动；图文文章另看阅读和后台可获得的读完/停留指标。涨粉、收益与工时放周复盘；后台没有的指标记缺失，不估数。

可以先生成两个标题候选，再选一个发布；不把同一稿重复发两遍当A/B测试。用不同但相近主题、相同体裁、同样发布后时长的小批量比较，结果只作方向参考。

头条官方不鼓励同一作品重复上传；声明首发还有额外条件，不能把“换封面/改标题”当成新作品。[内容创作规则](https://baike.toutiao.com/detail/211/212/570?enter_from=left_navigation)

现有“不导流不带货”约定继续执行，不默认把攻略尾部换成服务销售话术。

## 3. 小红书：先确认渠道装配正确，再优化图卡

外仓的历史盘点记录过：目标是小红书的成品包却以 `publish_channel=toutiao` 装配，夹带头条式尾注、领取话术或错误的发布清单。**这是历史发现，本轮没有重跑最新出图链路，不能声称问题现在仍未修。** 下次产出一份小红书样张时必须从实际成品验证：

- manifest/发布清单明确属于小红书；正文、图卡、复制文本都使用同一渠道设置。
- 不夹带不适用的关键词领取、站外交易引导或其他平台操作说明；AI参与按平台当时提供的标识功能如实处理，不以删声明来规避识别。
- 用用户自己的截图、自有排版图或已确认可用的素材；“从别人视频里抽到真帧”只说明不是生成图，不说明有使用授权。
- 发布前保存实际粘贴的正文、上传图片和选择的声明项；发布后保留链接/状态。装配产物不等于实际发出去的内容。

此前违规盘点一面承认没有实际发布稿，一面把某些文案写成“已被证明”的触发器，结论越过证据。不能据此说“只要删掉AI相关字样就不会违规”，也不能把相同模板直接等同于处罚原因。

平台官方社区公约强调真实分享、尊重原创，并要求交易使用平台提供的工具；旧计划里“把导流话术移到评论或简介”不能作为可靠方案。[小红书官方社区公约](https://pgy.xiaohongshu.com/help/detail?id=1eda0a065dd894063c2e029a49e8f6a1&userType=4)（本轮检索获取官方条目，直开页面为动态空正文）。

图卡建议先做一个可复用的短结构，**页数由信息量决定，不设算法偏好的假规则**：

1. 封面：具体问题、适用版本/等级、这一篇能得到什么。
2. 答案页：先给最有用的结论或总清单。
3. 步骤/对照页：一页一个任务，图中文字手机上可读。
4. 收尾页：容易弄错的条件与资料日期；无需强行让读者跳出平台才能获得答案。

小红书暂时没有本轮可核实的完整表现数据，所以“可保存使用的图卡”是内容试验建议，不是已证实更容易获推荐。用户未提供本次数据时不催截图、不恢复回填。

## 4. 公众号怎么选材：继续用库，但先定问题

素材库回答“有哪些线索和材料”；证据包回答“这篇能准确说什么”；文章回答“读者能做成什么”。不能因为某条视频很热，就自动扩写成公众号长文。

建议流程：

```text
选一个玩家问题
→ 在video2text按wechat渠道检索相关素材
→ 检查游戏版本、等级/阵营、发布时间与原始来源
→ 对照官方公告或原始资料、wow-forever基底
→ 必要时实际操作工具，留下截图和步骤
→ 形成选题卡与事实核对表
→ 写文章、排版、质检、人工预览与发布
```

已有 `media-planner` 支持 `GET /api/topics/radar?channel=wechat` 和带 `channel` 的选题包。可以沿用，不为此新建素材库。但 `knowledge_categories` 是偏好加权，不代表所有命中“攻略”的材料都属于 Forever；必须人工/规则核对产品和版本，不能混入别的游戏或正式服机制。

来源用途分开：

| 输入 | 用来做什么 | 不可直接推出什么 |
| --- | --- | --- |
| video2text里的视频转写、公众号/其他素材 | 找问题、找候选解释、定位原始来源 | 热门或入库不等于事实已核；ASR可能听错名字、数值和单位 |
| 官方原文/原始记录 | 验证公告、时间与规则 | 可阅读不等于全文/图片都可转售或搬运 |
| wow-forever 数据基底 | 查实体、属性、来源、分歧及版本 | 数据分级不能被“写进公众号”自动升级；数据来自第三方时仍应保留原始出处 |
| 自己实际操作与截图 | 证明页面如何查、操作是否可复现 | 工具操作成功不等于游戏内掉落/强度已实测 |

默认可以先取2–4条相关素材帮助定位问题，但数量不是门槛；多篇转载同一原文仍然是一条来源。单源可以如实写单源，不凑“多方验证”。第三方论坛在本项目仍只作选题雷达，不借素材入库绕过正文/观点使用边界。

## 5. 公众号成稿建议

主线建议为：**玩家具体问题 + 可直接使用的答案 + 必要的操作证据**。工具教程是其中一种文章，不必把公众号降成只负责点击跳转的入口页。

三类内容可按现有材料择一制作，不要求同时开三条生产线：

- 任务型攻略：解决一个出发前/选装备/查来源的问题，交付一张清单。
- 查询型教程：用一个具体装备或副本示范怎么查，读完能复现。
- 更新型说明：新公告到底改变了哪些已知事实，列出变化与未确认部分。

以“配装表上的装备去哪拿”为首篇方向，以下是**写作提纲，未核事实前不当成发布稿**：

1. 开头：读者拿到名单，却不知道获取条件；直接说明这篇要解决哪一步，不编“群友问我”的经历。
2. 先给一张核对表：装备名、获取途径、需要等级、制作条件、核对日期。没有证据的格子按来源情况如实处理。
3. 展开一个具体例子：分别核对穿戴条件和制作要求，避免把二者混成一回事。
4. 用两三张实际操作图展示查找步骤；不罗列整站规模来替代答案。
5. 解释哪里还不能确认、哪些来自同一源，保留版本适用范围。
6. 给读者能带走的结果；正式入口可用时再自然接“阅读原文继续查其他装备”。不要求先跳转才能获得本文核心答案。

文章长度由问题需要决定；旧技能里针对其他系列的2500字门槛不能未经核对直接套到新系列。若当前机器门有硬要求，先回到权威写作规则确认适用范围，不用填充段落凑字，也不私自跳过检查。

## 6. 同题如何分发

例题：配装表的装备来源怎么核对。

| 渠道 | 主要问题 | 建议产物 |
| --- | --- | --- |
| 头条图文 | 拿到配装名单后，哪些条件容易弄错？ | 结论、一个核对案例、可执行清单；微头条另按短体裁选角度 |
| 小红书 | 查一件装备，要核对哪几项？ | 可保存的核对卡，信息足够独立使用 |
| 公众号 | 怎样从一张名单查到具体获取条件，并判断信息是否可靠？ | 完整案例、操作图、核对结果与适用范围 |

一个事实包可以复用，不代表同一篇成稿能不顾权益条件同时发布。头条官方说明：声明首发的作品在头条发布后72小时内又在其他平台发布，会被认定为非首发；同平台实质相似重发也有额外规则。改标题、重排版不自动免除限制。[头条首发规则](https://baike.toutiao.com/detail/195/263/0?enter_from=left_navigation)

因此“公众号永远首发”和“头条稿全部声明首发”不能同时默认执行。每份成稿在发布清单记录是否使用首发权益、首发平台、时间和可跨发时间；需要同期发的独立作品应有独立价值，不能以改写规避规则。

## 7. 最小实施顺序

1. **复盘修正**：先改外仓头条复盘的日均算法、加权口径与适用体裁；小红书暂停范围明确成回填。此轮已重算，外仓原文件尚未修改。
2. **一份样稿验证**：选择一个有足够资料的玩家问题，在 video2text 做公众号选题卡；引用 wow 数据和原始出处，先不批量生产。
3. **渠道装配验证**：用同主题事实包准备一份小红书草稿，检查真实 manifest、复制文案、图卡和发布清单。只制作本地产物，不操作平台后台。
4. **发布后再判断效果**：保留相同观察时长，记录平台/体裁/日期/标题/事实包版本/已发链接/指标和工时。头条与公众号按现行流程；小红书回填继续遵守用户暂停要求。

现有 `media-planner`、`media-publish` 的渠道表只列头条与公众号，却有小红书成品需求，后续应补明确的小红书路由和清单，避免把头条包直接当小红书包用。先验一个样张，不为本次建议重建生产系统。

首月1,000元目标继续记录，但内容阅读、关注、询价、付款和净收入分别看。不能把三个平台都更新当作已完成变现；也不能凭样本不足就停掉原有攻略方向。
