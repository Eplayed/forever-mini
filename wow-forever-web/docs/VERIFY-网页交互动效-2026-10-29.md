## 二、机器验到的（不是"构建通过"那种）

`--only app,legacy_app,motion` → **154 / 154 全过**；整站 `site-check.py` → **669 / 669 全过**；
`npx vitest run` → **167 / 167 全过**（其中 1 条按本轮实现改了机制，见第三节最后一行）。

新增那 26 条里，关键的四条不是"类名在不在"，而是"这一下真的动了、而且没把内容弄丢"：

- **换页**：`page-leave-active` 与 `page-enter-active` 都出现过，且 `#main` 下始终只有一个 `.view`
  （`mode="out-in"` 的判据）；过渡结束后类名清干净、`opacity=1`。
- **展开收起**：抽屉建立的是 `grid-template-rows` 这条过渡、时长非零，展开后是内容的自然高度（实测 466px）。
- **减弱动态效果（反向钉）**：同一批过渡类算出来 `1e-06s`（Chrome 在 reduce 下不返回字面 0s，
  判据按"≤1ms 算不动"写）；换页轮询 1.2 秒**一条过渡都没建立**；全程 12 帧 `opacity` 全是 1；
  抽屉首帧就是 466px。**关掉动效不等于闪空白，也不等于还在滑。**
- **切完画面真的换了**：世界页切「稀有」后区域卡从 44 张变 0 张、当前标签是 rares——
  防止"挂了个类名但内容没动"这种白放。

红线扫描（motion.css 源码，注释除外）：`infinite` 0 处；位移最大 16px（≤20px）；无 >240ms 的写死时长。

## 三、加动效把三条旧断言打红了——都是取数时机，不是产品坏了

这条要单独记，因为它是"动效类改动"的通用坑：**断言点完立刻量，而量的是过渡期间的画面**。

| 红的那条 | 现象 | 根因与改法 |
| --- | --- | --- |
| 新站区域卡数量与数据一致 | 0 张（数据 44） | 面板切换是 `out-in`，旧面板先摘掉、新面板还没挂。改：每切一次调 `settle_motion()` 等过渡结束再数 |
| 点位平时是虚的，指上去才实体 | 默认 .60 → 悬停 .60 | 悬停是 140ms 的 opacity 过渡，量早了读到起始值。改：等 `.zdot.on` 的 opacity 到 1（最长 6 秒） |
| 点锚点真的滚到那一段 | scrollY 0 → 0 | 上面那步刚取消勾选、挑战组正在 220ms 收起，平滑滚动的目标还在动。改：滚之前先 `settle_motion()`，并把固定 1200ms 换成等 scrollY 落位 |
| （vitest）结果区没输入前是隐藏的 | `hidden` 属性读不到 | 结果层从 `hidden` 改成 `v-show` 才挂得上过渡。要求没变、机制变了，断言跟着改成 `style: display:none` + `aria-expanded=false` |
| 溯源页点名了这张插件图 | 读到 0 条（那一段其实还在页面上） | **这一条最阴**：`test_race_icon` 在同一个 page 对象上换 hash 走多页，换 hash 不重载文档、走的是换页过渡；等不到结束就 `body.innerText`，**读到的是上一页**。8821 上单测这段文字在不在是有的，只有门禁那条路径会红。改法：`probe()` 里导航后先 `settle_motion()`，并把同样的等待补到另外 10 处"换 hash 紧接着读内容"的地方（世界页 `?t=`、副本页 `?d=`、传承页 `?t=&plan=`） |

**这类红的通用形状**：判据本身没错，错在"点完/换完立刻量"。凡是量**过渡期间的属性**（opacity、transform、行高）
或量**换页后的正文**，都得先等过渡结束——所以下一轮再加动效时，`settle_motion(page)` 是默认要加的一行。

## 四、环境事实：门禁那台 headless 的动画时钟是饿着的

`--use-angle=swiftshader` 下 `getAnimations()` 里 `playState` 是 running 但 `currentTime` 恒 0，
一条 220ms 的过渡实测要走 1.5–1.9 秒才结束；同一份产物在普通 `--headless=new` 下实测正常插值
（抽屉高度 8px → 361px → 456px → 466px，换页 opacity 1 → 0.63 → 0.44 → 0.26 → 0 → 0.49 → 0.75 → 1）。
所以"逐帧在长"这类判据在门禁里量不到，机器只钉"建立的是哪一条过渡 + 时长非零 + 终态对不对"，
**中间帧由站主在 8821 人眼验收**（这也是为什么中间帧截图用的是 `--headless=new` 那台）。

## 五、渲染证据（中间帧是真量出来的，不是推的）

`docs/screenshots/check-2026-10-29/` 下 `motion-1…13-*.png`，同一动作的"前 / 中 / 终"三帧：

| 哪一处 | 中间帧实测 | 终态 |
| --- | --- | --- |
| 换页（首页 → 世界） | `.view` opacity **0.63**（淡出中） | opacity 1、类名清干净 |
| 世界页换面板 | `.wswap` opacity **0**（旧面板已摘、新面板还没挂＝out-in 的那一瞬） | 区域卡 44 → 0，当前标签 rares |
| 副本抽屉 | 高度 **433px** | **466px** |
| 传承页折叠 | 高度 **35px**（正在收） | 收起后不占位 |
| 物品详情抽屉 | `transform: matrix(1,0,0,1,1.92,0)`（还在滑）＋遮罩退场时元素仍在 DOM | 滑出后两者都不在 |
| 搜索浮层 | opacity **0.987**（淡入中） | 12 条结果照常列全 |
| reduce 下的抽屉 | 首帧就是 **466px**（没有中间态） | 内容一条不少 |

**一条要说清的人眼判据**：换页与换面板用的是 `mode="out-in"`，所以中间会有**一瞬内容区是空的**
（旧页淡完、新页还没挂）。这是"不两份同时挂"的代价，静态截图看着像白屏，动态只有 90ms 一瞬。
在 8821 上如果觉得这一下读成"闪白"，退路是把离场改成 0ms（旧页直接消失、新页淡进来），
改一行 `--dur-press` 就行，不用回退整轮。
