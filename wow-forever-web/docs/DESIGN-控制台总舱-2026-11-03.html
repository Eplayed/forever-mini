整合说明 · 为什么并、怎么并、wow-dev 的接线清单
  • 结论：三份合成一个 8830 控制台。现有工作台（01/02/03/04/05）+ 00 水源台 + 双管道同步屏，同端口同后端同令牌，不是新站，是给现有 index.html 加两屏一图。
  • 整合理由：① 同一个 jobs.py 白名单后端；② 取水→入井→分发→对账是因果链，拆两处要人肉接力；③ 超期 / 对账 / 门禁三样状态全屏共享（01 对账被 00⑥ 和 02 共用就是实例）。
  • 流域总图：常驻页头 SVG，每段可点跳屏；状态点（红/金/绿）直接读全局对账与超期接口，红在哪一眼看到。
  • 接线（后端改动极小）：jobs.py 白名单加 daily.sh 一条；job running 时流出 logTail 增量；reconcile/latest.json 旁加 append-only 发布账；闸门步沿用白名单单命令。前端全部是现有令牌拼装。
  • 红线不因整合变松：面板是眼睛不是手——执行全走白名单；发布/上传换指针仍需站主点头，闸门弹层只是慎重交互。
  • 落位：两份分屏设计稿（00 / 02）作为总舱两屏的详稿保留，实现时并入一个 index.html。
