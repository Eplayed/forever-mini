# 无限服人口普查方案

2026-11-10，北京时间。主角色 wow-pm。站主已同意核源后接数据并开发小程序。首版接入获许可的 Everloot 社区样本，地区与规则集未分组，职业表只展示全样本分布。国服采样保留为独立工作。 [接入与样本范围](DATA-无限服人口普查源-2026-11-10.md)

## 首版服务谁

给准备选阵营、选职业或和朋友一起开荒的玩家看。在同一地区和规则集里，玩家能看到最近一周观察到的角色中，联盟、部落各占多少，以及九职业在全部样本、联盟样本或部落样本中的人数和占比。页面可以叫「人口普查」，图表统一写「角色样本」。

## 推荐首版

**国服先试采一个规则集，海外数据另放参考页签。** 国服样本达到发布门槛后，网页先上线只读聚合。小程序复用同一个汇总数据基底，入口放在职业页附近，经 wow-ops 复核「工具-信息查询」口径后再开。

1. 页头给地区、规则集、采样时间窗与样本数。首版用「最近 7 天观察到的角色」，海外来源如果只提供累计快照就按源标注「累计同步」和日期。
2. 两张核心图表。第一张显示联盟／部落人数和占比。第二张固定职业顺序，显示九职业人数和占比，可切换全部／联盟／部落。固定排序方便扫一眼，也避免把角色构成读成强弱榜。
3. 图表旁保留一句「样本为采样期间观察到的角色」。数据出处、最近一次采样时间和覆盖情况在同一处展开。国服样本未达标时显示「国服样本采集中」，海外参考单独展示。
4. 首版只公开聚合。页面无角色搜索、公会排名、角色轨迹、登录和玩家上传入口。管理侧本地汇总后的快照沿用资料站的发布链。

## 国服试采与计算

- 先确认当前国服客户端允许的游戏内查询方式。在选定规则集用同一时段、同一等级范围、同一拆分策略分别采联盟与部落。依游戏支持的人为操作发起查询，记录超时、截断和未覆盖区间。查询上限以国服探针结果为准。
- 同一来源同一窗口内在本地去重。优先使用可合法取得的稳定角色键；只能按名字时，将地区、规则集、阵营和客户端返回的完整角色标识一起作为本地去重键，并注明改名限制。公开数据只包含汇总，角色名、去重键和原始日志均留在本地工作区之外。
- 阵营比例分母是当前切片里可比的联盟与部落角色数之和。职业占比分母是当前阵营筛选下、职业可识别的角色数。职业缺失另报数量。两边覆盖明显不齐、查询仍截断，或其中一边缺采样时，阵营比例显示「样本不足」。
- 建议试行门槛为最近 7 天至少 3 次双阵营配对采样，分布在至少 2 天、两个时段，且各阵营至少 200 个去重角色。此门槛只用来筛掉覆盖明显不足的批次。双阵营配对、分区完整和来源说明仍须逐项核对。
- 海外接入只用允许再发布的公开聚合数据或经确认的合作来源。每个来源独立保留正式服／测试服、地区、规则集、等级范围、时间窗、样本量和统计方式。不同源可并列，角色样本不跨站相加。

## 验收与交接

| 卡口 | 通过条件 |
| --- | --- |
| 来源可复核 | 每组统计能回查来源链接或本地探针记录、统计口径、起止时间及抓取日。缺失地区显示未覆盖，空样本无百分比。 |
| 数字可对拍 | 对同源同窗口，去重重复输入后总数不增；两阵营分母可对回样本数；九职业人数和等于已识别职业人数；四舍五入误差有容忍范围。 |
| 异常状态 | 单阵营、结果截断、过期、版本混入有明确状态；海外样本和 Beta 样本不会进入国服正式服统计。 |
| 公开载荷 | 只发人数、统计维度及来源元数据；页面能看出两种图表的分母。缺源时仍能明确解释当前可看的范围。 |
