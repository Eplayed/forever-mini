# 网页交互动效规格 · 2026-10-29

本轮角色：wow-ui ｜站主指令："web 网页中需要添加交互效果，页面跳转或者是展开收起、卡片切换等动作加入动效。帮我对网页版所有的页面设计一下，然后进行实现。最后在 8821 端口我来验收"

## 一、走哪条路（先说为什么不装库）

站是 Vue 3 + Vite，动效库那条路（React Bits）只服务 React，用不上。剩下的选择里：

| 方案 | 判 |
| --- | --- |
| 装 `@vueuse/motion` / anime.js / GSAP | **不装**。本站红线是不引组件库、加依赖要站主拍板；`three` 已经是唯一的重依赖。这三类动效 Vue 原生 `<Transition>` 全覆盖 |
| CSS `@keyframes` 常驻循环 | **不做**。查数据的站，循环动效会一直抢眼睛 |
| Vue 原生 `<Transition>` / `<TransitionGroup>` + 直接写 CSS | **用这个**。零新依赖、状态驱动、只在"变了的那一刻"动一次 |

新增动效全部集中在第四层样式文件 `app/src/styles/motion.css`（`main.js` 单独引入）。
要整体撤回这套动效：删 `motion.css` 与 `main.js` 里那一行 import，`<Transition>` 外壳留着也不动画面。

## 二、口径（三条，全站统一）

1. **只动 `opacity` / `transform` / `grid-template-rows`**，不动颜色以外的布局属性，不做阴影动画。
2. **单次播放**：全部由状态变化触发，页面静止时没有任何东西在自己动。
   数值上限按信息密集站的红线收：位移 ≤20px、缩放 ≤1.05、时长 ≤240ms。
3. **`prefers-reduced-motion: reduce` 全部归零，内容照旧可见**——沿用 2026-10-10 定下的
   "动画关掉不等于把内容藏起来"，`motion.css` 末尾一整套覆盖新增的每一类。

时长令牌在 `tokens.css` 补两个（原来只有 140/220/240ms，缺"离场"和"面板入场"这两档）：

```
--dur-press:90ms    /* 按下回弹、元素离场 */
--dur-panel:170ms   /* 页面与面板替换的入场 */
```

缓动沿用既有的 `--ease-out:cubic-bezier(.16,1,.3,1)`，不新开曲线。

## 三、逐个动作

### A. 页面跳转（22 条路由，一处改全站生效）

`App.vue` 的 `<router-view>` 外套 `<Transition name="page" mode="out-in">`。

- 旧页：**90ms 只淡出**，不做位移——离场拖东西没人看，且长页面 transform 会整层重绘。
- 新页：**170ms 淡入 + 上移 6px 归位**，6px 与既有 `.card` 入场 `rise` 的幅度一致，不另立标准。
- `mode="out-in"` 是硬要求：新旧页不许同时在 DOM 里。天赋页、配装页挂着 3D 预览与几百行表，
  重叠一帧等于同时挂两份，`site-check` 的逐页断言也会在同一页里数到两套元素。

代价说清：路由的 `scrollBehavior` 在导航那一刻就把页面滚回顶部，而旧页还在淡——所以
**换页时会先跳顶再淡入**。把离场压到 90ms 就是为了这一段短到人眼读成"切页"而不是"抖两下"。

### B. 展开收起

四类，机制统一成 `unfold`：外层 `display:grid` + `grid-template-rows: 1fr ↔ 0fr` + `overflow:hidden`，
内层必须是**单个包裹元素**（浏览器只在单行 grid 上能插值 `fr`）。子元素直接摊开的地方，本轮加一层 `.wf-in`。

| 位置 | 现在 | 改成 |
| --- | --- | --- |
| 副本列表「速览首领与掉落」`.drawer`（两处） | 点开瞬间撑开，无过渡 | `unfold` 220ms + 内容 140ms 淡入 |
| 传承页六组挑战 `.lchbody`（折叠） | 挂的是 `animation`，但元素是 `v-show`——**只有页面加载那一次会播，折叠展开时其实一动不动** | 同一套 `unfold`；这是本轮查出来的真 bug，不是"没做" |
| 天赋页「与经典旧世对比」`.cmpbox` | 同上，硬开硬关 | `unfold` |
| 顶部搜索 `#gres` 结果 | `hidden` 属性硬开硬关 | 它是 `position:absolute` + `max-height:340px` 内滚层，不能套 grid：改**淡入 + 上移 4px**（`pop`，140ms） |

`.lchcaret` 的箭头已经有 `transform` 过渡，但折叠态的 45°/-45° 是写死在 transform 上的，
本轮只补一句：**箭头旋转与面板展开同一时长**，避免"箭头已经到位、内容还在长"。

### C. 卡片 / 面板切换

只给**本来就在整块重挂**的面板加切换动效；长表页不加——一张 965 行的表为了 170ms 的淡入
先卸载再重挂，代价全落在玩家身上，这类地方改成给控件反馈。

| 位置 | 做法 |
| --- | --- |
| 世界页四个面板（区域 / 稀有 / 书 / 营地） | `swap`：出场 170ms 淡入 + 上移 4px，离场 90ms 淡出，`mode="out-in"` |
| 传承页三棵树 | 给格子那排补 `:key="tree"` 重挂，复用已有的 `lgeFade` 入场（200ms / 4px）——换树走的是就地更新，不重挂就一条都不播 |
| 职业页三系卡 | **不用 out-in**：这一排在页面中间，摘掉再挂回会把下面那张吸附表头的技能表挤得跳两次，比原来更难看。改成"按职业 id 重挂 + 一次性入场 `mIn`"（170ms / 4px），槽位始终占着 |
| 配装页职业 / 套装 / 阵营切换 | **不加**：`ModelViewer` 已按 `modelFile:setId:fac` 带 key，重挂就是重建 WebGL 上下文 |
| 动态页类别芯片、物品库筛选、翻页 | 不加内容动画；芯片与按钮给按下去的反馈（见 D），翻页那一下用平滑滚动把"表头回来了"接住 |
| 世界页图例芯片（S3） | 芯片本身给按下的反馈；点位不重挂（`v-for` 直接筛，加 `<TransitionGroup>` 会让离场元素还挂在 DOM 里，门禁"点数等于芯片数"那条会数多） |

### D. 按下去的手感

`.pick` `.kchip` `.lge-tab` `.pztab` `.zlg` `.ghost` `.cta` 加 `:active { transform:translateY(1px) }`，
`--dur-press` 90ms。规则上一条：`:active` 必须写在 `:hover` 之后——同样权重下后写的才赢，
这个坑在 S3 分级点位上刚踩过一次（`.zdot.t2{opacity}` 把 `:hover` 盖掉了）。

### E. 锚点跳转

动态页顶部"跳 ↓"三枚、职业页换职业：`scrollIntoView({ block:'start' })` 补 `behavior:'smooth'`，
在 `lib/motion.js` 里判 `prefers-reduced-motion`（reduce 就当场到位）。
**不开全局 `html{scroll-behavior:smooth}`**——那会把换页时"滚回顶部"也变成一段长滚动，
一页一万像素的话就是两三秒的滑行，那是事故不是动效。

## 四、明确不做

- 导航"当前项"小药丸在入口之间滑动（FLIP 共享指示器）：那条断言本身还在偶发红（开放项 #112），
  先不动它的几何。
- 点位（`.zdot`）出入场、表格逐行错峰：行数上千，重挂成本大于观感收益。
- 手机端适配：站主 2026-10-28 定"手机网页版不做"，本轮不加任何只为窄屏存在的动效
  （`app.css` 里既有的 375 断言一条不撤）。
- 视差、背景流光、加载骨架：常驻或循环，撞第二节第 2 条。

## 五、验收（8821）

人眼看这几处，每处都是"点一下才动一次"：

1. 首页 → 世界 → 天赋：整页淡掉再淡入上移，中间没有两块内容叠着。
2. 世界页点四个面板标签：面板整块轻抬进来，卡片头与筛选框不动。
3. 副本列表点「速览首领与掉落」：往下长开、箭头转，再点「收起」倒放。
4. 传承页六组挑战折叠/展开（这一处以前是**完全不动**的）。
5. 顶部搜索打字出结果：结果层淡入，滚动条位置不跳。
6. 物品库点一行：右侧抽屉滑进来；点遮罩关出去（原来只有进场有动效，退场是消失）。
7. 动态页「跳 ↓」：滑到那一块，不是硬切。
8. 职业页换职业：三系卡那一排淡入抬 4px（这一处不做 out-in，见下面"改过的三条"第 3 条）。
9. 系统开了"减弱动态效果"再走一遍 1–8：每处**当场到位、内容一条不少**。

## 六、落地后改过的三条（实测，不是预判）

1. **`unfold` 的内层必须给 `min-height:0`。** 第一版没给，`0fr` 那一行被内容顶住，
   展开时高度直接跳到 466px、收起时又整块消失——机器断言"中间帧采不到"就是这个。
2. **`prefers-reduced-motion` 那一版原来只把入场中间值改回终态，漏了退场。** 补上 `.page-leave-to`、
   `.swap-leave-to` 等六个值，口径改成可机器判的一句：**减弱动态效果下没有任何一帧内容是不可见的**。
   实测采样：正常模式换页采到 opacity 1→0.63→0.44→0.26→0→0.49→0.75→1；reduce 下 12 帧全是 1。
   Chrome 在 reduce 下把过渡时长报成 `1e-06s`（不是字面 0s），断言按"≤1ms 算不动"写。
3. **职业页三系卡不用 `mode="out-in"`。** 这一排在页面中间，out-in 会先把它摘掉再挂回来，
   下面那张吸附表头的技能表跟着跳两次，比原来更难看；改成"按职业 id 重挂 + 一次性入场"（`mIn`），
   槽位始终被占住。世界页那四个面板是整块主体，才用 out-in。

另外记一条环境事实，免得下轮把工具问题当成产品的错：**门禁那台 headless Chrome
（`--use-angle=swiftshader`）的动画时钟是饿着的**——`getAnimations()` 里 `playState` 是 running
但 `currentTime` 恒 0，同一份产物在普通 `--headless=new` 下实测会走 8px → 361px → 456px → 466px。
所以"逐帧在长"这类判据在这台环境里量不到，机器只钉"建立的是哪一条过渡 + 时长非零 + 终态对不对"，
中间帧由 8821 人眼验收。同理：换页结束后必须等过渡真的跑完再量（这台环境实测 1.5–1.9s），
固定 900ms 会量到 `opacity=0` 那一帧而误判成"停在半透明"。
