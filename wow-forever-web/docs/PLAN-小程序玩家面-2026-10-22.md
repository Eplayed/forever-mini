## 一、高价值功能（玩家要办的事，不是我们有什么数据）

| # | 玩家要办的事 | 对应页面 | 为什么值 |
| --- | --- | --- | --- |
| 1 | 进本前把这座本摸清楚：几级能进、哪个阵营、在哪、几人本、几个首领各几级、每个首领掉什么 | 副本列表 → 副本详情 | 进本前 30 秒要的答案，全站数据最厚的一块 |
| 2 | 掉了一件不认识的东西，想知道哪座本哪个首领出的 | 掉落反查 | 反向查是玩家最高频的"这东西哪来的"，网页端没有同等入口 |

## 二、玩家界面不出现的东西（本轮已按此清理）

判据一句话：**这条信息是描述"我们的数据"，还是描述"玩家要的那个东西"？前者一律不上界面。**

去除清单（六页全扫）：

1. 任何聚合计数：入口卡的"38 座 / 215 条 / 498 条 / 1050 条"、筛选 chip 上的条数、
   "41 条 · 3 系"、"首领 4 个 / 掉落 8 条"、"3 条来源"、"4 座本 / 4 处掉落"、"只看收藏 0" 的 0。
2. 覆盖率与可信度：首页"这站现在什么样"整块（L0/L1/L2/L3 数字、基准日期）、
   副本列表第二排"全部可信度 38 / L0 35 / L2 1 / L3 2"、内容页上的 L0–L3 徽标。
   （分级是维护用的档，网页端 2026-10-20 就已决定只留在溯源页。）
3. 缺口自述："还没确认的"整块、"路线未实测，本站不画路线"、"公开数据库里还没有它的掉落记录"
   这类"我们缺什么"的句子。缺的值本身仍显示「待实测 / 未记录」——那是值，不是自述，红线要求不编造。
4. 批次与核对日期："批次 a6162e5f5e45"、"最近核对 2026-10-11"、"核对至 2026-10-22"。
5. 方法论长段：掉落口径那一大段（谁取的、怎么推的）、"数据从哪来"弹窗。
6. 来源**条数**（"3 条来源"）去掉；来源**本身**保留并收进一个"来源"折叠里——
   根红线要求 L0 解包转述与 BiS 名单必须能让玩家点开看到是哪个站转述的、哪天抓的，这条不让步。

保留（玩家要用的）：每座本的等级区间/阵营/位置/人数、首领名单与等级、掉落归属、
技能级数与起学等级、逐级学习等级、译名与英文名、冲突时的"另一说法"、
收藏与最近看过、断网时"这部分要联网"的提示、页脚免责声明、素材转存一句话说明。

## 三、清理后的页面骨架

- 首页：标题一句 + 四张入口卡（只有名字和一句话）+「继续」横滑 + 页脚。
- 副本列表：搜索 + 只看收藏 + 一排类型 chip（无计数）+ 行（缩略图 / 名字 / 英文名 / 标签 / 收藏）。
- 副本详情：原画 + 名字 + 标签 + 关键信息四行 + 首领名单 + 掉落 + 折叠的「来源」+ 页脚。
- 技能速查：九宫格（图标 + 名字 + 英文名）→ 职业内搜索 + 按系分组 + 行（图标 / 名字 / 级数 / 起学 / 状态）→ 展开看逐级与来源。
- 掉落反查：搜索 + 结果行（图标 / 名字 / 品质 / 编号）→ 展开看哪几座本哪个首领 + 复制。
- 中英速查：搜索 + 类型 chip（无计数）+ 词条行 → 展开看英文名与来源。

## 四、单列未决：真机没图

站主扫预览码后回报手机上没图，模拟器六个页面全出图。两者唯一的差别在取图链路：
模拟器是 Chromium 的 `<image>`，真机是微信自己的图片管线；OSS 默认域名对每个对象强制
`Content-Disposition: attachment`（实测 1,117 张全这样，写 inline 也改不动）。
候选修法两条，都要站主拍板：① 小程序改用 `wx.downloadFile` 落盘再给 `<image>`（需要他在后台把
OSS 域名加进 downloadFile 合法域名，一分钟的事）；② 图片改走我们自己的 GitHub Pages
（网页端同一份素材已经在那儿，无强制下载头，但国内连通性不稳）。
本轮不动这条链路，等拍板。
