# 数据源地图（2026-10-22 一次性梳理 · wow-data）

这份是**当前状态的一页总览**，回答"我们页面上每条数据到底从哪来"。
明细与逐轮记录在 `wow-infinite-sources.md`（那是追加式的流水账，本文件是整理后的横切面）。
下表全部从各成品文件自己的 `meta` 字段读出来，不是凭记忆写的。

## 零、一句话

**五层来源，一条流水线**：官方中文页最硬但最窄 → 参考站转述的客户端数据是主力 → 插件整理补字段 →
客户端直取管编号与素材 → 本站自己写的东西单独隔开。越往下越要标清楚是谁说的。

## 一、官方中文页（`wow.blizzard.cn`）——最硬，但只有 6 篇

| 喂给哪些成品 | 拿的是什么 |
| --- | --- |
| `abilities.json`（86 条专精技能）、`races.json`、`glossary.json`（215 条）、`systems.json`、`timeline.json` | 职业/种族官方中文定名、种族特长整句、系统名、上线日期 |

取法：`tools/extract-abilities.py`、`extract-races.py` 按官方页自身结构取，
**名称必须原样出现在句里，否则丢弃**。这是唯一"能逐字回查、且回查对象就是官方本身"的一层。
**边界**：圣骑士、萨满、法师、术士、潜行者里有几系没有官方中文深度解析文章，
那部分**至今不机翻、不搬第三方**，`glossary` 的 note 里明写着。

## 二、参考站转述的客户端数据（`wowforever.wclbox.com`，我们内部叫 wclbox）——主力

物品、法术、成就、副本、世界地图、专业、传承、改动、天赋树，**九个成品文件的主源都是它**：

`items.json`（21,077 件全量名录）、`items-detail.json`、`spells.json`（498）、`achievements.json`（211）、
`dungeons.json`、`world.json`（地图/稀有/书籍/水袋四类点位）、`professions.json`（13 专业）、
`legacy.json`、`changes.json`（967 条改动）、`bis.json`（38 套）、`talents/*.json`（九职业天赋树）。

它本质是**别人解包客户端后做出来的中文站**，所以有 ID、有中文名、有结构。
站主 2026-10-08 决策：这类名字算 **`datamine_cn`，直接进 L0**，代价是两条硬要求——
① 每条带 `url` ＋ 抓取日期，界面上"来源"能点开看到是哪个站转述的；
② `tools/audit-translations.py` 要逐字回该页核对，保证我们没抄错。

**这一层的风险是单源**：`items.json` 的 meta 自己就写着"名称索引全量名录，**单源 L0**"。
21,077 件物品的名字目前只有一个转述方。

## 三、插件整理（GearInsight / XR_DungeonGuide / DungeonsForever）——补字段，不能逐字回查

| 成品 | 插件补的是哪一层 |
| --- | --- |
| `items-detail.json` | 属性与卖价（站主 10-20 定：**以最新插件事实字段为准**，插件之间 GI 属性优先 XR、卖价 XR） |
| `spells.json` / `achievements.json` | `spellId`、是否自动或天赋自带、成就目录 |
| `dungeon-geo.json` | **副本入口坐标、首领在副本内图上的位置、27 张副本内部底图**（DF 3 张自绘 + XR 25 张截图） |
| `world.json` | 稀有怪的地图号（主源已换成 GI 行内 `ui`） |

**三条边界要记住**：
① 只取字段，**说明文字一律不取**（DF 的 LICENSE 写"保留所有权利"，站主 10-19 只批了坐标那一层）；
② 插件是 `.lua` 文件，**没有能点开的网址、`audit-translations.py` 回查不了**，所以这一层整体按 L1 留档；
③ **同一份数据被两家插件抄过不叫两个来源**——实测过两次：XR 与 DF 的坐标表逐字相同、
XR `rares2` 与 GI `rares` 的中文名 **714/714 零差**。

## 四、客户端直取（wago.tools 的 CSV、CASC 归档导出、DB2）——唯一能自己复算的一层

| 成品 | 来源 | 现状 |
| --- | --- | --- |
| `queue.json`（51 条） | `wago.tools/db2/GroupFinderActivity/csv?build=1.60.1.70532` | 客户端排队表，**编号是硬事实**；副本页/团本页拿它做"两源并列" |
| `icons.json` + 1,000 多张 `.jpg` | 暴雪官方 CDN（`fetch-icons.py` 只允许官方域名）＋ 客户端 CASC 导出 | 缺口从 161 收到 **1** |
| `art.json` | 客户端 CASC（载入图、原画）＋ 第三方站转存 | 整目录删除即回退到自绘占位 |

**这一层撞到的墙**：这台客户端（`wowf` 1.60.1.70532）**实际装进去的 DB2 文本是韩文**
——`ItemSparse.csv` 17,844 行含韩文、**含汉字 0 行**（我方复算）。
所以从客户端直取**能拿编号、拿不到中文名**。总闸是开放项 46（让启动器把 zhCN 文本包装进来）。

## 五、本站自己写的（必须和前四层隔开）

`chooser.json`（玩法归类，meta 明写"不是官方推荐，也不构成强度排行"）、
`releases.json`（68 条"本站更新"，一条对应仓库里一个真实提交，构建会卡 commit 是否存在）、
`method.json`（我们怎么拿数据、哪些刻意没拿）、
`scale.json` / `search.json` / `talent-preview.json`（**派生物**，由 `build-data.js` 从已校验数据算出来，不许手抄）。

## 六、现在卡在哪（按"解开来能多什么"排）

1. **开放项 47**：`ai_data` 那份插件包（14,879 个中文物品名，与 wclbox **逐字同名 99.9%**）
   按哪一档用。定了这条，第二层的"单源"就变成"两源互证"。
2. **开放项 46**：装 zhCN 文本包。这是唯一能拿到**官方原文直取**的路，
   同时解开底图地名（38）、区域名对齐（43②）、物品存在性（45）三条。
3. **开放项 48**：34 件物品界面挂问号占位、其实客户端有真图标，缺 16 个图标文件。
   （2026-10-23 更正：准确的数是旧成品挂占位 **40 件**、这次名录一更新其中 **36 件**拿到真图标名，
   缺的图标文件是 18 个键里补回 30 张，见 `DATA-ITEMS-REFRESH-2026-10-22.md` 第七节。）
4. **配装线"第二家"这条我收回一半**（2026-10-23 重算）：XR 那份 BiS 与我们 wclbox 那份
   是**内容不同的两份名单**（621 vs 609 件、交集 371；战士 PvE 12 个部位 4 个首选不同），
   但**专精清单 38 对 38 一一对上、连冷门组合都同进同出**，所以"没有共同上游"证明不了 →
   **不据此升档，配装线仍是 L1**；能做的是**两源并列、分歧不裁决**（开放项 49）。
