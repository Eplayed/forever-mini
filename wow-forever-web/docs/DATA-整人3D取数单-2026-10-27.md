# 整套装备人物 3D：Windows 客户端取数与最小验证单（2026-10-27）

本轮角色：wow-data。状态：**已定（验证路径与所需输入）／待 Windows 实测（Forever 客户端能否被现成角色导出器正确读取）／阻塞（本机 SMB 只读挂载认证失败，未读取客户端新文件）**。本轮不发布任何游戏模型。

## 先改路线

目标是**固定推荐套装预制整人 GLB**，对照 [新手盒子配装页的实物观察](DATA-WCLBOX-3D-2026-10-27.md)；先不做浏览器里任意换装。本站 `bis.json` 已有 38 套、两阵营逐槽 item ID。只需证明「同一个人物穿两件不同胸甲，整人 GLB 里的胸部确实变」；成功后才考虑 38 × 2 批量生产。

此前把「自己补齐 5 张 DB2 表、逐列推断身体贴图」当成唯一入口过于保守。[wow.export 官方 CHANGELOG](https://github.com/Kruithne/wow.export/blob/main/CHANGELOG.md) 记载：0.2.4 支持角色 GLB；0.2.7 支持给人物预览/导出装备和整套装备；0.2.8 能按装备槽替换物品；0.2.9 修过装备渲染顺序与弓持握。**应先用 0.2.9 或更新版，在真实 Forever 客户端做探针**。官方声明支持 Retail/Classic 客户端，但没有给此私有 `_forever_` 分支的兼容保证；成功与否必须实测，不能把软件功能表当作本 build 的结果。

## Windows 侧只做一套、两次导出

**输入客户端**：`C:\GAME\World of Warcraft\_forever_\`，当前取数目标 build 1.60.1.70532（以 Windows 端实际显示为准；如已更新，记录真实 build）。只读加载，不往游戏目录写输出。

**输出目录**：`C:\GAME\World of Warcraft\ziliao-export\character-probe-2026-10-27\`，与 `_forever_` 同级。不要导出整包模型、全量 BLP 或 43,329 张身体贴图。

1. 在 Windows 安装或打开 [wow.export](https://github.com/Kruithne/wow.export)，记录版本号，选择本地客户端目录；若工具要求选安装根目录，则按 UI 提示改选其父目录。记录它识别到的产品与 build。若客户端加载失败，保存原始错误日志，**停在这一步**。
2. 在 **Characters** 中固定同一「人类男性战士」外观（种族、性别、皮肤、发型完全一致）。用本站 `app/data/bis.json` 中 `warrior` PvE 联盟套的可见装备先装：头 7915、肩 2278、胸 1488、腕 4438、手 3341、腰 250556、腿 250523、脚 4464、主手 280604、远程 9456、背 14593。工具若按 ID 找不到任一件，逐件记录「找不到／找到但无外观／找到且可见」，不要换一件近似名称蒙混。
3. 保持相机、人物与其余装备不变，导出 **A：胸 1488** 的正面/背面截图与整人 `.glb`。只把胸改为同一套备选列表中的 **2870**，导出 **B：胸 2870** 的正面/背面截图与整人 `.glb`。若 2870 在此 build 不可用，用备选 250518，并明确记录替代 ID。关键是两件胸甲都有实际外观、**只有胸槽变化**。
4. 在 wow.export 预览里和独立 GLB 查看器里各看一次 A/B：胸部纹理/轮廓是否按预期改变，头肩、手持武器、裤腿、鞋、人物皮肤是否保持一致；绕至背面看披风，检查缺纹理、错位、白块、悬空装备。`glb` 能打开但胸部不变算**失败**，不是成功。
5. 另存 `probe.json` 或简短 `probe.md`：工具版本、客户端 build/locale、人物种族/性别/外观设置、逐槽 item ID、A/B 差别、缺件原因、每份 GLB 字节数与 SHA-256、预览/导出各一张截图、错误日志。保存一份角色配置文件（工具提供的话），方便重烘。Windows 可用 `Get-FileHash -Algorithm SHA256 <文件>`。

**停手判据**：A/B 两个 GLB 都能离线独立打开，且只改胸槽便能看到相应胸部变化、其余部位稳定，才算「固定套装整人 3D 的资产链跑通」。此时也只证明这两件与这个人物，不自动外推 76 个角色。若导出器无法读取 Forever 或同一槽变化不生效，就带错误与截图回来，先定位缺在客户端表、热更、工具适配还是模型导出；不要继续扩表或批量烘。

## 完整生产真正需要的数据

| 层 | 最小输入 | 本站现状与验证点 |
| --- | --- | --- |
| 要穿什么 | 每套/阵营逐槽 item ID、装备槽位、必要的 modified appearance/变体 ID | `app/data/bis.json` 已有 38 套两阵营 ID；不能只按物品中文名找外观 |
| 穿在谁身上 | 种族、性别、皮肤/脸/发型等自定义、站姿/镜头 | 当前配装数据**没有**这套设定；先给每职业固定一组可复现外观，再决定展示是否合适 |
| 物品到外观 | `ItemModifiedAppearance → ItemAppearance → ItemDisplayInfo`，再到组件模型、材质与贴图；需同 build 关系与热更 | 现有导出链的身体部位映射缺口仍在；现成工具可能封装这一层，但要用 A/B 验它在本 build 生效 |
| 人物可见形态 | 人物基础 M2/skin、皮肤/发型、身体八槽贴图、geoset 可见性与装备覆盖优先级 | 胸/腿/手/鞋主要靠这一层，不能用「有无独立装备 M2」判死 |
| 附件 | 头、双肩、披风、武器/盾的 M2/skin/BLP，以及骨骼挂点、朝向与缩放 | 既有“21.4%”只量了独立 M2 的部位匹配；还要看真实穿在人身上的结果 |
| 可重做性 | 客户端 build、工具版本、角色配置、逐槽 ID、导出文件哈希、人工对照结论 | 每一份预制 GLB 都须能追到这些输入，客户端或名单更新后按同配方重烘 |

如果 wow.export 的角色层无法读这个客户端，才让 Windows 侧继续抽**少量原始证据**：A/B 两件的 `ItemModifiedAppearance`、`ItemAppearance`、`ItemDisplayInfo` 相关行，`ItemDisplayInfoModelMatRes`、`ComponentModelFileData`、`ComponentTextureFileData`、`TextureFileData` 引用，角色基础 M2/skin 和被实际引用的 BLP，及相关布局/geoset 行。每张保留 DB2 原文件、解析 schema、样本行与 FileDataID/路径/字节数；只围绕 1488 与 2870，不导全库。当前 `ConditionalItemAppearance` 零行不应被当作“整人无法穿装备”的通用证明。
