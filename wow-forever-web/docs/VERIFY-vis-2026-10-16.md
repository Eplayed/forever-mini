## 二、跑出来才发现的两件事

1. **窄屏 sticky 会画出一条空带**。`.boardwrap` 在 375 下是横向滚动容器，
   sticky 的参照物就从视口变成这个容器，表头与分组头不再吸附，
   而那条 `top: calc(--hd-h + 33px)` 的声明会在表格顶部留下一个空带（375 实拍看到的）。
   修法是在 `@media (max-width:899px)` 里显式 `position:static`——
   和旧站 `.scrollx thead th{position:static}` 是同一条教训，**这次是新代码里重犯了一遍**。
2. **行计数断言会被分组头行污染**。改成 `tbody.grp` 结构后，组头也是一行 `<tr>`，
   `#sptbl tbody tr` 从 498 变 531（+33 组）、成就从 198 变 225（+27）。
   断言选择器统一加 `:not(.grp2h)`。这类"结构改了、计数断言悄悄多算"的错，
   只有把断言写成"等于数据算出来的数"才能当场抓住——写死 498 就会一路红到被人改成 531。

### 先说一个流程上的坑：:8821 服务的是 `app/dist`，不是热更新

第一轮量列宽时，动态页改完 colgroup 再跑，量出来还是旧值（`[46, 267, 96, 96, 96, 417, 96]`）。
不是缓存，是 `tools/serve.sh` 起的是 `npx vite preview`——**它读的是构建产物**。
改过 `app/src/**` 或 `src/css/**` 必须先 `cd app && npm run build`，否则实拍与断言验的都是上一版。
（`refresh.sh publish` 里已经先构建再跑门禁，但手工量列宽这条路径没有这道保护，只能记进规矩。）

### 三处实拍才发现的问题与量到的数

| 现象 | 量出来的数 | 为什么断言没抓住 |
| --- | --- | --- |
| 职业页"改动条目"表顶出横向滚动 | 表宽 620 vs 容器 530，溢出 **90px**（1280 桌面） | `.chtab` 在 `app.css` 里带着旧站布局下的 `min-width:620px`；断言只查过"整页不横溢"，那一页当时还没进断言范围 |
| 动态页"核到哪天"折成两行 | 列宽 96px，`2026-09-29` 等宽字 + 内边距要 ≈101px | 断言查的是列宽是否存在，不查文本是否被折行 |
| 排行页"猎人hunter"粘在一起 | `.dim.mono` 前间距 0 | 传承页有 `.ltab td .dim.mono{margin-left:6px}`，别的名页没有这条 |

修法都在**新站才加载的 `board.css`** 里：`.board.chtab{min-width:0}`、`.board td.dt{white-space:nowrap}`、
`.board td .dim.mono{margin-left:6px}`。动态页那张另改 colgroup：七列百分比凑满 100%（4/34/10/11/12/17/12）。

**为什么是"凑满 100%"而不是给日期列一个固定宽**：`table-layout:fixed` 下，指定宽度之和小于表宽时，
浏览器把富余**按比例摊给每一列**——第一次只把日期列换成 112px 固定宽，量出来变成
`[81, 301, 111, 123, 134, 167, 197]`：图标列被撑到 81px、日期列 197px，等于把洞从一处摊成七处。
凑满之后是 `[45, 379, 111, 123, 134, 189, 134]`，富余全留在名字列（它是阅读起点，宽一点不别扭）。
