## 新发现 1：保存回包再次放行旧稿（P0，阻断）

位置：video2text `web/templates/index.html` 的 `saveWxArticle()` 与 `wxArtSync()`。保存开始时 `seq = ++_wxArtSeq`；用户在 PUT 未返回时继续输入，`wxArtSync()` 会立即清掉旧判定，但**不会立即推进 `_wxArtSeq`**，而是等 420ms 后 `/parts` 发出才推进。若 PUT 在这段时间返回，`if (seq !== _wxArtSeq)` 仍通过，保存回包把旧稿的 `publish` 重新放进 `_wxArtParts`、设置 `_wxArtStale=False`、启用复制。

**页面级复现**：打开 97 号，把修订稿临时放进编辑框并等结构通过；拦截 `PUT /api/wechat/article/97`，延迟 160ms 后返回针对保存时旧文本的模拟绿色判定（真实服务器未写入）。点击“保存”，50ms 后在编辑框加入 `### 发布前还要回查的三件事`。第 280ms：编辑框已含待办，页面却又显示绿色“结构检查通过”，三颗复制按钮 `disabled=[false,false,false]`；等到第 880ms，新的 `/parts` 才把它判红并禁用。也就是说，上轮刚修的**旧正文可被复制**在“保存后继续改字”路径仍存在。

**最短修法**：任何 `input` 立即推进判定代次（不等 debounce），并使在飞的 PUT、`/parts` 回包都失效；`saveWxArticle()` 返回前再核对编辑框仍等于提交时的 `md`。若保存期间发生新输入，只说明“刚才提交的版本已保存/结果待核”，当前编辑框继续保持禁用，直到它自己的 `/parts` 成功且 0 error。给此路径加页面级红绿用例，PUT 继续用 mock 拦截，禁止真实库写入。

## 新发现 2：顶部 lint 仍是旧元数据（P1）

`GET /api/wechat/article/97` 当前返回的顶层 `lint` 只有旧 warning（“1 个段落超过 200 字”），而同一响应的 `publish.lint` 有**编辑待办 error + warning**。`openWxArticle()` 顶部读的是 `d.lint`，红条读的是 `d.publish`；实时编辑后的 `/parts` 也只刷新红条，不更新顶部 lint。交接所称“绿条、复制许可、lint 面板都读一份最终判定”因此尚未落实到界面。

**最短修法**：`read_article()` 现算 `article_verdict(md)` 后用这份结果覆盖响应 `lint`；前端顶部 lint 在打开、`/parts` 成功、保存成功时都从当前 `publish.lint` 渲染，不再显示生成当时存入 `article.json` 的旧判定。加入 97 号原稿打开态和编辑态断言，要求顶部 error 与红条一致。
