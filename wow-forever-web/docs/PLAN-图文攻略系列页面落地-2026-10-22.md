# 图文攻略系列怎样落到页面

日期：2026-10-22｜主角色：wow-planner｜输入：`PLAN-系统图文攻略系列-2026-10-22.md`、`PLAN-original-guide-2026-10-21.md`、当前 video2text `web/static/schedule.html`、资料站 `app/src/router.js`、`app/src/lib/nav.js` 与 `app/src/pages/UpdatesPage.vue`。

**状态：已定（线索先行的页面顺序与信息结构）／待 wow-pm 更新旧 PRD 的必填口径／待 wow-ui 出视觉与交互证据／待 wow-dev 和 video2text 维护者实现。** 这是可交接的页面结构方案；本轮没有修改工作台或资料站页面。

## 1. 先纠正流程入口

站主已明确：**先从素材库找线索，不存在必须先写的“玩家问题”。** 系列是线索经核查后的归档和发布结构，不是预先生成 26 张空文章卡来等素材填。正确顺序是：

`素材库视频／转写或官方信息 → 选中一条线索 → 核 Forever 归属与原始来源 → 归入系列、定本篇切口 → 补本站的查证／实操／比较 → 整理稿 → 拆文案并审内容 → 看版面 → 人工发布 → 资料站归档与后续回填`

“本篇切口”可以是一项改动解读、一个设置示范、一份职业对照或一个交易记录；允许陈述句标题。页面、数据库和模型提示词都**不应把“玩家问题”设为前置必填**。标题、切口与系列位置可在核查后再改。

当前 `schedule.html` 有手写排产卡、素材行的“采用／打开／预览”和上方官方公告；公告行实际只有“打开／复制标题”，没有“纳入系列”，也没有系列列表。资料站当前 21 条路由中没有攻略入口；`/updates` 是官方时间点、客户端改动、本站更新三类事实页，不能直接当成预测专栏。这些是页面设计的起点，不可把下面的新页面说成已存在。

页面主线可压成两张小图，避免误把“系列大纲”做成公开空页面：

```text
video2text：素材库线索 / Forever 官方信息
             ↓ 选中、看原文、纳入系列
           系列候选卡（来源｜归类｜待核｜本站增量）
             ↓ 证据齐后
           整理稿 → 拆文案 → 看版面 → 人工发布

资料站：    图文攻略总览
           ├─ 从上手到进阶：仅显示已发布的 A/B/C/D 文章
           └─ 官方信息观察：事实速读 / 影响推测 / 回看
             ↓
           文章详情 → 对应职业、副本、专业等查询工具
```

## 2. video2text 工作台：从线索进系列

入口仍放在现有排产表 `#schedule`，但主操作改成一个清晰的线索流水线：

| 页面位置 | 用户看见什么 | 主操作 | 保存什么 |
| --- | --- | --- | --- |
| 顶部“素材线索” | Forever 素材库最新／待核线索；标题、作者、日期、所属产品线判断、转写预览、原视频链接 | 打开素材、**纳入系列候选**；站主给的 DD 等库外公开链接可先人工登记为线索 | 素材库稳定 ID 或外部原 URL、发现时间；不复制整篇转写进排产卡 |
| 顶部“官方信息” | 只显示 Forever 的国服公告或已确认官方蓝贴；发布者与所属产品线分开展示 | 打开原文、**纳入系列候选** | 官方原 URL、发布日期、素材 ID；重复点复用同一候选 |
| “系列候选”列表 | 按 A 入门、B 职业、C 成长、D 进阶、O 官方观察筛选；展示来源、版本、核查状态和本站增量状态 | 归类、合并重复线索、搁置、开始整理 | 系列代码、可改的内容切口、采用素材 ID、核查记录、状态 |
| 候选详情 | 左边“采用的线索／原始来源”，右边“本站准备补什么／还缺什么”；下方已有关联整理稿 | 核原文、记实操、进整理稿 | 来源与版本、证据缺口、授权与实操记录；**无“玩家问题”字段** |
| 制作流程 | 当前本篇的整理稿 → ①拆文案与内容审核 → ②看版面 → 待发布包 | 按既有四关继续 | 同一候选 ID、稿件版本、内容审核状态、画面与使用依据 |

候选状态只需 `线索／待核／可写／文字待审／版面待审／待发布／已发布／待回填`。状态由证据和人工动作推进，不由系列归类或素材热度自动升级。“系列候选”不是第二份素材库；它只保存原素材 ID 和本站编辑信息。官方消息可以插队，但仍要进同一候选、核查和拆文案流程。

**与旧需求的冲突要先回流：** `PRD-video2text-Forever排产与海报质检-2026-10-21.md` 第 2 节 R1 第 4 条仍写“先让站主写玩家问题和本篇增量”。这条已被站主 2026-10-22 的新指令覆盖。wow-pm 必须更新该 PRD 再交 Qoder；开发不得继续做“玩家问题必填”的入口。现有手写排产历史记录和已采用素材保留，不因改入口被删除。

## 3. 资料站：一座系列入口，两类详情

资料站保持查询工具本职，新增一个内容入口 `#/guides`（实际路由仍用本站 hash 模式）。首页在已有板块入口旁放一张“图文攻略：从上手到进阶”卡，**至少有已审核发布的文章后才露出**；第一版不改目前固定的 11 格主导航。已有 `#/classes`、`#/dungeons`、`#/professions`、`#/updates` 继续是事实／查询页，只在对应文章发布后加“查看相关攻略”链接，不把文章正文复制进原页。

### 3.1 系列总览 `#/guides`

- 顶部两个栏目：“从上手到进阶”和“官方信息观察”。默认展示前者；各栏目只列**已发布**内容，不画 26 张空白卡、不显示虚假的完成率。
- 主系列按 A 入门、B 职业、C 成长、D 进阶排列。每篇卡片展示标题、1 句内容价值、适用版本、最近核对日期、预计阅读成本和指向的本站查询工具。素材多可以筛职业／场景；没有结果时显示真实空态。
- 对后来才发现但适合“入门”的素材，归类仍放 A。页面阅读顺序按难度编排，**不是**素材入库时间，也不限制后台先做哪个系列。
- “官方信息观察”按事件时间排列，卡片就地标“事实速读／影响推测／已回看”；同一官方事件的三篇内容互相串联。未上线的推测不混进 `#/updates` 的官方事实列表。

### 3.2 普通攻略 `#/guides/:slug`

页面顺序：面包屑“系列／阶段／本篇” → 标题与适用版本、核对日期 → 开头的实用结论 → 分步正文与必要截图／关键帧 → 自制选择表或回退清单 → “到本站继续查”相关工具链接 → 参考原文／素材来源与图片使用说明 → 上一篇／下一篇已发布攻略。手机端单列，先给结论和操作，再放大图；没有许可的他人关键帧不用，纯文字页成立。

文章可以由头条图文改编到网页，但网页必须提供更完整、可更新的来源与条件，避免只嵌一张头条长图。网页显示的是**已审核发布版本**，文中具体事实仍由 `src/data/` 唯一基底支撑；不在 Vue 组件里写第二份事实。内部素材 ID、待核清单和审核术语不上玩家页面。引用他人创作内容时，文末有原始链接与必要署名；资料条目的细粒度分歧仍到现有溯源页查。

### 3.3 官方观察稿 `#/guides/:slug`

同一路由、不同正文模板，四个醒目区块依序为：**官方已公布**（原文、时间、适用版本）／**本站判断**（影响路径与成立条件）／**还不能断定**（反例和缺口）／**后续回看**（新版本证据与此前判断是否成立）。预测与事实不能共用同一种标签颜色。回看时保留旧判断的日期和文字，新证据另起记录；不静默把旧预测改成“早就说对了”。

## 4. 数据与发布关系

首期只需要一个公开文章索引和各篇已审正文，拟落在 `wow-forever-web/src/data/` 并由新站读取；字段至少有 `id/slug/series/stage/title/summary/status/publishedAt/checkedAt/applicableVersion/sourceRefs/relatedRoutes/mediaAttribution/previous/next`。授权原件、后台候选与原始转写仍留在内部，不把未审核稿、第三方完整转写、许可原件或联系人放进资料站的公开构建。真正字段名、文件拆分和同步方式由 wow-dev 根据现有 `build-data.js` 与 `app-assets.py` 确定，不在本策划里制造第二个事实源。

只有在“内容事实与原创增量审完、图片使用依据齐、人工确认发布”后，候选才能进入公开索引。头条链接和网页链接在同一候选记录中回填，未发布时为空；版本变化则提示复核，不能以旧稿长期占着“最新”位置。小程序首期不加文章流、职业排行、动态预测、宏／WA 字符串或跳网页求助。
