# Wowhead 风格还原诊断与网页改版方案（wow-ui · 2026-10-11）

设计稿：[`docs/design/wowhead-style-2026-10-11.html`](design/wowhead-style-2026-10-11.html)（单文件，浏览器直接打开，可切「首页 / 天赋计算器 / 组件与令牌」）。

---

## 一、结论（先看这个）

**每次 AI 改页面都还原不出 Wowhead，不是"画功"问题，是四个必要条件在当前工程里根本不成立，加上流程上没有视觉对拍。** 具体：

1. **字体不对**——字形骨架是风格的第一载体，Wowhead 用的是专门字体，我们只用系统字体；
2. **色板方向相反**——Wowhead 是中性黑 + 无限蓝，我们是冷蓝灰 + 琥珀金；
3. **没有美术/纹理填充层**——Wowhead 的图标盒、天赋树、Hero 全是游戏美术，我们是纯色平面；
4. **组件语言不同**——圆角、大写拉字距标签、小节标题样式都不一样；
5. **工程与流程**——令牌不是单一事实源（裸 hex、内联样式散落），没有参考实拍入库，回归只数结构不看视觉。

## 三、为什么 AI 每次都还原不出来（根因拆解）

1. **字体（头号原因，权重最大）。** Open Sans 的字面、字距、大写形态与系统字体完全不同；标题用的 Brother 1816 是偏几何的窄骨架展示字。**字体不换，颜色调得再准也只是"像配色的另一个站"。**
2. **色板色相相反。** 冷蓝灰底 + 暖琥珀金 = "档案/工具台"气质（这是 2026-10-10 改版主动选择的方向）；Wowhead 是中性黑 + 冷蓝 + 白描边。两套语言互斥，靠局部改色无法统一。
3. **缺美术填充层。** Wowhead 的"魔兽味"主要来自游戏原画密度（图标轨、Banner、树底图），不是装饰特效。我们没有这一层，页面就永远是"通用深色后台"。
4. **组件规格不同。** Wowhead 圆角 2–3px（硬、利落），我们 6–8px（软）；标签一律大写拉字距；小节标题是居中带两侧横线的招牌样式。
5. **令牌不是单一事实源。** 实测现状：组件规则里 34 处裸 hex + 35 处 rgba，旧站 `app.js` 还有 29 处内联 `style=`（UI.md 7.3 已记）。AI 改页面时无法一处改全站，还会被内联样式盖掉。
6. **流程没有视觉闭环。**
   - `docs/reference/` 只有 3 张 wowclassicforever 实拍，**没有 Wowhead 实拍基线**，AI 凭印象生成；
   - `tools/site-check.py` 只断言结构计数与文案，**不做视觉 diff**，改完像不像没有任何东西能判；
   - 根 `AGENTS.md` 引用的六个角色 skill（wow-pm / wow-ui …）**在三个 skill 目录里都不存在对应文件**（本轮已核实），角色流程只靠台账约束，没有可执行的步骤固化。
7. **硬规则本身排除了必要条件。** 「无 Web 字体、无图标库」是当前红线；在这个约束下，任何 AI 都不可能还原 Wowhead——**需要用户决策放开"自托管字体"这一条**（字体文件本地化，不违反"素材一律本地、不热链"的红线）。

## 四、需要安装什么：插件 / skill / 依赖

| 类别 | 结论 |
| --- | --- |
| VSCode 插件 | **不需要**任何"风格生成"插件 |
| npm 依赖 / UI 库 / 图标库 / 动画库 | **不装**（守红线：不引组件库、不引图标库） |
| **Web 字体（需点头）** | 自托管 **Open Sans**（OFL，免费可商用）做正文与大写标签；**Brother 1816 是商业字体不能用**，用 **Hanken Grotesk**（OFL，气质最接近）做标题；中文继续走系统字体。设计稿 `docs/design/fonts/` 已示范：可变字体 woff2 随仓库走，**不引 Google CDN** |
| 工具栏 / 导航小图标 | 全部**内联 SVG**（设计稿已给出全套：撤销、重做、导入导出、布局、分享、全屏、反馈），零依赖、可随 currentColor 变色 |
| 角色 skill | 六个 wow-* skill 实际**未安装**。建议（可选）用 `skill-creator-for-work` 把 wow-ui 固化成真正的 skill：令牌引用 → 改动 → 无头截图 → 与参考基线对拍。不固化也可继续靠本文件 + ROLES.md 约束 |
| 设计类 skill | 已装的 `doubao-creative-design` 可用于后续出图；本稿用 HTML 直接做，与工程同源、无需 Figma |
| 视觉回归（可选增强） | 给 `tools/site-check.py` 加 pixelmatch 类视觉 diff：每页与 `docs/reference/wowhead-*.png` 基线比对，差异超阈值即失败。这是防止"以后再改又走样"的长期闸门 |

## 五、网页怎么改（交接 wow-dev 的落地顺序）

纯表现层改版，**不改数据字段、路由、真实文案与来源结构**。

1. **用户确认两件事**：① 本设计稿方向；② 放开"无 Web 字体"，改为"允许自托管 OFL 字体文件"。
2. **建令牌单一事实源**：新建 `src/css/tokens.css`（内容即设计稿 `:root` 令牌：中性黑 + 无限蓝 + 计算器橙 + 品质六色 + 字体栈 + 2–3px 圆角），静态站与 Vue 站共同引用；旧令牌保留一版映射，避免一次性大爆。
3. **改外壳 AppShell**：两行条（版本页签风格的首行 + 二级导航）+ 原画图标轨；静态站 `src/` 与 Vue `app/` 各实现一次并结构对拍。
4. **首页按设计稿顺序落地**：Hero（原画压暗 + 搜索）→ 最新收录 → 倒计时 → 精选指南 → 本站更新；**所有数字运行时读 `scale.json`，组件里不写死**。
5. **天赋计算器页**：工具栏内联 SVG、职业 Banner 原画、三棵树纹理用纯 CSS 多层渐变（零新素材）、图标与点数读数据。
6. **其余 12 个内容页逐页套壳**：每页完成后跑 `build-data.js` → `site-check.py`（桌面 + 375）→ `app-parity.py`，截图存 `docs/screenshots/`。
7. **清理技术债**：消灭组件内裸 hex 与内联 `style=`（令牌化），断言总数只增不减。

**最大风险/决策点**：字体规则变更（待确认）；其余均为低风险样式重构。纹理与图标轨全部复用仓库已有原画（`src/img/art/` 与 2013 张本地图标），**不需要新增素材**。

## 六、这一轮明确不做

- 不引任何第三方 CDN（含字体 CDN）、不引图标库 / UI 组件库 / 动画库；
- 不做 Hero 视频（用本地原画 + 渐变替代）；
- 排行页仍标注"本站整理的主观排序"；**本方案仅网页端，小程序不跟**（个人主体类目限制不变）；
- 不改任何数据、路由与来源结构。
