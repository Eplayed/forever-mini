# 无限资料小程序：移动查询首期 PRD 与开工单

日期：2026-10-21｜主角色：wow-pm｜版本：v0.1｜交接：wow-dev（Qoder）；备案与上线条件交 wow-ops 复核。

## 1. 产品决定与成功标准

小程序的工作不是把 21 个网页路由搬进微信，而是在玩家**排队、组队、进本前、看到陌生名称时**，用手机在几十秒内确认一条可靠信息。首期只做**副本随手查**，沿用现有中英速查能力；完成后再按实际使用需求推进技能、稀有坐标、天赋。界面应能清楚回答“这是哪个本／几级能去／在哪里／有哪些首领／哪条信息还待核”，并提供本地收藏、最近查看和微信内分享。地图、掉落等缺数据时不能用空图或猜测补齐。

目标用户：无限服玩家在手机上临时查资料，尤其组队前临时核对副本的玩家。首月小程序只承担**免费工具与复访入口**，不承担直接收款；是否带来 9.9 元资料包/整理服务的询问，需要在内容和经营台账中观察，不把打开量当成交。

首期验收（发布前用 5 个真实查找任务手测，不把目标当已实现）：从微信打开后，用户能在 **30 秒内**找到指定副本、看到关键字段和“待实测”标记；分享卡打开能直达同一副本；断网时不白屏且明确显示缓存/快照。实际用时、失败任务及设备型号记在 `for-mini/docs/VERIFY-*.md`。上线后两周观察：是否有人主动使用收藏/分享、哪几个字段被反复查、是否出现“缺某本/某项”的反馈；没有可靠统计就先做 5 人任务观察，不装分析 SDK。

## 4. P0 用户路径与页面契约

1. 微信内打开 → 首页“副本随手查”明确可用 → 一次点击到列表。首页原有术语入口仍可用。
2. 列表默认展示名称、类型、可核的等级区间、阵营/区域和 L0–L3 标记；搜中文或英文名。筛选只对实际存在的字段生效；未知字段显示“待实测”，不能当 0 或“所有阵营”。
3. 详情展示中文/英文名、适用等级、位置、队伍人数（有源才显示）、首领名单与各自状态、来源及核对日期。完整数据没有路线时不出现虚构“路线图”；掉落若显示只能列事实性物品与归属，不写掉率或“必出”。团本缺中文名时显示英文原名 + “中文名待核”，不机翻。
4. 用户可把该本加到本机收藏、最近查看；不上传个人行为，不要求登录。分享给微信好友应带稳定的副本 ID，接收方冷启动可直达，ID 不存在时回列表并给明确提示。复制名称/位置由用户主动触发。
5. 在线请求失败：已有缓存展示“离线缓存”及其生成/核对信息；首次离线至少展示小体积的副本索引快照，详情没有缓存时显示“详情需联网”，不能让人误以为实时完整。数据源沿用 `live/cache/snapshot` 三态。
6. 图片是可选增强。首单默认文字卡；未来加入客户端原画或插件自绘图时，遵守根规则的来源分类、manifest、OSS 独立目录与就地“示意图”说明，不热链，也不把图塞进主包。

首期不提供“推荐打哪个本”“哪个职业强”“预计收益”“几率”和战斗指导。对等级、阵营、名字分歧保留两个来源并说明本站当前取值，不以页面简洁为由删去来源。

首单最小验收样例（期望从**当轮基底现读**，不把下列值复制成页面常量）：

| 场景 | 输入/操作 | 必须看见 |
| --- | --- | --- |
| 新本 | 搜 `hall-of-thanes` 或“领主大厅” | 同一详情、等级/区域/首领来自该条记录；分歧名有说明，缺路线不画路线 |
| 经典本 | 搜 `ragefire-chasm` 或“怒焰裂谷” | 阵营与首领名单可读；掉落若出现只写物品与归属、L2 仍标待核 |
| 缺字段团本 | 打开 `barrow-deeps` | 英文名可读，中文名与等级缺失有明确状态；首领空数组不显示“0 个已确认首领” |
| 分享与异常 | 分享前两条到微信会话后冷启；再打开不存在的 ID | 真 ID 直达同一条；假 ID 给错误提示并能返回列表 |
| 网络退化 | 清缓存断网、曾访问详情后断网各测一次 | 首次可看索引快照但不冒充完整详情；缓存详情可读且明确标“离线缓存” |

## 5. 更新与发布机制

**唯一真源**仍是 `wow-forever-web/src/data/`。小程序侧只消费 `export-mini.js` 派生文件。一次更新按顺序执行：

`确认原始证据/插件版本 → 改基底与 provenance/checkedAt → build-data.js → export-mini.js → 核差分/快照预算 → 上传 beta 命名空间 → 真机联网/断网/旧缓存测试 → 生成版本化发布清单 → 提审/发布 → 推 release 命名空间 → 记录回滚版本`。

产品要求（可由 wow-dev 分步实现）：

- 每批产物有 `schemaVersion`、`buildId`、构建时间、源文件哈希、记录数和**另列**的事实核对日期；不能把 `buildId` 时间填成所有条目的 `checkedAt`。同一批文件要能识别是否混版，客户端版本不兼容时提示更新小程序。
- 先上传到 `wow/beta/v1/` 验证，再发布 `wow/release/v1/`。优先上传不可变版本目录，全部校验通过后切换一份小清单指针；至少保证一批新数据不会在一半上传成功时被用户读到。保留上一批能回退。
- 页面显示当前数据版本/核对日期；缓存落盘记录对应版本。失败时回退且明示 `cache/snapshot`，不能用旧缓存冒充“今日最新”。读请求尽量只取首页索引，进详情才取详情，避免每次打开都下载全量大 JSON。
- 数据改动跑 `cd wow-forever-web && node tools/build-data.js`，再跑 `node tools/export-mini.js`；导出重跑同源应字节一致。开发验收需覆盖有网/断网/旧缓存/损坏文件/版本不兼容/回滚。上传动作不包含在 Qoder 首单 M01；正式发布前作为单独发行验收。
- 更新节奏：**每周一次小批核对并发布**，开服/插件变更时只紧急核本轮会显示的字段。每次按“新增/修正/撤回/仍待实测”留简短差分；无新证据不改数。运营每周根据真实查询与反馈决定下周核什么，不维护第二套小程序手写数据。

## 6. 成本、工时与停止条件

**现金成本结构**：现有 OSS Bucket 增量存储 + GET 请求 + 外网下行；没有新服务器的 P0 不产生固定云主机成本。独立小程序 appid、名称、备案/认证、域名白名单是发布前置工作，是否有认证/域名等一次性费用要以账号后台和实际采购单核对，**目前不记成 0，也不在此编一个官方价**。广告、支付、云函数、数据库首期均不买。OSS 的计费项可参见[阿里云计费概述](https://help.aliyun.com/zh/oss/understanding-billing/)。

为让预算有数量级，用**公开案例单价作演算假设，不是当前账号报价**：外网下行 ¥0.50/GB、GET ¥0.01/万次（[阿里云案例，注明单价来自 2024-11-20](https://help.aliyun.com/zh/oss/billing-examples/)）；标准存储示例 ¥0.12/GB/月（[存储费用说明](https://help.aliyun.com/zh/oss/storage-fees)）。假设每次完整使用都下载现有三份 JSON 共 420,363 字节，3 次 GET，按 1 GB 的预留存储计；不含图像、免费额度、共享 Bucket 的其他项目流量和税费：

| 月完整使用次数 | 估算下行 | 下行费 | GET 费 | 1 GB 存储假设 | 示例合计 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 万 | 4.20 GB | ¥2.10 | ¥0.03 | ¥0.12 | **约 ¥2.25/月** |
| 10 万 | 42.04 GB | ¥21.02 | ¥0.30 | ¥0.12 | **约 ¥21.44/月** |

这是保守的“每次都下完整三文件”演算；分片与缓存可下降，图片会显著上升。若日后每次额外加载 2 MB 图片，1 万次约新增 20 GB/¥10，10 万次约新增 200 GB/¥100（仍用同一演算价）。真实账单按 OSS 地域、冗余类型、忙闲时段、是否走 CDN/资源包及账户免费额度重算，首次发布前从控制台导出当前 Bucket 的三个计费项单价和用量。不要为了几百 KB 数据提前买服务器或资源包。[阿里云资源包说明](https://help.aliyun.com/zh/oss/purchase-resource-plans/)建议用量稳定后再购买。

**人力是主要成本**：M01 建议时间盒 **15–25 小时开发与验证**（估算，不承诺 Qoder 用时），站主另留 2–3 小时做 5 人查找任务和真机核对；稳定后每周约 1–2 小时核本期新增/更正数据与回复问题。以 `实际小时 × 自定小时机会成本` 单列核算；Qoder 模型费用按实际 token/调用账单记，不凭模型名估价。若首单超过 25 小时还不能完成 38 本基础查询，暂停图片/地图/筛选扩展，先交文字列表、详情与离线状态。

**经营判断**：小程序是免费复访与信任工具，不要求它直接产生 ¥1,000。若 2 周内 5 人任务有 ≥3 人找不到目标，先修入口/搜索；若能找到但无人愿再打开，优先改查找场景或内容，不继续堆页面。每周把小程序维护工时与 9.9 元商品、定制服务的已履约收入放在同一张经营台账比较，避免为免费端长期投入超过现金回报。
