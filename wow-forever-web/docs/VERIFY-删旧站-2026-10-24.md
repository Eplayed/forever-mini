## 二、路径改口打到哪一层

`tools/` 里 60 个脚本的路径常量与说明文字、`app/` 里 21 个文件（含 11 份单测的取数路径）、
`app/src/main.js` 的三份 CSS 引用、`fonts.css` 的 `url()` 相对层级（`../fonts/` → `fonts/`）。
另外三处不是"改个路径"就能了事的：

1. **`build-data.js` 那两处"回旧站核对"**：上线日期原来同时读 `src/js/app.js` 的 `LAUNCH`，
   搜索分组顺序表原来读旧站的 `SKIND_ORDER`。现在都改读这一站自己那份真源——
   `app/src/lib/fmt.js` 的 `LAUNCH_AT`、`app/src/lib/search.js` 的 `KIND_ORDER`；
   "索引指向的页面在不在"改成查 `app/src/router.js` 的 `MIGRATED`，不再查磁盘上有没有那个 `.html`。
2. **`app-assets.py` 的头标**：源目录变了以后原来那句 `if not exists: continue` 会**静默不拷**，
   public 里留着上一轮的副本，"站根没图标"这件事在本地永远看不出来。现在改成
   `(源, 落点)` 成对表 + 缺文件直接非 0 退出。
3. **数据里写死的旧路径**：`app/data/art.json` 那条天裔回退说明、`dungeons.json` 的 manifest 指向、
   `ui-art.json` 的来路句子、`guide.json` 的 source、两份 manifest 的登记串——
   都是玩家或维护者会照着找文件的话，已按当前结构改口（生成侧 `merge-dungeons.js`、
   `build-icon-map.py`、`fetch-art.py`、`make-favicon.py` 同步改，避免下轮重跑又抄回旧路径）。

## 三、门禁重做：界面门槛从此只测新站

`site-check.py` 原来默认打 `src/*.html`，`--app` 只是"新站端口不通就算失败"。现在：

- 被测对象是**它自己起的静态服务打的 `app/dist`**（`--app-base` 可改打 preview 或线上，给了就要求连得上）；
  所以跑之前必须 `cd app && npm run build`——`refresh.sh` 的 `gate()` 已经把构建排在它前面。
- 撤下 19 个"只在旧站跑"的小节，**共 366 条断言**（逐节条数见下表）。
- 天赋计算器与 375px 那两节**整节搬进新站**并跑通：新站的 `.node[data-n]`、`.rank`、`lock`、
  `@contextmenu`、`@touchstart` 与旧站同一套钩子，只有两处写法要换——
  派发真事件而不是调 `n.oncontextmenu()`（Vue 用 addEventListener，那个属性是 undefined），
  以及分享还原改成"新上下文直接给那条 hash 地址"（旧写法把整条 hash 拼了两遍）。
- 新增 `[21] 全站逐路由底线`（240 条）：路由名单**从 `app/src/router.js` 现读**，
  逐条路由查——一个 H1 且正文非空 / 无脚本报错与失败请求 / 图片有 alt 无坏图 / 按钮有可读名 /
  **正文没有文件式 `.html` 地址** / 整页不横溢 / 溯源层（徽标·来源块·覆盖率条·来源轨）只在溯源页出现 /
  会出掉落的那 8 页不出现百分比与"掉率" / 正文没有面向开发的词 / 文字对比度达 AA /
  375 下点击目标够 44px 且没有格子被切掉。
- `copy` 那节从遍历 19 个 html 改成遍历这批路由，另加副本页与天赋页"来源展开后"两条。

**这条新断言自己错过两次，记下来防再犯**：
① 我第一版把"点击目标 ≥44px"直接套在地图编号点位（`.zdot` 14px）和只有 3 个字的跳转链接上，
   还把 `.boardwrap` 里横向滚动的表格判成"被切掉"。判据要分层——有效点击区取"元素自己或
   包住它的 label / `cursor:pointer` 祖先中较大的那个"，溢出只算没有被滚动容器接住的那些，
   点位本体豁免（每条点位都有右侧列表那一行做等价大目标，`world_pins` 钉着这个联动）。
② `design_baseline` 那条"正文与控件"我原样搬过来要求控件数 >3，结果系统规则、时间表、排行、
   溯源四页全是纯读数页被误判。改成只要求正文非空 + 一个 H1。

**真实问题两处，已改代码不是改断言**：物品库分页器（34×32）与配装页部位芯片在 375 上戳不中，
以及传承页顶部三段跳转里"传承树"那颗宽度不足 44。统一在 `board.css` 加了一条窄屏规则
（`min-height/min-width: 44px` + `inline-flex` 居中），没有逐页补——逐页补的结果是下一张表格又忘。

## 八、补记：把"回落旧站"这一层也拆了（同日续做）

第一节只顾着改路径，漏了页面代码里那层"没迁的页回旧站"的分支——旧站没了，留着它就是把
"点了没反应"这个坑留在原地等下一个人踩。这一轮把它拆干净：

- `app/src/lib/nav.js`：删掉 `legacyUrl()` 与它的地址基准常量，删掉 `linkForQ()`（它的职责
  已经并进 `linkFor`，两份解析迟早漂）、`isMigrated()`、`MIGRATION_NOTE`。
  现在站内链接只有一个产出方式：认得的文件名 → `#/路由`（带 query 照带、锚点折成 `?to=`）；
  **认不出的交给路由表 catch-all**，由 `Unmigrated` 送去有内容的一页，不再拼 `.html`。
- `app/src/lib/search.js` 的 `itemLink()`：原来"类型不认识"和"目标页没迁"两条分支都拼
  `legacyUrl(...)`，现在一条回首页、一条走站内路由；顺手把"参数解两遍"合掉
  （`queryString()` 拼好、`linkFor` 折成 query，两处各解一次迟早对不上）。
- `app/.env.development`、`app/.env.production` 删除——这两个文件存在的唯一理由是
  `VITE_LEGACY_BASE` 那个开发期跨端口基准。
- `TalentPreview.vue` 三处 `linkForQ` 改 `linkFor`。
- `app/tests/lib.spec.js` 那组"导航链接归属"按新契约重写，并新增一条硬判据：
  **导航十二格逐格不许产出 `.html` 地址**（旧断言正好相反——它钉的是"锚点一律回旧站"
  和"旧站基址可配置"，旧站一删那两条就成了给死行为上锁）。
  `search.spec.js` 里"不认识的类型给旧站 index.html"那条改成断言回首页。
