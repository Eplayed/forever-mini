## 1. 结论与目标

赞成用排产表作为日常生产入口。现有排产表已有选题、节点、写作角度、人工钉选素材、实时查库与官方公告栏，足以承接选题工作，不必同时维护另一个雷达页面。

建议流程：**排产表选题 → 选头条/公众号 → 查看该题资料及要求 → 生成或继续整理稿 → 成稿与质检 → 人工发布 → 登记回填**。渠道也可以在表顶部预选；进入详情后保持不变。

核心区别：表中一条代表准备制作的一篇内容，可以关联多条素材。素材库仍然保存原料；整理稿仍是中间产物，生成成功不代表可以发布。

首月净收入目标为1,000元。本次改造的作用是减少重复选题、串渠道和找稿成本，不能把完成功能等同于收入。先打通一条头条与一条公众号的可验收链路，不扩成新的运营管理平台。

## 3. 用户规则的必要补全

### 3.1 从选题进入，单条素材仍可预览

- 保留当前卡片上的选题、决策时点和“必须有的那一格”，增加一个明确主入口“开始整理/继续处理”。
- 主入口带上选题要求，详情里允许选用一条或多条素材；素材标题的“打开/预览”继续只查看原料。
- 系统推荐的实时结果是候选。用户确认采用后保存本稿的素材清单；“重新查素材”只刷新候选，不能悄悄替换已用证据。
- 官方公告仍可临时加入排产，选择时建立任务关联，无需另建热点页。
- 不要求为了“交叉核对”凑够两个转载作者。一条官方事实可形成整理稿，但明确单源；多作者同源不能冒充独立验证。关键分歧留在待核项。

### 3.2 渠道从入口一路带到发布登记

- 一个选题可以做头条与公众号，但分别保存任务、稿件版本、质检结果、发布日期。
- 至少区分目标渠道与内容形式：头条图文、头条微头条不是同一产物；公众号使用公众号素材档案与成稿规则。
- 默认映射建议：头条攻略用现有 `game_guide`；公众号用 `wechat_material`。头条其他形式按实际内容用途选择，不把所有头条任务都强转同一类型。
- **summary_type只是整理结构，不能单独替代channel。** 同一素材也可能用于不同选题；按任务与精确素材关联找稿。
- 已有目标任务的整理稿时，主按钮默认“继续处理”；显式重生成才新建版本。其他渠道的稿可以参考，不能自动当成当前任务已经完成。
- 详情直接确认素材并发起原生成流程，避免靠搜索标题、轮询卡片完成勾选。

### 3.3 排产进度必须由真实产物推进

建议主状态只保留：待整理 → 整理中 → 待成稿/核查 → 待发布 → 已发布。失败或缺资料显示原因，并能继续；暂停与取消可作为辅助操作。

- 点进详情不推进状态；创建任务才进入整理中。
- 整理完成只证明中间稿存在，不能标“待发布”。
- 质检通过且对应成品存在才进入待发布。
- 复用现有人工发布登记，关联平台、最终内容快照、链接或平台内容标识、实际时间后，推进对应渠道任务为已发布。
- 原 localStorage 勾选迁移为“历史人工标记、待核对”，不能直接伪造成已验证发布；保留旧记录以便核对。
- 正式进度存入现有服务端数据层。浏览器缓存只存筛选偏好；当前静态计划至少迁入可持久编辑的排产记录，首次迁移不得丢掉标题、日期、hook、note、来源和钉选素材。

### 3.4 日期、版本、平台条件分开处理

现有“节点前三天”来自此前号主规则，本轮不擅自撤销。建议下一版采用以下区分：

| 类型 | 建议核查方式 |
| --- | --- |
| 公告、活动、补丁等节点内容 | 保留节点窗口；超期提示重新核对或改角度，不能仅改发布日期就恢复有效 |
| 配装查询、资料站使用等长期教程 | 建议改为版本/build是否适用、关键结论最后核验时间；老资料经核验仍可用，无需为了日期强找新转载 |
| 历史变化对比 | 可使用旧资料，但标明各自时间/版本，不能把过去与当前数值并排当作现行冲突 |

该分层是规则调整建议；未采纳前继续执行原窗口。排期逾期与事实失效应显示为两件事。

当前页面给所有任务展示“首发5倍补贴”“后台现在是0”“正文>100字”等旧提示。不能将历史账户状态和活动条件固化为永久通用验收。按渠道、形式、是否申请首发权益加载现行规则；条件未知显示待核。本轮未重新核验活动资格或收益政策。

真实操作证据可为截图、演示记录或可复算数据，不要求虚构亲历。公众号教程特别要说清操作前提、步骤、结果与不适用范围。

### 3.5 轻量复盘，服务首月目标

表中优先显示：计划日期、渠道、选题、状态、待补项与主按钮。详情可记录一句“读者完成什么任务”及内容用途（获取阅读/展示工具/展示服务样张），不要求填长表。

优先做资料够、能给读者明确结果、能展示自有资料能力的选题；不再用库内素材条数当作市场热度。缺证据的高热选题不能挤掉已经可交付的稿。

复盘复用现有发布记录，分别看阅读与收藏、真实询问、成交及成本。阅读不是收入；一笔订单只计算一次，无法归因就标未知。无需为本次改造新增收入系统。
