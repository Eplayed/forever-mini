## 二、Qoder 实施范围

### R1｜排产表只留 Forever 主线与 Forever 官方公告

1. `#schedule` 默认只展示 Forever 选题；`odur` 这类纯时光服题从主列表移出。`server` 这种对比其他服、但最终帮助玩家判断**要不要选 Forever** 的题可以保留，题卡必须写清 Forever 是决策对象。历史槽位、已采用素材和已生成稿件不删库；旧链接按 ID 仍可回看，不能被当新 Forever 稿继续误发。
2. 官方栏只列与 **Forever／“无限”该产品线**有关的暴雪公告，其他资料片、经典服、时光服公告不混入。来源身份和产品归属分开判断：`source=blizzard` 只能证明发布者是官方，**不能证明公告属于 Forever**。中文“无限”也不能匹配《火炬之光：无限》；模糊项不自动采用。公告为空时给真实空态，不以旧公告补数。
3. 不再以“标题或作者含魔兽/无限”作为本篇可用素材的充分条件。候选按**具体选题**核归属、时间、正文与证据价值；作者名不能给一条跑题视频洗成 Forever 素材。跨线候选不进主列表、不计新鲜度和优先级。已采用的旧跨线材料要显示“需复核／取消采用”，**不静默移除、不送入新稿**。不要用一个不透明 AI 分类结果冒充事实；给出可复查的归属依据和待人工核项。
4. 顶部 Forever 官方公告加“作为选题／开始整理”入口：创建或复用一个稳定 ID 的排产任务，自动关联这条官方材料及链接/日期；先从素材线索核来源、确定本篇切口和本站增量，再进同一套任务弹窗，**不要求预先填写“玩家问题”**。重复点不建重复题；公告如果只能做资讯，就如实选「资讯整合／资料速查」，不能自动命名为“亲测攻略”。若该公告已有本篇任务，点它应继续旧任务。
5. 原先颜色/新鲜度 R1–R5 的修复仍按上游任务书做；**颜色只代表处理优先级，不代表文案通过或可发布**。排产主屏收起无关奖池/跨平台首发宣称，不再把 72 小时或“首发 5 倍”写成自动通过条件；这不改变平台规则，只避免误导工作流。

### R2｜从排产任务进入“头条 Forever 攻略”专注模式

1. 贯通 `slot_key + channel=toutiao + form=guide + version + summary_id`，从卡片/官方公告 → 本篇采用 → 整理稿 → 海报时显示同一题的标题、内容切口、采用证据和稿件版本；如果编辑自愿记录玩家问题，可作为可选说明。刷新/返回/重开不串篇；不能拿全局 `_poster_status` 上一篇计划回填另一篇。
2. 从这个入口打开的 AI 海报只显示本次有关的主操作：**① 拆文案（含内容审核）→ ② 看版面 → ③ 生成待审成品／导出待发布包**。头条渠道与图文攻略身份固定可见；藏起小红书/公众号切换、AI 直出画字、三张挑一、通用插画与豆包底图等无关选择。默认攻略页排版 + 素材关键帧，不用模型重画新图；缺可用帧可做纯文字页。确需替换为自有截图时单独标来源与用途。只在 Forever 专注模式收口，不破坏工作台其他题材/渠道原功能。
3. 重拆文案、重开稿件不得悄悄把 `guide` 改成插画布局，亦不得恢复上次小红书渠道或把另一个稿的发布配文带进来。若用户明确切到非攻略路径，须退出专注模式并提示会改变出图方式与成本。

### R3｜**重点：① 拆文案改成“生成 → 核查 → 人工确认”的内容主卡口**

1. 输入不能只有整理稿一段文字。沿用排产版本、采用素材快照、`guide_provenance` 的内容切口/独立贡献/逐条结论证据和已有【风险核查】，把**已核事实、参考转述、待核、我们的判断**分开送入拆解；旧字段若名为“玩家问题”，其值只作可选编辑说明，不是起稿条件。资料站查询记录不能写成游戏内实测；缺证据时允许生成内部草稿，但不能给“可发布”结论。无需新建第二份事实真源。
2. 拆解结果先展示完整的**可编辑文字攻略**：适用版本与对象、内容切口、前提/入口、按顺序可执行的步骤、完成后的检查点、例外/未知、本站新增内容、每页图上文字、头条标题和完整发布配文。资讯题没有可执行步骤就明确标为“资料整理/速查”，不凑攻略。让站主在图出现前即可读完整稿，逐页修改并与原始证据对照。
3. 自动检查至少指出：题目与所选 Forever 选题是否相符；关键名称/数字/版本/条件有无可回查出处；待核说法是否升格为标题、大字、行动指令；步骤是否缺入口、前提、结果；同页或跨页是否矛盾；标题与配文是否新添正文没有的结论；配文是否截半句；是否把时光服/正式服/《至暗之夜》的事实写成 Forever 事实。机器抓不准的语义问题列“人工待核”，不要假报全自动通过。复用 `fact_gate.check` 与现有反例，**把可定位的事实问题前移到拆文案阶段**，③ 出图时仍做最终复查以防编辑后回归。
4. 现在 `fit_plan()` 的“删末位卡片／截短说明”和字段 `_clip` 不能静默损失步骤、适用条件、警告或来源。超字数优先增页/缩小题目；若超过页数或文字预算，显示被舍弃/压缩的**原句与位置**并保持未确认，交人改，不能只给「已压到 200 字」。发布配文不得硬切断句。
5. 站主逐项确认“可执行、事实与条件、独立贡献、标题/配文”后，保存**内容审核记录**，绑定排产任务版本、整理稿内容哈希、文案计划与发布配文哈希。修改任一文字或证据、重新拆文案、换采用素材/版本，都让旧确认失效并提示要复核。缺项可存草稿；“字数合格／✅ 可出图”必须改成准确的“版式字数合格”，不能代替内容通过。人工确认是编辑状态，**不是平台原创认证**。
6. 图片用途先留在稿件计划中：这一页希望关键帧帮助读者看清哪个界面/动作/对象及它不能证明什么。真正选帧与审核在下一步；图片**解释或展示信息即可，不要求与文字逐字一致**。不得把泛用场景帧写成“已实测该数值/效果”的证据，也不得把去字幕/水印当使用许可。

### R4｜② 看版面只验呈现，回改文案不重跑选题

1. 继续使用当前免费预览的实际 `poster_typeset` 排版函数，逐页显示主标题/卡片、真实关键帧或纯文字页、页序、折行/裁切、字的可读性、图是否帮助解释这一页；图注只留档不上图。显示“第几页有真帧、哪张帧、来源及用途”，不虚报“都有图”。
2. 进入②前显示①的内容审核状态；未确认文字可做**带“内部草稿”标记**的免费预览用于修改，但不能由预览绿灯升级为内容通过。对照人工确认的文案哈希：文字或证据变动使内容确认与版面预览都过期；仅换帧使版面预览和用图审核过期，**不必让已核文字重新签一遍**。重预览后才进正式成品。
3. 预览发现内容/事实错误，回①直接修改；只有排版问题就在②换页/改版；关键帧不适合就撤帧或换帧。不要用反复换皮肤掩盖内容问题。允许一页没有合适关键帧；没有真帧时不自动退回 AI 插画。
4. 最终成品逐页与**当前**审核过的文字和预览对拍，事实闸、编辑证据链、关键帧来源与使用依据、发布配文都仍要检查。缺项时可保留内部草稿，不得标待发布。复用上轮 `prepare_guide_release.py` 的逐项人工签核／出包逻辑，做成可从成品页找到的“导出人工待发布包”入口，或给等价的清晰入口；不要另造一套放行标准。头条后台仍由人查看、上传、判断声明并发布。
