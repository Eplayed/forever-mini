## 统计口径与局限

排序名是“周下载量排行”，卡片指标是“周安装量”和“总安装量”。本文沿用卡片指标，不能解释为活跃用户、独立下载者或付费意愿。

平台未在所读页面解释是否包含更新、重装、整合包带装，也未说明周的起止时间及版本归属。为检查版本归属，临时查看正式服同名条目：BlizzMove 两页均为周 6.5 万／总 670.3 万；Details 两页均为周 8.4 万／总 2 亿；DBM 总量均为 4.8 亿，周量先后 18.8／18.9 万。该观察支持“数字可能按项目共用”的判断，但不足以证明后台统计实现。主样本始终只取无限服页，正式服不参与排名。用户提醒后已恢复无限服并核实。

不同汉化、分发条目、主插件与数据库、整合包和子模块不可直接相加：DungeonsForever 两条、Questie 与 QuestieDB、Lueur 原版与汉化版尤其明显。本文不给合计玩家数、类别市场份额或由周量／总量推导的增长率。名称里带未来日期照录为名称，不当成发布日期。

榜单说明“有人安装这一类产品”；一个全能插件的量不能归因到其中每个子功能，排名也不能证明产品质量或当前 Forever 兼容性。

## 面向“容易实现且高价值”的选择

估时是熟悉 Lua 的开发者制作窄范围可试用版的规划估计，包含基本游戏内验证；不含新手学习、DD 入库、全套兼容和内容维护。接口探针不过需重估。顺序兼顾需求证据、实现成本和本项目可用资料，不是按下载量机械排序。

### 1. 找人找入口：轻量服务点查询

建议首选。输入“修理、邮箱、拍卖行、训练师、某副本入口”，只显示已核位置、所在区域、地图点。起步限两个主城和五座常去副本；支持阵营筛选及原生地图点，导航接现成能力前先测兼容。

依据：openmap、Waypoint、NPC五合一、MapNotes多个产品指向“找到目标”场景。不是另造高清地图或全世界最短路径。暂估 3–5 人日，另算坐标核对。

差异化尚待验证：现有 HandyNotes/MapNotes 是否已经足够；应亲测“打开→搜索→找到”的步骤后，决定改善速度、中文搜索还是无限服新增地点。自家已有坐标可降低采编成本，但旧资料未必覆盖所选主城与服务点。

### 2. 聊天便签：留住有用的一句话

候选首作。手动把聊天中的坐标、物品链接或密语存成可搜索记录，标时间，支持复制和清理。首版只做本人本机保存、手动钉选，不上传聊天、不自动私聊或刷组队消息。暂估 2–4 人日。

依据：WhisperPop、Copy Anything、MtjChatBar 的独立小工具也有数万周安装量。该方向比上一轮泛化的“上线便签”更有榜单支撑，但榜单不能证明“自动提取坐标”这一具体设计已被验证。开工前核 QIM 的功能，避免把停止维护误当成无人竞争。

### 3. 物品去哪了：轻量定位与缺口

显示用户指定物品在当前背包、最近查看过的银行及已记录角色上的数量和时间，支持一张目标清单。先做当前角色背包／银行，再扩多角色。首版不做邮件、拍卖行、公会银行。暂估 4–7 人日。

依据：BagSync、Syndicator 各 4.6 万周安装量。真正难点是银行未看过、离线数据过期，以及各插件缓存不一定提供稳定接口。不要把旧快照标成实时，不以替换整个背包 UI 为目标。

### 4. 进本前任务核对

长期产品匹配度高，开发不算最轻。只服务三座副本，按任务 ID 展示已接、已完成和缺前置，明确未知状态，先不做全任务导航。暂估 5–10 人日，另加任务与前置核验。

依据是任务、副本类最强的榜单信号，以及本项目已有资料能力。但大插件的下载量无法单独证明“漏接检查”需求；先亲测它们现有清单，找到具体缺陷。现有 questID 桥接缺口仍需 wow-data 先交文件。

### 5. 猎人宠物技能来源小助手

只做一个职业、少量已核宠物技能的来源查询和地图点，目标是回答“这个技能去找什么野兽学”。先核 Forever 真实机制与数据，再决定范围；暂估 3–5 人日加采编。野兽图鉴与 Hunters Handbook 已有直接竞争，细分人群的量不应与全职业工具直接比高低。

## 对上一轮建议的修订

「本地已安装」不是“市场需求已饱和”的证据。这次用整个无限服榜单中的已安装和未安装条目一起判断。地图查询、聊天信息留存、物品归属查询的需求证据更充分，提升优先级。

「出发检查」「下次上线接着做」仍可作为低成本假设，但前 100 样本没有足够直接证据支撑优先推荐；这不代表全库没有，也不代表无价值。专业备料同样不能因为本机已有一个工具就判定没机会，真正可研究的是已存在工具没完成的具体流程。
