# 全站视觉改版方案（2026-10-10）

工具：`frontend-design` skill v2.4.0（已装到 `~/.qoder-cn/skills/frontend-design`，装前审过它的三个 Python 脚本：
无联网、无子进程、无 eval，只有 `--persist` 会往 `./design-system/<项目>/` 写 md，本轮不用这个参数）。
它给的推荐我**没有照抄**，取舍写在下面第三节。

---

## 一、读题（Design Read）

一句话：**这是给"要查证一条中文叫法/一个数值能不能信"的无限服玩家用的深色资料档案站，
走"档案 + 工具台"语言，不追潮流；辨识度来自等宽小字元数据 + 大字标题 + 一条来源轨，不是来自配色花哨。**

### 目标用户（三类，按来这站的动机分）

| 谁 | 来干什么 | 页面上最在乎什么 | 最烦什么 |
| --- | --- | --- | --- |
| 国服无限测试玩家（开荒前查一下） | 查天赋怎么点、本里谁掉什么、传承有什么 | 数据新不新、是不是游戏里的叫法 | 满屏攻略废话、要登录才能看 |
| 从英文客户端切过来的人 | 中英对照、找官方中文名 | 译名有没有出处 | 机翻、别名混在一起 |
| 做内容的人（写攻略/做视频） | 引用一条名称、坐标、上限 | 这条能不能引用、要不要标待实测 | 引用了假数据被评论区抓 |

三类人问的是**同一个问题**：这条数据可信到什么程度。所以这一站的视觉主角不是装饰，是**可信度**。

### 核心任务（每页一个，改版不许改变它）

搜索 → 定位到某一条 → 看清它的分级与来源 → 决定信不信 / 要不要引用。
所有版式决策都为这条链服务：一眼能扫到"哪条是核过的"。

### 内容特点（决定了版式）

1. **表格密度高**：配方 1990 条、改动 964 条、掉落 1055 条 —— 不是营销页，是数据台。
2. **每条都带元数据**：分级、来源、核对日期、物品编号 —— 元数据是内容的一部分，不是脚注。
3. **缺口是常态**：6 格未公开、83 个缺图、5 个职业没中文名 —— "没有"必须看得见，不能藏。
4. **中文为主 + 数字英文对照** —— 中英混排的对齐与字距是排印难点。
5. **有真实游戏素材**（图标、原画）—— 底色必须压得住图，不能和素材抢色相。

### 三个旋钮（取值 + 理由）

| 旋钮 | 取值 | 为什么 |
| --- | --- | --- |
| `DESIGN_VARIANCE` | **4**（偏稳） | 资料站靠"可预期"活着。首页与时间表可以有一点版式变化，数据页一律规整。 |
| `MOTION_INTENSITY` | **2**（克制） | 玩家是来查东西的，不是来看动效的。只做三处，且都能关。 |
| `VISUAL_DENSITY` | **7**（密） | 一屏能看到 15 条配方比"呼吸感"重要；靠元数据行与规则线分块，不靠大留白。 |

## 二、这一版真正要修的问题（不是换皮肤）

审代码量出来的，都是能复现的缺陷：

1. **一个色板在给四件事编码，互相打架。** 分级 L0/L1/L2/L3、阵营联盟/部落、改动四态、
   物品品质（游戏原生语义）现在共用同一批绿/蓝/黄/紫。后果很具体：
   **琥珀金既是本站品牌色，又是 L2「待实测」的颜色**——选中格描金和"这条没核实"在同一个页面上长一个样。
2. **`.conf`（译名分歧提示）用 `--bad` `#c9564a` 写在 12px 小字上，实测对比度 4.08:1，低于 AA 的 4.5:1。**
3. **34 处裸 hex + 35 处 rgba 散在组件规则里，`app.js` 还有 29 处内联 `style=`**，会盖掉媒体查询（这条 UI.md 7.3 早就记过）。
4. **完全没有 `prefers-reduced-motion`**：全站有过渡动效，但没有一处关得掉。

## 三、skill 推荐了什么、我为什么不照抄

| 它给的 | 我的处置 | 理由 |
| --- | --- | --- |
| 风格 "Modern Dark (Cinema Mobile)"：玻璃拟态 + 环境光斑 + indigo | **拒绝** | 它自己的反默认清单就列了 glassmorphism；而且"糊一层毛玻璃"和"这条数据可不可信"是相反的气质。 |
| 配色 Felt green + gold（`#0F172A` 底 + 绿主色） | **拒绝换底**，保留近黑暖底 | 用户已定"保留近黑 + 琥珀金"；换 slate 蓝底会让本地转存的客户端原画偏色。 |
| 字体 Orbitron + JetBrains Mono（Google Fonts 链接） | **拒绝引字体**，只借它的**角色分工** | 不引 web 字体是既定规则；但它"标题/正文/等宽元数据"三角色、以及"标签用等宽 + 字距拉开"这套结构是好东西，照搬。 |
| 版式模式 "Hero(实时状态) + 关键指标 + 怎么做 + CTA" | **采纳** | 和首页现有的"倒计时 + 覆盖率条 + 搜索 + 模块卡"对得上，只做强化。 |
| 底线清单（对比度、键盘焦点、reduced-motion、语义 token、不用布局属性做动效） | **全部采纳并写进断言** | 这几条我们现在确实没做到。 |

## 四、配色：让颜色只承担一件事

规则：**分级不再靠色相**，改成"形状 + 文字 + 明度"三通道（分级是有序量，本来就不该用四个色相表示）；
阵营与物品品质是游戏原生语义，保留色相但只在各自语境里出现；琥珀金从此只管交互与品牌。

### 命名色板（每个色一个职责）

| 名字 | 值 | 职责 | 实测对比度（vs `#0e1013` / `#171a1f` / `#1e222a`） |
| --- | --- | --- | --- |
| 墨底 | `#0e1013` | 页面底 | — |
| 砚面 | `#171a1f` | 卡片底 | — |
| 砚心 | `#1e222a` | 控件/内嵌底 | — |
| 界线 | `#2b3038` | 分隔线、轨道底 | 图形件 ≥3:1 达标 |
| 纸字 | `#e7e9ee` | 正文与标题 | 15.69 / 14.36 / 13.12 |
| 灰注 | `#98a1af` | 次要说明、元数据 | 7.31 / 6.69 / 6.11 |
| 琥珀金 | `#e0a96d` | **只用于交互与品牌**：当前页、链接、焦点、选中格 | 9.13 / 8.36 / 7.64 |
| 分歧红（文字态） | `#ff9b8f` | 译名分歧、错误提示的小字 | 9.38 / 8.59 / 7.85 |
| 分歧红（图形态） | `#c9564a` | 只做边框/三角等图形，不做小字 | 4.46 / 4.08 / 3.73（图形 ≥3:1 够用） |
| 联盟 | `#6fa8ff` | 仅阵营语境 | 7.91 / 7.24 / 6.62 |
| 部落 | `#c9564a` 图形 + `#ff9b8f` 文字 | 仅阵营语境 | 见上两行 |

**改的两处具体冲突**：`.conf` 的小字从 `--bad` 换成 `--txt-alert`（4.08 → 8.59）；
L2「待实测」从琥珀黄 `#d9a13b` 挪出金色族（见下）。

### 分级四态：形状 + 文字，不再靠色相

| 级别 | 轨道/圆点形状 | 文字 | 明度 |
| --- | --- | --- | --- |
| L0 已核实 | 实心方块 | 已官方核实 | 最亮（`#cfe8dd` 冷青白） |
| L1 仅官方英文 | 半填（左半实心） | 仅官方英文 | 中亮（`#a9b8c6`） |
| L2 待实测 | 空心环 | 待实测 | 中（`#9aa3ae`） |
| L3 缺数据 | 斜纹填充 | 缺数据 | 最暗（`#6b7280` + 斜纹） |

形状是有序量读不出来的部分，靠"实心 → 半填 → 空心 → 斜纹"表达"有 → 半个 → 没有"，
和文字徽标同时出现，色盲与黑白打印都还读得懂（这条进断言）。

## 五、排印：不引字体，靠角色与尺度

| 角色 | 字体栈 | 规格 | 用在哪 |
| --- | --- | --- | --- |
| 展示 | 系统中文无衬线（`--font-cn`） | h1 `clamp(28px, 4.4vw, 42px)` / 700 / `letter-spacing:-.015em` / 行高 1.18 | 每页唯一 H1 |
| 区块标题 | 同上 | 20px / 650 / 行高 1.3 | 卡片 h2 |
| 正文 | 同上 | 16px / 400 / 行高 1.75 | 说明段 |
| **元数据** | 系统等宽（`--font-mono`） | 11.5px / 500 / `letter-spacing:.09em` / `tabular-nums` / 拉丁与数字转大写 | 级别徽标、日期、编号、坐标、条数、板块眉标 |

辨识度就压在三件事上：**标题够大够紧、元数据一律等宽小字拉开字距、卡片头统一三段式**（眉标 → 标题 → 数值行）。
中文不做 `uppercase`（无效），只对拉丁字母与数字生效。

## 六、版式与签名元素

### 签名元素：**来源轨（provenance rail）**

每张内容卡左缘一条 3px 竖轨，**轨的填充形状 = 这张卡最弱的那条数据的分级**（实心/半填/空心/斜纹），
卡头的等宽元数据行写同样的级别文字。它不是装饰：一眼扫过去，轨的"实心程度"就是这页的可信度分布。
缺数据时轨是斜纹而不是没有轨——**空着也要看得见**。

### 卡片头三段式（统一 15 页）

```
┌───────────────────────────────────────────────────────────┐
│▌ 天赋 · 猎人 · 964 条改动里 112 条是新天赋      ← 眉标（等宽小字）
│▌ 三棵传承树，27 个槽位里 6 格还没公布           ← 标题
│▌ ● 已官方核实   ◌ 待实测   ▨ 缺数据   核对 2026-10-10 ← 元数据行
└───────────────────────────────────────────────────────────┘
 ▌ = 来源轨
```

### 首页（采纳它的 pattern，强化实时感）

```
┌ 无限资料站 · 距上线 25 天 13:01:35 ────────────────────────┐
│  查一条中文名，先告诉你它核实到哪一步        ← H1 就是承诺  │
│  ┌ 搜索框（全站 4292 条）───────────────────────────┐      │
│  └──────────────────────────────────────────────────┘      │
│  ▓▓▓▓▓▓░░░░ 覆盖率条  L0 366 · L1 114 · L2 360 · L3 2      │
│  ─────────────────────────────────────────────────────────  │
│  真树预览（左树右详情，与传承页同一套卡片头）              │
│  模块卡 7 张：每张左缘一条来源轨                            │
└────────────────────────────────────────────────────────────┘
```

## 七、动效（三处，CSS-only，可关）

| 位置 | 触发 | 规格 | 只动 |
| --- | --- | --- | --- |
| 卡片进入 | 首次渲染 | 240ms `cubic-bezier(.16,1,.3,1)`，`opacity` + `translateY(6px)` | transform/opacity |
| 来源轨填充 | 首次渲染，错峰 40ms | 220ms，`transform:scaleY()` | transform |
| 交互反馈 | hover / active / focus | 140ms，边框色 + `translateY(-1px)`；焦点环 2px 金 | 不动布局属性 |

`@media (prefers-reduced-motion: reduce)` 下三处全部归零（保留最终态，不做隐藏内容）。
倒计时每秒只改文本节点，不做动效——它本来就在动，再加动效是干扰。

## 八、判据 → 断言（写进 site-check 第 20 节）

改版不许只改样式不留证据，所以每条都要能跑：

1. 正文/标题/元数据三类文字对各自背景的对比度 ≥4.5:1（大字号 ≥3:1），逐页取计算值。
2. `.conf` 等红色小字必须走文字态色值（≥4.5:1）。
3. 分级四态：徽标除颜色外必带文字；来源轨形状与徽标级别一致（读 `data-lv` 与轨的 class）。
4. 琥珀金不出现在任何"数据状态"元素上（只允许 nav/链接/焦点/选中）。
5. 组件规则里不许新增裸 hex（对基线数做上限断言，只降不升）。
6. `prefers-reduced-motion: reduce` 下，卡片与轨道的 `transition-duration` 为 0s。
7. 焦点环可见（`outline` 非 none）且键盘可达。
8. 原有 415 条断言一条不许红：功能、路由、深链、真实文案全部保持。

## 九、这一版明确不做

- 不引 web 字体、不引图标库、不引动画库、不引 CSS 框架（两栈共用这一份 app.css）。
- 不做浅色模式（素材与原画是按深色压暗配的，浅色会重新踩一遍对比度）。
- 不改任何数据字段、页面路由、真实文案与来源结构。
- 不给"缺数据"编视觉占位（斜纹轨是"这里确实没有"，不是"我们假装有了"）。
