## 三、文档说明

### 名词解释

| 术语 | 说明 |
|------|------|
| Forever | 《魔兽世界：无限》的官方英文名，检索与命名一律用它，不用 Infinite |
| 专精 spec | 职业下的方向分支，如 猎人 → 生存/射击/野兽控制 |
| 天赋节点 node | 天赋树里一个可点格子，含层级、列位、最多点数、前置关系 |
| 基底 seed | `forever-seed.json`，人工核对后的数据源，站点与小程序共用 |
| 数据完整度 | 单个字段的可信等级：L0 官方中文已核 / L1 官方英文 / L2 待实测 / L3 缺失 |
| 溯源 provenance | 每条数据挂的来源类型 + URL + 核对日期 |

## 四、需求背景

### 4.1 产品 / 数据现状

- **产品现状**：无限服 2026-11-05 全球同步上线，国服 Beta 2026-10-06 开启。英文侧已有成体系资料站（wowclassicforever.info、Wowhead Forever 专区），中文侧只有零散攻略文章和一个天赋模拟器，**没有结构化、可查询、带译名对照的中文资料站**。
- **核心问题**：中文玩家查无限服资料要跨英文站（还要能访问）、跨视频、跨帖子，且英文技能名与国服官方中文名对不上，抄错译名是高频事故。
- **北极星目标**：玩家在手机或 PC 上，**3 次点击内**查到某职业某专精的完整天赋加点方案，并同时看到每个节点的官方中文名与英文名。

### 4.2 用户调研

| 调研方法 | 样本情况 | 关键结论 |
|---------|---------|---------|
| 需求侧证据采集（贴吧无限吧、B站实测视频评论区、头条/网易转载） | 2026-09 至 10 月公开内容 | 高频提问集中在三件事：天赋怎么点、这个技能国服叫什么、这个本哪个 BOSS 掉什么 |
| 官方资料盘点（wow.blizzard.cn 职业深度解析） | 猎人、德鲁伊、牧师、战士等篇 | 官方**只给文字描述，不给可交互天赋树**，但给出了权威中文技能/天赋名，正是本站最缺的译名基准 |
| 插件生态变化 | 官方公告与玩家讨论 | WeakAuras / Hekili 等循环提示被禁，玩家失去"告诉我点什么"的工具，资料站承接这部分需求 |

### 4.3 竞品分析

| 竞品 | 主要信息 | 关键结论 |
|------|---------|---------|
| wowclassicforever.info | 英文粉丝站，有天赋模拟器、副本、套装、新物品索引，带简中路由 | **功能形态照此对齐**；数据禁止整库搬运，只作核对参照 |
| Wowhead Forever 专区 | 逐本指南、每职业天赋计算器、三张天梯、任务/声望/专业全套 | 资料最全，但大陆网络下脚本抓取 403，且禁止搬数据 → 只作人工核对源 |
| foreverchanges.pro | 9 座新本名单与等级区间，掉落大量"not known yet" | 说明**连英文专库都没有完整掉落**，本站不能假装自己有 |
| pigtogo.cn 无限天赋模拟器 / 百家号公众号工具 | 中文，只到天赋一层 | 中文已有工具**不做译名对照、不做溯源、不给副本**，这是差异化空间 |

## 五、需求范围

### 5.1 功能架构

```
无限中文资料站（纯静态）
├── 首页            职业九宫格 + 全站搜索 + 数据完整度总览
├── 天赋计算器 ★P0  职业→专精→三系天赋树，点击加点、前置校验、方案编码分享
├── 技能书          按职业/专精列技能，中英对照、来源与核对状态
├── 副本手册        9 新本 + 经典本，BOSS 列表、路线、掉落（按完整度显示）
├── 装备与套装      按部位/套装筛选，属性字段留结构，缺数据不编造
├── 中英术语速查    全量词条搜索，一键复制
├── 溯源与核对      每条数据的来源、URL、核对日期；未证实清单
└── tools/          构建脚本：基底 JSON → 站点分片 JSON + 覆盖率报告
```

| 数据层 | 统一 JSON 契约 + 分片加载 + 溯源字段 | P0 | 小程序可复用同一份 |

## 六、功能详细说明

### 6.1 产品流程图

```
进入首页
  └─ 选职业（9）
       └─ 选专精（3）
            └─ 天赋树页（3 系并列）★ 北极星路径，3 次点击
                 ├─ 点节点加点 / 右键减点
                 ├─ 前置不足 → 置灰 + 提示缺哪个
                 ├─ 「复制方案」→ 文本
                 └─ 「分享」→ URL hash，打开即还原
       └─ 技能书页（同职业，中英对照）
  └─ 顶部搜索：输入技能名/副本名/装备名 → 直达对应页
```

### 6.2 交互原型图

见同项目 `docs/UI.md` 与 `docs/ui-*.png`（UI 稿阶段产出）。

### 6.3 功能说明

| 序号 | 模块 | 功能 | 详细说明 |
|------|------|------|---------|
| 1 | 数据层 | 统一契约 | 所有页面只读 `data/*.json`，字段与溯源结构见 6.4 |
| 2 | 天赋计算器 | 渲染与交互 | 三系并列，节点显示图标位、中文名、英文名、已点/最大点数 |
| 3 | 天赋计算器 | 规则校验 | 层级解锁需上一层点数、单系最少投入门槛、总点数上限，全部由数据驱动不写死 |
| 4 | 天赋计算器 | 方案持久化 | localStorage 保存 + URL hash 分享，两者可互相还原 |
| 5 | 技能书/术语 | 搜索 | 中文、英文、拼音首字母都不支持时至少支持中英包含匹配，实时过滤 |
| 6 | 副本手册 | 完整度显示 | 无数据的字段显示"待实测"，不出现空表格 |
| 7 | 溯源页 | 覆盖率 | 按职业/模块统计 L0-L3 占比，低于阈值时页面顶部黄条提示 |
| 8 | 构建工具 | 卡口 | 缺字段、来源非官方却标 verified、JSON 解析失败 → 构建失败 |

**功能名称**：天赋计算器（P0，核心）

**需求描述**：
- 玩家选职业与专精后，看到该专精三系天赋树，可点击加点、查看每个节点的官方中文名与英文名，并把方案分享出去。

**交互流程**：
1. 首页点职业卡片 → 进入职业页，默认选中第一个专精；
2. 点天赋节点：可点则 +1 级；已达上限则不响应并提示"该天赋上限 N 级"；
3. 右键或长按节点：-1 级；若导致依赖它的下级天赋失效，自动级联减点并提示；
4. 切换专精：保留各专精已点方案，不互相覆盖；
5. 点「分享」：URL hash 更新为编码方案，复制后发给别人可原样还原。

**页面元素**：

| 元素 | 类型 | 说明 | 校验规则 |
|------|------|------|---------|
| 职业选择 | 卡片栅格 | 9 职业，显示该职业数据完整度 | 无数据职业仍可见，标"待补" |
| 专精切换 | Tab | 3 专精 | 必选其一 |
| 天赋节点 | 可点击方块 | 图标位 + 名称 + `已点/上限` | 前置未满足时置灰不可点 |
| 点数统计 | 文本 | 各系已投点数 + 总点数 | 实时刷新 |
| 重置 | 按钮 | 清空当前专精方案 | 二次确认 |
| 复制方案 | 按钮 | 输出文本（含中英名） | 无内容时禁用 |
| 数据来源 | 折叠区 | 该树来源类型、URL、核对日期 | 必填，缺失即构建失败 |

**异常处理**：
- 数据分片加载失败：显示重试按钮与本地缓存兜底，不白屏；
- hash 方案与当前数据版本不匹配：提示"方案基于旧版数据，已按可识别部分还原"，丢弃无法识别的节点；
- 节点缺中文名：显示英文名并标 L1 徽标，**不自动翻译**；
- 移动端长按误触：减点改为显式"减点"按钮 + 长按双通道；
- localStorage 不可用（隐私模式）：降级为仅内存态，分享链接仍可用。

**埋点需求**：见第八章（MVP 仅本地计数，不上传）。

**验收标准**：
- [ ] 从首页到某专精天赋树，点击次数 ≤ 3；
- [ ] 猎人、德鲁伊的天赋节点 **100% 有官方中文名**（来源 `official_cn`），其余职业允许英文 + L1 徽标；
- [ ] 加点/减点/级联减点/前置校验四类操作在 375px 宽与 1440px 宽下均可完成；
- [ ] 分享链接在无痕窗口打开可还原同一方案，误差为 0；
- [ ] 首屏 JS+CSS+首页数据合计 ≤ 300 KB（gzip 后），移动端首屏渲染 ≤ 2 s（本地服务实测）；
- [ ] 任一节点被点击后，界面无需整页刷新即更新点数（DOM 局部更新）。

**功能名称**：数据溯源与覆盖率卡口（P0）

**需求描述**：每条对外展示的数据必须能回答"你从哪知道的、什么时候核的"。

**页面元素**：

| 元素 | 类型 | 说明 | 校验规则 |
|------|------|------|---------|
| 来源类型 | 枚举 | official_cn / official_en / media_cn / fan_db / video / open_data | 必填 |
| 来源 URL | 链接 | 可点击跳转 | 必填且需为 http(s) |
| 核对日期 | 日期 | `YYYY-MM-DD` | verified 状态必填 |
| 完整度徽标 | 标签 | L0/L1/L2/L3 | 由状态推导，不可手填 |

**异常处理**：
- 状态为 `verified` 但来源不含官方类型 → 构建失败并指出条目 id；
- 核对日期早于该数据源最近变更日 → 覆盖率报告里列为"疑似过期"。

**验收标准**：
- [ ] 站点任意一条展示数据，都能在 2 次点击内看到它的来源与核对日期；
- [ ] `tools/build-data.js` 对"verified 但无官方来源"的样例数据返回非 0 退出码；
- [ ] 覆盖率报告输出每个模块的 L0-L3 计数，与人工抽查结果一致。

### 6.4 数据契约（站点与小程序共用）

```jsonc
// data/talents/{class}/{spec}.json
{
  "classId": "string，如 hunter",
  "classNameCn": "string", "classNameEn": "string",
  "specId": "string，如 survival", "specNameCn": "string", "specNameEn": "string",
  "dataVersion": "string，如 forever-beta-1.60.1",
  "rules": { "totalPoints": "number", "tierUnlockCost": "number[]，每层解锁所需点数", "specGate": "number" },
  "trees": [{
    "treeId": "string", "nameCn": "string", "nameEn": "string",
    "nodes": [{
      "id": "string，全站唯一",
      "tier": "number，从 0 起", "column": "number，从 0 起",
      "maxRanks": "number",
      "nameCn": "string|null，null 表示无权威中文名，禁止机翻",
      "nameEn": "string",
      "iconKey": "string|null，指向本地图标，不允许外链",
      "descCn": "string|null", "descEn": "string|null",
      "requires": "string[]，前置节点 id",
      "grantsSpell": "string|null，学到的技能 id",
      "level": "string，L0|L1|L2|L3",
      "provenance": [{ "type": "string", "url": "string", "note": "string", "checkedAt": "string|null" }]
    }]
  }]
}
```

```jsonc
// data/glossary.json —— 中英术语速查，与小程序共用
{ "items": [{ "id": "string", "cn": "string", "en": "string|null",
  "kind": "string，skill|talent|item|dungeon|boss|system|zone",
  "classId": "string|null", "specId": "string|null",
  "level": "string", "provenance": "同上数组" }] }
```

```jsonc
// data/dungeons/{id}.json —— 副本手册
{ "id": "string", "nameCn": "string|null", "nameEn": "string",
  "kind": "string，new|classic|raid", "levelRange": "string|null",
  "bosses": [{ "orderNo": "number", "nameCn": "string|null", "nameEn": "string|null",
    "abilities": [{ "name": "string", "kind": "string，读条|瞬发|被动|召唤",
      "playerAction": "string，写可验证动作，不写精确数值" }],
    "drops": [{ "nameCn": "string|null", "itemType": "string", "how": "string" }] }],
  "route": [{ "stepNo": "number", "area": "string", "action": "string", "tip": "string" }],
  "level": "string", "provenance": "数组，同上" }
```

**三条硬规则（写进构建卡口）**：
1. `level=L0` 必须至少有一条 `type` 以 `official` 开头的来源；
2. 掉落字段**不允许出现百分比数值**，正则拦 `%`；
3. 所有 `iconKey` 必须指向仓库内文件，出现 `http` 即失败。

## 七、非功能需求

- **性能**：首屏资源 ≤ 300 KB（gzip）；天赋树渲染 60 节点内无明显卡顿；数据按职业/专精分片，不进首页包。
- **安全与合规**：站名与页面不出现"魔兽 / 魔兽世界 / WoW / 暴雪"作为名称主体；页脚固定声明"非官方粉丝资料站，与暴雪娱乐及网易无关"；不展示任何用户内容（无评论、无投稿）；不抓取粉丝站数据库，人工核对后自己重写。
- **兼容性**：iOS Safari 14+、Android WebView（微信内置浏览器）、Chrome/Edge 最近两版；375px 到 1920px 自适应。
- **可维护**：数据与代码分离，改数据不碰代码；构建脚本可在无网络环境跑。
- **技术栈约束**：原生 HTML + CSS + JS，不引 React/Vue/Tailwind/动画库；Python 侧脚本兼容 3.9（禁 `match`、`X|Y` 标注）；JS 避免 `?.` 与 `??`。

## 八、埋点

MVP **不接任何上报通道**（纯静态、无后端、且个人主体小程序侧另有统计）。只预留本地计数，用于自己判断功能有没有人用。

| 参数名 | 参数说明 | 参数值 |
|--------|---------|--------|
| `evt_page_view` | 页面访问 | 页面 id |
| `evt_talent_alloc` | 天赋加点次数 | 职业、专精、累计次数 |
| `evt_share_copy` | 复制分享链接 | 职业、专精 |
| `evt_search_hit` | 搜索命中/未命中 | 关键词长度、结果数 |

| 指标名 | 说明 | 计算方式 |
|--------|------|---------|
| 北极星达成率 | 3 次点击内到达天赋树 | 首页→职业→专精 路径占比，目标 ≥ 70% |
| 搜索无结果率 | 数据缺口的直接信号 | 无结果次数 / 搜索次数，目标 ≤ 15% |
| 分享使用率 | 内容是否有传播价值 | `evt_share_copy` UV / 天赋页 UV，目标 ≥ 5% |

### 明确不做

不做角色查询、不做 DPS/评分排行、不做评论区与投稿、不做付费、不做需要登录的功能、不把粉丝站数据库整库导入、不做游戏内插件。

### 风险与对策

| 风险 | 对策 |
|------|------|
| 天赋树结构与数值在正式版改动 | 数据带 `dataVersion`，页面顶部显示"基于测试服 X 月 X 日数据"，上线后整批重核 |
| 中文侧被指侵权 | 站名与素材避开商标词；数据自采自录并留溯源；页脚非官方声明 |
| 数据不全被玩家认为"假资料站" | 完整度徽标 + 覆盖率页公开化，宁可显示"待实测"也不编造 |
