  不是手写的。所以新页上线时给那条「本站更新」补上 `职业` 这个 tag，导航角标就会自己出现；
  别在 `app.js` 里硬写。（`app.js` 第 275 行那句"标签对不上导航项名字就不画"是硬规则。）
- 改动点：`src/js/app.js` 的 `NAV` 表 + `app/src/lib/nav.js`（新站那份），两处必须同步，
  否则 `tools/app-parity.py --strict` 会报导航差异。
- 顶栏宽度：导航 17 项已经在 1180px 里排满一行，加项要重测 `--hd-h` 与换行断言
  （`site-check.py` 有"入口排在一行内 / 带子 ≤56px"这条）。

## 二、职业页 `classes.html` 要做成什么样

**版式照稿子**（`docs/DESIGN-DOUBAO-2026-10-12.md` 第 3.2 节，逐块几何都在里面）：

1. 页首图带（300px）：kicker `CLASS · WARRIOR`、大标题中文职业名 + 英文原名（英文用等宽/Georgia 且吃**职业色**）、
   右侧一枚 158px 的职业立绘框（我们已有 `src/img/art/classes/<职业>.webp` 九张，直接用）。
2. 三系专精：三张卡，当前选中那张吃金边 + 选中底（`.plate` + `--elev`），卡片上是系名与节点数。
   **系名用官方定名，另一个叫法走红框悬停**（`talents/*.json` 的 `nameAlt`，与天赋页同一套符号）。
3. 两栏：左"这一职业有什么"（键值行），右"技能变化"列表（新增 / 改动 / 移除 / 未变四态 + 官方中文名）。
4. 底部三个入口：天赋计算器 / 技能书 / 玩法问答（稿子这里是"生成分享链接"那种要账号的按钮，不做）。

**内容必须从我们自己的数据现取，一条都不许写死**：

| 槽位 | 数据来源 | 注意 |
| --- | --- | --- |
| 职业名 / 英文原名 / 职业色 | `src/data/classes.json` | 英文原名不全，缺的就不显示，别机翻 |
| 三系与节点数 | `src/data/talents/<职业>.json`（`trees[].nameCn` / `nameAlt` / 节点计数） | 层级点数门槛仍未核实，不做"第几层需几点"的暗示 |
| 技能四态与官方中文整句 | `src/data/abilities.json`（按职业过滤） | 只有官方公告整句里出现的名字才收 |
| 改动计数 | `src/data/changes.json` 按职业聚合（`scale.json` 已有 `changesTalents` 等全站数） | 只列名称与类别，**不列前后对照句子** |
| 可选种族 / 阵营 | `src/data/races.json` 的职业矩阵 | 稿子那行"人类 · 矮人 · 暗夜 …"是硬编码简称，我们按 `races.json` 的正式中文名渲染 |

**稿子里这一页不能照抄的东西**（`docs/DESIGN-DOUBAO-2026-10-12.md` 第四节有全表）：
职业概览六行（战斗定位 / 核心资源 / 护甲类型 / 可用武器 / 可用种族 / 团队职责）**整块是写死的字面量**，
其中"怒气（攻击与受击产生）"这类是常识描述、不是我们从客户端或官方稿核出来的——
要么找到来源并标 L0/L1/L2，要么这一行就不显示，**不许把稿子的描述句当数据搬进来**。
"悬停查看完整法术说明"稿子里根本没有实现，我们做的话 tooltip 里只放名称与归属，不放攻略文案。

**参考页**：<https://jjwow.cn/spellbook.html> —— 用户指定参考它的**信息组织方式**（按职业 → 按等级段 → 法术列表）。
红线照旧：只取它的事实性标识符（名称、等级、ID），**不复制它的描述文案与攻略正文**；
它的截图/图片一律不搬。取数前先确认这个站能不能访问、是不是客户端渲染。
