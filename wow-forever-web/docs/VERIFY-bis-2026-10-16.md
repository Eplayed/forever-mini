本轮角色：wow-data（采与合并）+ wow-dev（卡口与页面）+ wow-ui（呈现）
｜输入：站主给的参考站 `https://wowforever.wclbox.com/peizhuang`、站主三个决定（走 C / 人物用 2D 纸娃娃 / 导航单独一组）
｜产出：见文末清单 ｜状态：**已定**（门禁全绿 + 桌面与 375 实拍），模拟器那一层**未做**（缺口见第五节）

## 一、站主拍板改了什么规则

仓库根 `AGENTS.md` 第五节"第三方站取数边界"加了一条例外（原文在文件里，这里只记要点）：
配装线允许取第三方站的 **BiS 名单与同部位备选顺序**，只到"哪件装备在哪个部位、按什么顺序"这一层；
该页写的"为什么这件好"、属性优先级、循环建议、任何成段中文说明一律不取；
每条带 url + 抓取日期；页面固定写"本站整理、不是官方结论、没做模拟计算"；
整条线按 **L1** 留档，不许因为"看起来合理"升 L0。
同时写明仍然不做：战斗日志、DPS 或强度评分、宏与循环提示。

## 二、采到的结构与实测口径

参考站那三层（总览 / 职业页 / 配装模拟器）里，本轮只做了前两层。

| 事实 | 实测值 |
| --- | --- |
| 套数 | 38 套（9 个职业；职业基础页 = 该职业第一套，带 spec 的是其余各套） |
| 等级段 | 全部 30 级（另有 `/peizhuang/level-20` 一档，本轮没采） |
| 纸娃娃 | 1,265 格（每套 16–17 格，含两枚戒指与两个饰品） |
| 同部位备选 | 6,626 行 |
| 用到的装备 | 去重 175 件 |
| 阵营 | 每套两个版本。**SSR 只给联盟那一版**，部落版要点 `.pz-faction` 的按钮才换数据——所以抓取必须开真浏览器，curl 拿不到部落 |
| 战士 PvE 两阵营差异 | 16 格里 4 件不同（手 / 一枚戒指 / 一个饰品 / 主手） |

**部落那一版是点出来的，不是抓出来的**：`tools/scrape-wclbox-bis.py` 每页读一次联盟、点一次按钮再读一次部落，
页间 0.6 秒，38 页单线程。试过 URL 变体（`/warrior/pve/horde`、`/warrior/horde`）全是 404，
也试过 `/_shuju/<发布号>/peizhuang.json` 这类静态接口，同样 404——这一层没有免浏览器的路子。

## 三、落盘前删掉了什么（这是本轮最容易出事的地方）

参考站"来源"那一栏的原文长这样：

> 从奥特兰克花岗岩里拿到，希尔斯布莱德丘陵开启铁质宝箱世界掉落，12 张掉落表里都有，也可以去拍卖行找**按本页权重比第二件高 20%**
> 群体打击者9-60，诺莫瑞根，**掉率约 0.3%**

一句话里同时有三样红线东西：它写的描述文案、它的权重结论、**掉率百分比**。
所以抓取阶段就把整段中文丢掉，只把链接拆成 `{kind, id}`（配方专业 / 任务号 / 副本 / 物品），
数字只抠括号里那个技能点（`锻造（150）` → `skill: 150`）。落盘后再验一遍：
快照与成品里 `掉率` `权重` `拾取后绑定` `拍卖行` `使用：` `使你的` **全部 0 处**。
`build-data.js` 里另钉了一道：整份 `bis.json` 序列化后出现 `\d+%` 或"掉率"字样直接构建失败，防合并脚本改回去。

## 四、数据只存顺序，数值全回本站名录查

`bis.json` 每套只有：职业 / 专精 / 模式 / 等级段 / 地址 / 抓取日 / 纸娃娃格 / 各部位备选 ID 顺序 /
附魔（物品 + 贴哪个部位 + 技能点）/ 消耗品 / 来源的结构化指向。
**名字、品质、装等、需要等级、属性行、图标一律不存**，页面运行时回 `items.json` 与 `items-detail.json` 现查。

这条选择带来一个白捡的核对机会：把它的名单跟我们自己的名录对一遍——

| 核对项 | 结果 |
| --- | --- |
| 名单里的物品 ID 是否都在我们名录里 | 175 件首选 + 全部备选，**缺 0 件** |
| 中文名是否一致 | 1,265 格里 **分歧 0 处**（两边都是客户端解包出来的名字，本来就同源） |
| 它把某件装备列的部位 vs 我们库里这件装备自己的 `slot` | **分歧 0 处**（要先解决两套词表：它叫"项链 / 戒指 / 双手武器"，我们叫"颈部 / 手指 / 双手"；投掷与弹药进远程槽也算对） |

第三项原本报 912 处分歧，逐条看全是词表不同名与单手武器的主副手之分，不是数据错，
补了 `SLOT_OK` 对照表后归零。**这个归零本身就是这条名单可信度的一次实测**——
它列的每件装备，部位跟我们从客户端读出来的一致。

## 五、界面上做了什么、没做什么

做了：2D 纸娃娃（16 格，图标 + 部位 + 装备名 + 装等，点任意一格换右侧备选表）、
职业 9 格 / 模式 / 阵营三排筛选、同部位备选表（图标 / 装备 / 装等 / 需要等级 / 从哪儿拿 + 属性行摘要）、
附魔与消耗品两张表、页顶那句红线口径。桌面与 375 都不横溢，375 下点击目标全部 ≥44px。

**没做，也不是偷懒**：
- **配装模拟器（换装后属性即时重算）**。缺的不是规则许可，是数据：
  ① 我们没有任何职业 30 级的**基础属性表**（力量/敏捷/智力/精神/耐力起点值）；
  ② 没有属性换算规则（攻击强度怎么算、暴击等级每 1% 要多少点、护甲减伤公式）；
  ③ 参考站那页自己写着"使用 30 级的职业与种族基础属性"——那套基础值我们一份都没有。
  这三样任何一样编出来就是假数据。要做只能先解决来源（客户端导出或官方公布），列进开放项。
- **20 级那一档**没采（参考站有 `/peizhuang/level-20`）。
- **部落版的备选表**采了，但界面上切阵营时只换纸娃娃与备选，没做"两阵营并排对比"。
- 配装页**没进全站搜索**（search.json 里没有 bis 这一类），首页也还没给这一页卡片入口——目前只有导航那一格。

## 七、要你定的三件事

1. **模拟器那一层要不要立项**。要做，先得有职业基础属性与换算规则——你手上那台装客户端的机器能不能导出这两样？
   导不出就只能停在"换装看图标与装等，不算属性"。
2. **20 级那一档要不要**（参考站有，本轮只做了 30 级）。
3. **配装页要不要进全站搜索与首页卡片**。现在它只在导航里，搜索"野人铁盔"不会指向这一页。

## 八、10-17 第二轮：布局照参考站对齐 + 补图标（站主实拍后指出三处）

站主看完页面提了三件事：布局没和参考站统一、联盟/部落没有徽记、职业条没有图标。三条都改了。

| 改了什么 | 依据 |
| --- | --- |
| 职业条从"纯文字按钮"改成**图标 + 名字 + 本职业套数**，横排成一条 | 图标用本地 `img/icons/class_*.jpg`（与排行页同一套，`classes.json` 的 `iconKey`），不新素材 |
| 联盟 / 部落按钮**加阵营徽记** | 用已有的 `art.json → factions`，文件就是 `src/img/art/factions/{alliance,horde}.png`（10-09 那批转存的原画，带 manifest），没有新增外链 |
| 纸娃娃从"三列小方格"改成**左列 6 格 / 中间一块 / 右列 8 格，武器与远程压在中间下面** | 参考站那页实测 `.pz-doll` 是 `grid-template-columns: 471px 360px 471px` 的三栏，中间放 3D 人物。我们没有 3D，中间铺**职业原画**（`art.json → classes`），不拿别的图冒充"穿在身上的样子" |
| 装备图标按品质描边（绿/蓝/紫/金） | 与参考站同一语法，颜色用 `tokens.css` 里已有的品质色 |
| 新增「这套装备给的属性」一排：力量 / 敏捷 / 耐力 / 智力 / 精神 / 护甲 | **纯把这套装备的属性行相加**，数字来自我们自己的 `items-detail.json`，门禁那边独立解析同一份数据比一遍（实测战士 PvE 联盟：79 力量 / 75 敏捷 / 59 耐力 / 16 智力 / 4 精神 / 1171 护甲） |

属性那排写清了口径："只把上面这些装备的属性行相加：不含职业与种族的基础值，也不含附魔和套装效果"。
为什么不含基础值——见下一节，那是唯一还缺的一块。

断言从 15 条加到 20 条（`--only bis` **20/20**）：职业条九格且每格图标真渲染出来（查 `naturalWidth`，坏图即红）、
两枚徽记在、三栏部位归属等于按数据算出来的 6/8/2、中间确有背景图、
**属性合计等于门禁独立解析的结果**。
过程中被自己钉的一条抓到：三栏布局下 DOM 顺序不再等于数据顺序，
原来那条"名字逐位比对"红了——改成比"部位+序号 → 装备名"的对应关系，不是比列表顺序。

## 九、模拟器到底是怎么做的（站主问的，实测扒到底）

**它不是战斗模拟器，是一张静态表加一遍加法。** 页面 `/peizhuang-moni/warrior` 打开时拉：

```
/_shuju/<发布号>/gongneng/peizhuang-moni-warrior.json     211 KB
```

里面五块东西：

| 键 | 内容 | 我们有没有 |
| --- | --- | --- |
| `items`（454 件） | 每件带 `stats: [[属性号, 数值], …]`、`armor`、`slots`、`enchant`、`ilvl`、`icon` | **有**（我们的 `items-detail.st` 是同一批数的中文句子形态，175 件首选全覆盖） |
| `enchants`（108 条） | 每条带 `stats: [[7,1]]`、`armor`、`slots`、`profession`、技能点数 | **没有结构化的**（只有参考站那句"力量 +5"的文字，按红线没落盘） |
| `sheet` | **职业 + 种族的 30 级基础属性**：人类战士 = 力量 62 / 敏捷 44 / 耐力 57 / 智力 24 / 精神 30，生命 374 | **没有，这是唯一缺的一块** |
| `starts` | 三套起始方案（PvE/PvP/坦克）× 两阵营的部位→物品映射 | 有（就是本轮 bis.json） |
| `statNames` | 38 个属性号对应的中文名 | 不需要 |

换装时它做的就一件事：`基础值 + Σ(身上每件 .stats) + Σ(附魔 .stats)`，然后重画那张属性面板。
没有战斗模型、没有 DPS、没有权重——**它页面上那句"不含增益和天赋"就是这个意思**。

顺带一个发现：它的 `items` 装等跟我们库里 **454 件里有 37 件差 1–3 点**（例：银星 我们 37 / 它 35，
十字军斗篷 我们 33 / 它 35）。这属于两源分歧，按红线要两个都留，本轮没动我们的数。

### 开源有没有现成的

有，但要分清两类：

- **能借的是数据管线，不是成品**：[WoWSims](https://github.com/wowsims) 这个 org 下面 `classic` / `sod` / `tbc` / `wotlk` / `cata` 五个仓库全是 **MIT**，
  另有 `exporter`（游戏内插件，把客户端 DB2 导出来）与 `DB2ToSqliteTool`。
  也就是说"基础属性表 + 每件装备的结构化属性"这套数据，业界的做法就是**从客户端导**，
  参考站那份 JSON 也是这么来的。这条路对我们开放——站主那台装了客户端的机器就能跑导出。
- **不要碰的是战斗模拟**：[ClassicSim](https://gitcode.com/gh_mirrors/cl/ClassicSim) 与
  [SimulationCraft](https://www.simulationcraft.org/) 是 C++ 事件驱动 DPS 模拟器，
  输出的是秒伤与属性权重——正是红线里"不做 DPS 或强度评分"那一条，不接。
- **3D 人物**：搜到的都是需要客户端模型文件的查看器（如 GPL 的 WMVx 这类），
  素材与授权两关都过不去，维持 2D 纸娃娃。

### 所以要补齐属性面板，只差一步

`sheet` 那一块（职业 + 种族的基础属性）。三个选项，等站主定：

1. **只加"装备给的"这一排**（本轮已经做了）——不碰基础值，零新数据，最保守。
2. **从参考站那份 JSON 取基础属性表**——要再开一次红线例外（现在的例外条款只放开"名单与顺序"，
   没放开属性数值）。取到之后就能做真正的换装即时重算。
3. **自己从客户端导**（照 WoWSims 那条路）——最干净，数据归我们所有、能标 L0，
   但要站主在那台 Windows 上跑一次导出插件。

我的建议是 3，退一步是 2；1 已经落地，不阻塞。
