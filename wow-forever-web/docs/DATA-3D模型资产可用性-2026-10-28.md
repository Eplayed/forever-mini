## WCLBox 猎人页公开实现核对（2026-10-28）

页面 `https://wowforever.wclbox.com/peizhuang/hunter` 首屏是 `/moxing/bis/dffe8e48d474.webp` 海报；点击“旋转 3D 模型”后，公开的 `Features-BA7wCfkG.js` 将同一路径扩展名换成 `.glb`，懒加载 `GearModel-DoWQ15Sf.js`。后者用 three.js 的 GLTFLoader + OrbitControls 显示模型，没有浏览器逐件装备或读取客户端的逻辑。这证明该页采用**预制整人 GLB + 海报回退**，不证明其后台如何从物品 ID 制作模型。

公开的猎人 GLB 通过只读 HTTP 核对：247,136 B，glTF 2.0；`asset.generator = "xinshou client_figure.py"`，1 个 mesh / 8 个材质图元 / 8 张内嵌 WebP 贴图，约 7,255 三角形；无 skin、动画，也没有逐件物品 ID 元数据。`generator` 字段提示有离线生成脚本，但脚本本身未公开，不能据此断言它用了哪个客户端版本、哪些补源、或每件装备都严格对应页面 ID。与我们的 12.6 MB wow.export 部分 GLB 相比，它是已经合并和优化的静态展示资产。

**对本地客户端的判断**：第五包不能推出“客户端数据不全导致做不了”。E4 清单表明若按本地已安装变体取，绝大多数模型/贴图有本地字节；六个猎人物品卡在 wow.export 的 `ItemSparse` 物品列表入口，但各有外观 ID，尚未证明对应外观资源不存在。头盔落脚边是导出附件变换错误。真正的资源缺口只可逐 FDID 证实；不能以“工具搜不到”代替。若目标只是 WCLBox 式静态整人旋转图，优先打通外观 ID → 资源 → 正确拼装 → 优化 GLB 的离线流水线。
