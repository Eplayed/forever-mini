## 身体装备的关键纠偏

第九包 README §4(a) 用 `ItemDisplayInfo.ModelResourcesID=0`、`GeosetGroup=0` 和没有 `collection_model_renderers` 推出“胸、腿、腰、脚、手没有外观数据，只会是默认衣服”，**这个推论不成立**。它们没有独立附件 `.m2`，不等于没有贴图或角色主体 geoset 外观。第六包 `shoulder-2278/offline-chain.csv` 已对猎人胸甲 **7374** 给出反例：IDI 8071 的 `ModelResourcesID=[0,0]`、`GeosetGroup` 全 0，同时有 `ItemDisplayInfoMaterialRes` section 0/3/4 和六个 TextureComponent FDID，且四个本轮样本物品链路资源全本地可读。第六包同表还记录靴子 **20093** 的角色 M2 靴 geoset 切换及贴图。第四包胸甲 2870 与 250518 A/B 的两份整人 GLB，我独立抽出六张内嵌图复核：只有身体复合贴图第 0 张变化（1,371,456 B / 1,388,717 B，SHA 前缀 `c8cc9d30` / `388d1455`），证明此工具确有“装备贴图烘到人物 M2”的通路。因此当前证据既不能宣称猎人全套身体外观已正确，也不能把 76 份整批判成“客户端无数据”。

## 两个口径决定

1. **76 份批量暂缓，先做身体外观最小 A/B。** 同一人类男、No Animation、同一相机与皮肤，先把猎人胸甲 7374 空槽/穿上两态各导一份 GLB；比对 GLB 内嵌身体复合贴图哈希与胸部像素、记录 section 0/3/4 的 FDID。再按同法逐个切换猎人其他身体可见槽（背 13108、腕 6410、手 7358、腰 252521、腿 9624、脚 20093），逐槽给 `TEXTURE_CHANGED` / `GEOSET_CHANGED` / `NO_VISIBLE_CHANGE` / `BLOCKED` 与证据。若某槽没变化，先查材料/角色贴图链与导出烘焙，不据 `.m2` 数量判客户端缺失。确认可见槽链路后再批量，并在每 job 的交付里分列附件模型、角色贴图、角色 geoset 的证据。
2. `NOT_RENDERED_BY_GAME` 只按**静态角色预览**口径用于项链、戒指、饰品、圣物这四类槽；它们仍留在完整 `doll`，不进 `visualDoll`。猎人主手 2280 因本站选“手持远程”而不在这份 GLB 展示，理由应标 `NOT_DISPLAYED_IN_THIS_EXPORT`，不是“游戏不会画”。身体装备即使没有独立 `.m2`，也不得归入 `NOT_RENDERED_BY_GAME`。
