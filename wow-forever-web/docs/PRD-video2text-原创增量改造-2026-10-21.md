# video2text：参考素材做头条图文攻略的增量改造与 Qoder 任务书

日期：2026-10-21　主角色：wow-pm　状态：**已定（需求与验收口径）／待 Qoder 实施／待 Codex 复验**。

## 背景和目标

站主会参考别人的视频、再制作 Forever 项目的图文攻略。当前 video2text 已有排产任务与素材快照（`src/plan_tasks.py`）、事实风险闸（`src/fact_gate.py`）、配图判帧及最终 `publishable` 状态（`src/ai_poster.py`）。近期 83 号图文的四关修复已有交接，不应重做。缺的是一条**编辑证据链**：这篇解决哪个玩家问题、我们独立补了什么、结论怎样核查、借来的文字和画面能否使用、是否只应标为整理。目标是让操作者在发布前看见这些缺口，并保留可回查的记录；工具不能自动证明“100%原创”。

输入：本站 [`PLAN-original-guide-2026-10-21.md`](PLAN-original-guide-2026-10-21.md)、[`PRD-图文攻略四关验收-2026-10-21.md`](PRD-图文攻略四关验收-2026-10-21.md)，以及 video2text `output/角色交接/2026-10-21-头条-dev-83四关交付-2.md`。头条[文章原创规则](https://baike.toutiao.com/detail/242/243/0?enter_from=left_navigation)说明改词改序、拼接整合和未授权改编等不能仅靠加工取得原创声明资格；站主最终须按实际成品与当时平台规则判断。

## 改造完成后的实际工作流程（按操作者顺序）

1. **从素材库发现线索。** 浏览订阅视频与转写，圈出值得回答的玩家疑问；这一步只把视频记为候选，不因它热门就直接生成攻略。没有正文的素材仍不能当作事实输入。
2. **确定一个玩家问题和本篇增量。** 写清读者要完成什么、原素材留下什么空白、我们准备通过查询/操作/解释补上什么。若只是转述原视频，应在此决定走“有出处的整理”或换题，不假装亲测。
3. **选定素材并核查结论。** 从候选中确定本篇采用的素材快照，再对关键名称、步骤、数值和适用条件逐条找原始来源或真实操作记录；标清“外部说法／本站查询／游戏内实测／待核”。查不到的结论删掉、降级表述或暂停，不能靠 AI 补写。
4. **形成可编辑的文字攻略稿。** 由整理稿进入现有 `/api/poster/plan` 文案计划，人工审标题、每页论点、步骤、发布配文和来源说明。**这是内容质量的主卡口，必须在正式生成攻略页前通过**：能回答问题、可照着操作、关键事实有凭据、贡献说得清、待核没有写成确定结论。未通过就退回步骤 2–4 修改文字，不用反复排图来掩盖内容问题。
5. **为每页挑有解释作用的素材关键帧。** 沿用现有抽帧→裁后期层→判帧→按编号绑定的“攻略页”链；看这张帧能帮助读者辨认什么，以及它不能证明什么。无合适帧就留纯文字页。记录外部帧的来源和使用依据；画面洁净与能否使用分开审核。关键帧与文案不要求逐字对应，也不能让泛用画面暗示具体效果已实测。
6. **免费预览，再正式生成。** 在现有预览中检查分页、文字可读性、关键内容是否被裁掉或遮挡，以及画面是否真正帮助理解。预览发现论点/步骤错误，退回步骤 4；选帧不当，退回步骤 5。通过后才生成正式攻略页；这条攻略页使用视频真实帧，不调用模型重画插图。
7. **核对最终成品并人工发布。** 看最终每页、配文、事实闸、未判帧与素材使用依据。生成成功不等于可发布；缺项保留草稿状态。操作者再逐篇判断是整理还是有独立贡献，并按平台当时规则决定是否声明原创/首发，工具不代判、不自动发布。发布后回填实际表现，供下一轮选题复盘。

**退回规则：** 内容问题回到文字稿或查证；关键帧的解释作用/使用依据问题回到选帧；版式问题在预览调整。不要把三种问题统称为“出图质量”并靠重新生成碰运气。

## 用户场景和四步改动

**仅做 `toutiao + guide` 的一条样稿闭环。** 从排产选定素材到成品预览，保留“研究输入”和“我们的交付”两层；允许继续做有出处的整理稿，但不能把它包装成亲测或平台原创。

1. **选题卡补三项编辑输入。** 在现有排产任务或其紧邻的单篇记录中，录入“玩家要解决的问题”“本篇新增的可指认内容”“新增内容的证据/操作记录”。沿用现有 `video_ids`、`sources` 快照；每条外部材料标明用途是选题线索、事实来源还是被引用的表达/画面。空项可以保存草稿，但在成品预览明确显示“独立贡献未说明”。已开工版本不得被后来修改的选题卡悄悄覆盖；Qoder 应复用现有版本/快照语义，避免另造排产系统。
2. **把可核结论与贡献挂钩。** 一条结论至少能回看“结论文字—证据链接/本地操作记录—核验者与日期—状态（已核/待核）”。从素材口播转写而来、未独立核查的内容保持“参考转述”；本站页面查询不能写成游戏内实测。接入现有 `fact_gate` 与成品风险显示，避免复制一套数字事实闸。人手填“我测过”但没有可回查记录，仍按待核；不要求每篇多源或虚构跑分。
3. **核对关键帧的解释作用与使用依据。** 当前“攻略页”从素材视频的 `frame_pool` 选真实帧，`plan.pages[].photos` 引用帧编号，`poster_typeset.typeset_guide()` 将帧与文字排进页面；本单沿用这条链，不以模型重画插图取代它。逐页说明关键帧帮助读者看清了什么（操作位置、界面状态、场景或对象），以及它**不能证明什么**。画面可以用于辅助理解，不要求与文字逐字对应；但不能拿一个泛用场景图暗示具体选项、数值或效果已被实测。没有能提供帮助的可用帧时允许纯文字页，不强配图。对进入最终稿的外部视频帧与文字，另记来源 URL/作者、使用方式、授权或使用依据及审查状态；缺依据时列出具体对象，最终“待发/可发布”状态保持为否。`frame_pool` 的“无字幕/水印”只处理画面洁净，不能替代解释作用或使用依据审核。加出处不等于取得许可。
4. **预览增加人工判断页/区块。** 汇总前三步及现有事实闸、关键帧解释作用和使用依据，明确显示“整理转述 / 有独立贡献待人工评估 / 证据不足”之类编辑状态；此状态是内部提示，**不是平台原创资格认证**。不得自动勾选或输出“100%原创”“已获原创/首发”标记；首发还取决于发布时间与跨平台情况，本单不判。最终发布仍由人处理。对 83 号旧样稿应显示：来源与待核项可回看，尚无亲测证据，不能因重排图文变成原创攻略。

## 范围与边界

- 只改 video2text 的头条攻略生产/预览流程及必要的持久化和测试；不改 Forever 资料站、小程序、游戏数据，不发布内容，不自动打平台标签。
- 保留现有四关成果：事实 `force` 放行须逐条证据、`photos_unjudged` 提示、帧判定失败关闭、最终 `publishable` 判据。新编辑层应与其叠加，不把已有结果推翻。
- 不引入“原创度百分比”、AI 洗稿改写、自动授权判断、以多素材数量当独立性证明，也不要求所有文章都做游戏内实测。
- 与事实可发布性区分：所有阻塞项合并影响待发状态；“可能有独立贡献”绝不自动升级为平台原创资格。历史成品和数据库迁移默认安全回退，旧记录缺新字段显示“未审”，不能默认通过。

## 可验证验收

1. **正向编辑流：** 在隔离测试库建一条 `toutiao/guide` 排产，选择素材，填写问题、独立贡献、可回查证据；从已判帧清单选一张确实帮助解释该页的素材关键帧，记录画面用途与使用依据。生成预览能逐项显示并在重新打开后保持，版本快照与整理稿关联不串篇。这里仍只显示“人工评估”，不自动宣告平台原创。
2. **反向流：** 单视频换词改写、多视频拼接、填“我实测”但无证据、借用视频帧清掉字幕却无使用依据、帧画面与论点有关但不足以证明文案所写效果、为纯文字也能讲清的页硬配泛用帧、旧记录字段缺失，各自有明确提示与非待发状态；人工补齐一项不得冲掉其他缺项。缺陷定位到具体字段、证据或图片。画面“能否帮助解释”属人工编辑判断，测试应验证人可标记不适用并阻止待发，不要求模型可靠地自动判语义。
3. **流程顺序：** UI 实操从素材库候选开始，确认玩家问题→选定素材→核查→审可编辑文字稿；未过内容卡口不进入正式攻略页。文字通过后才选帧、免费预览、正式生成和最终人工审查。反向实操证明在预览发现文字错误能回改文案，在关键帧审核发现不适用能撤帧或换帧，不被迫重跑整个选题。
4. **83 号样稿回归：** 用现有样稿和独立测试夹具复查，保留事实风险与判帧结果；仅凭已有转写和成图不能标成独立测评/平台原创。不得重生成或覆盖生产样稿充当测试。
5. **回归与证据：** Qoder 先跑最小定点测试及 UI 实操（独立临时服务、数据库、输出目录），提供选题卡、成品预览、缺项状态的真实截图或操作记录；再按 video2text `AGENTS.md` 跑全量图形卡口，记录实际命令、退出码、失败修复。涉及 Flask 重启遵守外仓共享工作区协作规则。只提交本单改动，不顺手清理他人未提交文件。
