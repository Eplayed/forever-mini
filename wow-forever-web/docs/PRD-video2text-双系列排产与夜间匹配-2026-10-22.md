S1 的 A1–D4 共 26 个**位置**；S2 是三个**章节模板**，由实际消息创建一篇或多篇稿件，不预置虚构公告。O1 的一则公告可以直接做资讯；O2/O3 必须关联前序事实或预测。章节和条目可显示“未匹配／有候选／已采用／整合稿中／待拆文案／看版面／待人工发布／已发布”及数量，但每种状态只由对应服务端事实计算；整理完成 `done` 不能冒充已发布。默认首页突出两个系列和当晚新增候选；历史排产任务仍可通过旧 ID 查看，不删除其采用素材和稿件。

## 3. 操作链与页面按钮

**从系列进入：** 打开 `#schedule` → 展开系列/章节/位置 → 看候选素材与来源、日期、内容摘要、Forever 归属依据 → 勾选一条或多条 → “采用到本篇” → 看采用清单并“生成/继续整合稿” → 先在 AI 海报 `①拆文案（内容审核）` 校对事实、步骤、条件、标题、配文 → `②看版面` 检查真实关键帧是否有助于解释/展示本页信息，允许无合适帧的纯文字页 → 导出人工待发布包 → 人工在头条发布 → 回工作台登记平台标题、发布日期、链接并勾“已发布”。勾选应可一次提交多条、可在生成前增删；候选与已采用明确分区。已采用集合有服务端快照，次日晚间新匹配只刷新候选，**不得替换已采用项或旧稿证据**。

**从素材库直接进入：** 在素材库选一条或多条素材 → “做图文攻略”或“做资讯整合” → 可选关联 S1/S2 的章节/位置；不关联也能创建稳定的独立任务 → 后续复用同一整合稿/海报/登记链。先创建独立稿再关联系列，应建立引用关系，不复制任务或把多篇并成一篇。官方公告也可从公告栏或素材库直接作为线索起稿，先核实是否真属 Forever；公告速读不得自动称为“亲测攻略”。同一素材可以成为多篇候选，但**每篇采用由人决定**，生成时只用本篇勾选的 ID，不偷偷加入未勾选的候选。

整合稿输出必须区分可核事实、第三方经验、本站分析/假设、待核项，给关键结论可回查的素材 ID、原始链接、时间/版本与来源片段。整理稿质量门沿用 `PRD-图文攻略模型换档验收与优化-2026-10-22.md`：未经核实的数值、效果和操作建议留在待核清单，不能在标题、行动建议或海报中变成确定句。图片是素材关键帧，用来更好解释或展示文字信息，**不是重新出图，也不要求逐字与文字一致**；原视频来源、帧用途与使用依据可回查。平台是否允许声明原创由人逐篇判断，不由模型或本流程保证。

## 4. 夜间匹配及“已发布”真相

默认每天 **22:00 Asia/Shanghai** 执行一次，时间可配置；页面显示开关、下次计划时间、上次成功/失败时间、候选增减与跳过数，并提供“现在匹配”手动按钮。复用现有工作台进程内定时器/锁模式即可：工作台关闭期间不运行；下次启动后若错过当晚计划，补**一次**，不要为每个错过的自然日连跑多轮。运行中重复触发、重启、接口重试按“日期 + 任务/位置 + 素材 ID”幂等，不产生重复候选；失败留记录并可重试。默认匹配是素材库的只读检索和可解释排序，不自动采集外站、不批量调用付费模型、不自动生成/出图/发布。

仅对**未发布**的系列位置和未发布的独立排产任务刷新候选。候选在每个位置按素材 ID 去重，列明匹配理由；排除其他服务器/资料片/游戏，来源只是 `blizzard` 或标题含“无限”均不足以判 Forever，正文不足以判断的标“待人工判定”，不自动采用。候选为零就显示零，不拿历史素材填位。已发布的条目不再参与夜间或手动重新匹配；新版变化需要另建“后续篇/复盘篇”，不能悄悄重开旧稿。发布过的素材是否可启发别的未发布篇，由人判断；**不把已发布稿的已采用集合复制为另一篇的采用集合**。

“已发布”必须是服务端可查、跨浏览器一致的事实：排产勾选应触发或绑定现有 `/api/ops/register` 发布登记，关联稳定 `slot_key` 与 `channel`，保存标题、日期、平台链接（无链接时明确记录待补原因），同时能从登记回显勾选；不得仅凭 `localStorage` 或生成任务的 `done` 判断。应兼容该接口 `slot_key` 现有长度/字符约束，S2 多篇与独立篇用不会碰撞的稳定短键。双击提交、刷新、重启不产生两条发布记录。已有浏览器里“已发布”但服务端无对应登记的历史勾选，展示“待核对旧勾选”，在用户核对/登记前保守跳过夜间匹配；不得静默清空或悄悄当成已正式登记。若服务端能查到已发布，任何浏览器都显示已勾并跳过匹配。撤销误登记要留变更记录、说明影响，不允许只取消前端勾选而服务端仍算已发。

## 5. 实施顺序与验收

1. **先统一身份与发布状态**：设计系列/章节/条目和独立稿的稳定键，读写服务端，接发布登记并处理旧本地勾选。确认不破坏现存 `plan_tasks` 版本与 `summary_id`。先做这步，夜间匹配才有可靠的“跳过已发”判据。
2. **再接两个起稿入口**：排产系列/章节/候选多选与素材库直接起稿，共用任务、整合稿和 AI 海报链；官方公告归属和 `guide`/`mix` 稿型正确。老题卡与老稿不迁删。
3. **最后加夜间匹配**：可配置时间、补跑/幂等/锁、成功失败记录、候选显示和手动重跑。低风险先用临时库与固定时钟测，不对真实素材库做收费或批量改写。
4. **端到端验收后交付**：头条单素材攻略、双素材攻略、多素材资讯、官方公告 O1、O1→O2→O3、素材库独立稿各走一遍；浏览器刷新与双浏览器发布状态一致；隔夜已发不再匹配、未发只新增候选且已采用/整合稿/海报不变；跨服假阳性、零候选、重复启动、失败重试及旧 `localStorage` 勾选均有反例。保存排产桌面/窄屏与海报入口截图，列出未验的真实人工发布步骤。

发布登记只证明“已人工发布”，不等于内容质量通过；发布前仍受原有整理稿质量门、拆文案内容审核、看版面与人工待发布包约束。Qoder 完工应停在 Codex 验收点，不直接在头条代发。
