**素材通道补完（M02-1）**

## 三、真跑出来的问题（先红，再改，再绿）

1. **素材台账被当成不可变对象**。第二次发素材时 `assets/index.json` 字节必然变（素材集变了），
   却被"同路径不许覆写"的守卫拦下 → rc=1、报"冲突 1"。这条守卫是对的，作用域错了：
   不可变的是图片对象，台账是可重导的清单。改成 `mutable` 标记 + 短缓存头。
   反例已进自测：素材集变小后台账必须能更新且只 PUT 1 个对象；同名图片字节不同仍要判冲突、PUT=0。
2. **Content-Type 比对写法错了**。JSON 的 MIME 带 `; charset=utf-8`，比对时只把远端值摘了后缀、
   本地值没摘 → 每次都对不上 → 台账每次重发一遍。两边都摘后缀再比。
3. **职业图标漏登记，线上 404，而清单报"缺登记 0 条"**。实拍时发现九宫格里职业图标全是自绘块。
   根因：`useIcon()` 只在法术行上调用，职业名单条目自己的 `iconKey` 没登记——
   "缺登记 0"只说明"问过的都在"，不说明"该问的都问了"。
   补 `useIcon(c.iconKey)`，并加**反向卡口**：扫全部产物里界面会拼的 `iconKey/art/portrait`，
   没登记就构建失败。红测：把那行注掉 → 9 条不合规、rc=1；恢复 → rc=0。
4. **门禁自己抄了会变的数**。`oss-release-test.js` 里写着"bundle 收 79 个文件""核对日期 latest === 2026-10-11"
   "界面拿得到核对日期 === 2026-10-11"——加了九片职业分片与一张掉落表之后，这些字面量把绿门禁变成假红。
   改成从批次构成现算（`2 + 副本×2 + 职业片 + 3`）、从逐文件 `facts.max` 现算、从指针 `factDates` 现算。
5. **对拍沙箱少拷一个文件**。导出层新读 `tools/copy-banned.json`，`reExportCompare()` 的临时目录里没这份，
   报错长成"重导出没有产出 oss-preview"。补拷，夹具 `freshFixture()` 同步补。
6. **反例改的是没被执行的那份文件**。`runBuild()` 默认起仓库里的工具，改夹具副本不生效 → 三条掉落反例 rc=0 蒙混过关。
   改成显式把夹具那份工具传进去，并给夹具补 `src/img` 符号链接（否则素材全"缺"，反例因错误的原因变红）。
7. **M01 的 A 组前提过期了**。那四条断言的前提是"真 bucket 的 beta 是空的"，beta 一有数据就全红。
   改成把取数地址指到一个必然 404 的前缀——"拿不到指针"这件事不该依赖线上还没发东西。
8. **模拟器上"等页面回调再回话"的 evaluate 会超时**。掉落页 onLoad 要同步拼 1,018 件物品，
   主线程忙时导航的 evaluate 拿不到回包（稳定复现）。改成发完导航在 Node 侧等，再单独查当前路由。
9. **禁词扫描扫到了样式名**。`class="todo"` 命中禁词表的 `\bTODO\b`。改成先剥标签与属性，只扫玩家看得见的文字。

- 零 UGC、不开虚拟支付、不开 web-view（来源网址＝复制到剪贴板）。

## 六、没验到的（要人工过一遍）

   本机开发者工具是关着域名校验跑的，`downloadFile合法域名` 目前是空的。
2. **真实点击**。所有交互都是调用页面自己的事件处理器 + 合成事件对象，

   职业九宫格、法术行展开、"换职业"、"全部职业"、"复制这条"、掉落来源行跳座、"看这座本"、复制、返回。
3. **断网两页的样子**。技能与掉落两页刻意没有主包快照，飞行模式下应看到
   "技能表要联网才能取" / "掉落反查表要联网才能取"两条红字提示，而不是空白页——这条只验了代码分支，没在真断网下实拍。

   弱网下的等待与"正在取…"提示没量化过。

## 追加（同日 12:40–12:58）：站主追问"图片问题也修复下"之后实测的三件事

站主贴了微信后台「request合法域名」的截图（里面确实有 `poe2-all-class.oss-cn-hangzhou.aliyuncs.com`），
要我把图片问题收尾。分开量了三件事，结论是**白名单不是原因，但列表页真的没图——那是界面的锅**。

1. **白名单**：`<image>` 直接访问媒体资源不查域名，只有 `wx.request/downloadFile/getImageInfo` 那类 API 查。
   本站小程序只用 `wx.request`（取清单与分片，域名已配）+ `<image>`（渲染素材），
   没有 `downloadFile` 调用，所以 `downloadFile合法域名` 空着不影响出图。
   顺带说明：开发者工具 `urlCheck` 是 `false`，所以"模拟器能显示"从来不是白名单的证据——
   这条靠读代码调用面得出，不靠模拟器。
2. **OSS 默认域名强制下载**：每个素材对象响应都带 `Content-Disposition: attachment` +
   `x-oss-force-download: true`；PUT 时显式写 `inline` 被覆盖，1,117 张全这样。
   唯一真解是绑自定义域名（要备案，走 wow-ops）。
   这个发现还修掉一个我自己埋的成本：`cmdAssets` 会把"远端 attachment ≠ 我要的 inline"判成元数据漂移，
   于是每次发素材全量重传 1,117 个对象。现在认出 `x-oss-force-download` 后不判漂移，
   并把这件事在输出里说一次（`素材：传 0 · 已存在跳过 1118 · 补正 0` 才是稳态）。
3. **列表页没图是真的**：38 座里 37 座有客户端原画，但 `art` 以前只进详情分片，索引里没有，
   副本列表整页空白。现在索引每条带 `art`（缺的那座是 `null`），主包快照同步带上，
   列表行左侧出 132×84 缩略图（`components/icon-cell` 新增 `wide` 档，懒加载，取不到回落自绘块）。
   实拍：`docs/screenshots/m02-2026-10-22/d1-list-art.png`、`d2-list-art-scrolled.png`。
   断网路径也验了：把取数地址指到必然 404 的前缀，列表仍 38 座、37 个 `artUrl`（来自快照），
   图本身取不到时回落自绘块，不摆空框。

**这一段的门禁**：`oss-release-test.js` 153/153（新增"索引带 art 且是 assets 相对路径""索引里的 art 都在素材层登记过"两条，
以及素材通道那条 `Content-Disposition: inline` 断言 + 幂等必须 PUT 0）；
`mini-m01-check.js` 41/41；`mini-m02-check.js` 23/23；`export-mini.js` 的索引逐字段对拍两边同步改完才绿。
