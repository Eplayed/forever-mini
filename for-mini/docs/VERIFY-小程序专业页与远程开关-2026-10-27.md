## 1. 开关为什么是一个单独的对象，而不是写在批次清单里

站主要求的是"不发版就能放出来一页"。指针 `wow/{env}/v1/manifest.json` 本来就是可变的
（`Cache-Control: public, max-age=60, must-revalidate`），最省事的办法是把 `features` 塞进那份清单。
**没这么做**，理由有两条，都是这一层自己定的规矩：

- `builds/{buildId}/manifest.json` 是**回滚位**，同一 buildId 必须逐字节恒定（`build --check-identity` 就是卡这个）。
  把随时要拧的策略写进去，等于每次改开关都要换批次号、重发整批数据。
- 回滚一批数据会**顺手把开关退回旧值**（回滚就是把那份自带清单指回去），
  "我把专业页关了一下，结果回滚副本数据把它又打开了"这种因果不能存在。

所以：**开关 = 与指针并列的一个可变对象 `wow/{env}/v1/flags.json`**，同一档缓存语义。

| 谁 | 路径 | 可变？ | 缓存 |
| --- | --- | --- | --- |
| 数据批次 | `builds/{buildId}/**` | 不可变（同路径不同字节绝不覆盖） | immutable 一年 |
| 指针 | `manifest.json` | 每次发批覆盖 | max-age=60 |
| **开关** | **`flags.json`** | **每次发开关覆盖** | **max-age=60** |

真源在仓库里是 `wow-forever-web/app/data/flags.json`；`flags.json` **故意不进 `BASE_INPUTS`**
（那条名单是"算进 buildId 指纹的构建输入"，改开关不许换批次号——由 `oss-release-test` 那条钉着）。

## 2. 怎么公开 / 关掉一页（操作口径）

```bash
# 1) 改真源里那一行： "professions": { "on": false } → true
# 2) 只发开关，不重跑数据、不发小程序版本
node wow-forever-web/tools/oss-release.js flags --env beta          # 先 --dry-run 看一眼
WOW_ALLOW_CROSS_CREDS=1 node wow-forever-web/tools/oss-release.js flags --env beta
```

约一分钟后玩家侧生效（对象本身 max-age=60 + 客户端每次进被门控的页与每次回首页都重取）。
`flags` 是写命令：照旧要 `WOW_ALLOW_CROSS_CREDS=1`，release 还要 `--yes-release`。

发之前构建端会核三件事（红在电脑前，不红在玩家手机上）：

1. `on` 必须是布尔、开关名只能是 `[a-z0-9]`、每条都要写 `name`（关着时界面要念出这一页叫什么）与 `note`；
2. `page` 指向的页面必须在 `for-mini/app.json` 的 `pages` 里——**页面没进代码包，开关拧 true 也打不开**；
3. `needs` 列出的数据入口必须在**玩家实际能读到的那一批**里（`flags` 子命令读线上指针核，`build/upload` 用本批核）。
   关着的页也核，只是话术不同："拧 true 之前先发数据批次"。

`rollback` 会拿目标批次重核一遍开关（回滚到一批没有这些数据的老批次 = 页面变空壳），
不核对不上就不动指针；`verify` 会比"线上开关 vs 本地刚构建的那一份"，
**改了 flags.json 忘了发，就在这里红**。

## 3. 客户端三层兜底（这是这一层唯一要紧的规矩）

`for-mini/services/features.js`：`live（远端这一条） > cache（上次存下的这一条） > local（打包默认表）`，
**逐条**落定，不是整份替换。

- 远端取不到 / 结构不对 → 用缓存；没缓存 → 用 `for-mini/data/flags-local.js`。
- 两个方向的错都不许犯：不许把已公开的页**关掉**（所以 `bis` 默认 true），
  也不许因为"远端没说关"把没公开的页**放出来**（所以没上线的页默认 false）。
- 缓存 key 是 `wow_forever_v1_flags_beta`（**不带 `@`**）：带 `@` 的键会被 `noteBuild` 当旧批缓存清掉，
  开关不是按批存的东西，被顺手清了就等于断网时没有兜底。
- 开关名集合与 `flags-local.js` 必须相等，由 `oss-release-test` 那条卡（写歪一个字母 = 静默走兜底，界面看不出差别）。

界面义务（写进下发对象的 `policy` 四条里）：关着的页只说"这一页还没开放"，
不许编"数据维护中"那种理由；入口卡关着时**整块不渲染**，不留空白格。

## 4. 专业线数据通道：1.5 MB 基底 → 手机上一次点一个专业

基底 `app/data/professions.json` 是 **1568 KB / 13 专业 / 1990 条配方 / 55 个采集点**，
不进主包快照（主包只剩 6.3 KB 余量），也不整份下发：

| 产物 | 体积 | 什么时候下 |
| --- | --- | --- |
| `professions/index.json` | 12.8 KB | 进这一页时一次（13 个专业 + 分箱 + 列名 + 出处） |
| `professions/set/{id}.json` | 0.2–65.8 KB，13 片合计 273.2 KB | 点开哪个专业才下那一片 |

最大一片是制皮 511 条 = **65.8 KB**（预算 80 KB，注释里写了下一步该干什么：按分箱拆片，不是抬预算）。
行用位置数组存，**图标 / 材料 / 商人 / 图纸字典就地带一片一份**（同一个商人在 500 行里重复 500 次是这份数据的主要体积），
分片按紧凑 JSON 写（`flat: true`）——同一份内容按缩进写会胖到 137.8 KB，纯数字数组不值这个流量。

构建时数出来并写进指针的数（不是抄基底的）：
`professions 13 · profRecipes 1990 · profNewRecipes 889 · profNodes 55 · profShards 13`。
卡口：基底自报的 `counts` 与实际拆出来的行数不等就红；配方行缺 ID 或缺名字就红；
材料平铺数组出现奇数长度就红；图标序号越界就红；
`rowsWithoutBand 29`（这四箱盖不住的进"技能档位没标出来"那一箱，界面照实显示）、`rowsWithoutIcon 14`（画自绘块，不猜图）。

**列名与分箱只在索引里写一份**：`cols` / `colNote` / `bands` / `skillKeys` 随索引下发，
13 片各抄一遍等于把同一句话复制 13 次。网页 `ProfessionsPage.vue` 里那两个常量由
`oss-release-test` 一条去 grep 对拍——两端飘了就红（红在测试，不把发布卡在一个文件的排版上）。

## 6. 这一轮真踩到的四个坑（都已修，都留了门禁或注释）

1. **`features.load(true)` 被签名吃成 env**：第一版写的是 `load(env, force)`，页面按直觉传 `load(true)`
   → 命名空间拼成 `undefined` → 请求必失败 → 永远走打包默认表，**而界面看不出任何不对**（开关"就是不生效"）。
   改成只收一个参数 `load(force)`，注释写清为什么。**这类错的特征是"改了没反应"而不是"报错"**，
   只看界面永远查不出来，得把请求 URL 打出来看。
2. **回归脚本往 `for-mini/` 里写开关** → 开发者工具 `compileHotReLoad` 把小程序打回首页，
   制造一片"路由没到位"的假红（这个坑 AGENTS.md 只写在截图那一段，这次轮到写文件了）。
   给假 OSS 加了 `FAKE_OSS_FLAGS_FILE`：开关那份放 `/tmp`，代码与批次数据一个字节都不动。
3. **内部脚本名漏到玩家界面**：页头副标题原本渲染 `meta.method`
   （"tools/scrape-wclbox-prof.py --write 抓 → tools/merge-professions.js 整形"），实拍里一眼看见。
   分发层不再下发 `method`（第一次只删了模板引用，测试那条"meta 里不许有 tools/ 与 .py/.js"把它逮住了——
   字段还在产品里），模板改渲染 `meta.took`，门禁同时钉"索引里没有 method"与"模板不引用它"两条。
   —— 又一次证明：**只看 data 不看图，看不见这种错**。
4. **草药点那一行在重复名字**：30 行"可得的就只有它自己"，实拍里每一行都是「宁神花 / 宁神花 / 区域」三行。
   改成与采集点同名时不显示那一行，采矿那种一矿多料照旧列全（m01 两条各钉一边）。
5. **探针自己的假红**：`p.pickProf(); var o = {...}; setTimeout(() => r(o))` 拿的是**同步快照**，
   读到的是切换前那一刻的空数据，看起来像"草药学 0 个采集点"。改成到点再读 `p.data`。
   页面本身顺手补了一个 stale-callback 守卫（换专业时把上一片的解码结果清空 + 排号），
   筛选回调是异步的，不挡就会拿旧专业的 0 条覆盖新专业刚画出来的表。

## 7. 公开这一页之前必须修的数据缺陷（交 wow-data）

**钓鱼那一档的表头被当成了名字**。基底里 fishing 的 6 行是：

```
nameCn: "25"   yields: ["一开始"]  zone: "丹莫罗、艾尔文森林…"
columns: { 稳定上钩: "25", 开始咬钩: "一开始", 区域: "…" }
```

源表那一页是"技能数 / 开始咬钩 / 区域"三列，采集时把第一列塞进了 `nameCn`，
于是界面上"水域"这一栏列出来的是 25 / 75 / 150 三个数字。
**网页那一版同样错**（同一份基底），不是这次编码引入的。
处理方式：不机翻、不编一个名字，等 wow-data 重排这一档的列映射（`tools/scrape-wclbox-prof.py` 的 fishing 分支）。
开关现在关着，所以线上没有玩家看到它；**要公开这一页，先把这条修掉**。
