## 3. 构建时卡住的红线（不是"界面小心点"，是产不出来）

- **没来源就不下发**：一条宏必须有 `url + checkedAt` 的 provenance，缺的按"待核"丢掉并计数（本批 `droppedNoSource=0`）。
- **强度与循环指导类词**：标题/说明里出现"秒伤 / DPS / 权重 / 更好 / 优于 / 推荐顺序 / 性价比 / 循环提示"直接构建失败。
- **交易类词**：宏产物里出现"收费 / 购买 / 会员 / 付费"失败（我们自己的免责句"不收费"不在扫描范围内——扫的是行数据与分组名，不扫 meta）。
- **正文不许有链接**：宏正文是要原样粘进游戏的，出现 `http` 就是异常。
- **百分比这条口径写清了边界**：红线拦的是"本站算出来的掉率与强度评分"，不是插件抄来的技能效果句。
  "断筋减速 40%""威慑 +25% 躲闪"这类是技能自己的数值，网页那 245 条已按这个口径上线，小程序不另立更严的一条把同一条内容判成两端不一致；
  但**宏正文**里出现百分比一定拦（正文里没有这种语法）。这个数不藏：索引里 `counts.percentInNotes = 4`。
- 行解码防漂：`cols` 只有一份，分片不抄列名；`src` 指不到来源条目的行 → 构建失败。

## 4. 页面长什么样（`for-mini/pages/macros/index`）

- 进这一页只取 **1 次索引 + 1 片当前职业**（点哪个职业才取哪一片，不会一把拉 9 片）。
- 顶部固定显示分发层下发的那句口径（"第三方插件整理…本站没有逐条进游戏试过"），页面不改写措辞。
- 九职业 chips（带条数）+ 关键字搜索（标题/说明/**宏正文**都参与）+ 该职业自己的用途分组 chips + "清掉筛选"。
- 列表一行：标题、"新"角标（无限新增）、说明、用途、几级起、谁整理的。一屏 40 条，"再显示 N 条"往下放（setData 有 1 MB 上限，专业页 511 行炸过一次）。
- 详情底弹层：宏正文**原样多行**（`white-space: pre-wrap`，可选中）、`复制宏文本`、`复制来源`（名字 + 文件 + 核对日）、
  有法术名退回插件烘的那一份时如实标出来。没有编辑框、没有执行按钮、没有外链。
- 空态分两种：这个条件下没结果 → 说"换个用途或清掉筛选"；这一职业本来没宏 → 说"这一职业的宏还没整理，不拿别的职业凑数"。
- 离线：明说"宏命令要联网才取到，这一页没带在小程序里"。
- 迟到的那片不许盖掉刚选中的职业（`this.data.cls !== classId` 就丢）。

## 8. 职业条补上图标（2026-10-30 22:40，站主："小程序宏命令页面加入职业的图标"）

原来九职业是一排文字 chips（名字 + 条数）。现在换成**与配装页同一副长相的职业条**：
横着滚的一排小卡，每张是 `icon-cell`（职业图标）+ 职业名 + "N 条"，选中的那张描金边。
同一件事在两端就该长一个样，所以样式与尺寸直接对齐 `pages/bis` 的 `.rail/.rtab`，没另立一套。

**图标键不自己造名字**：`macros/index.json` 的每个职业条目带一个 `iconKey`，
值是从同批的 `classIndex` 里取的（`class_warrior` 这种）。两处各抄一遍字符串，
迟早一端漂了另一端还绿着；取不到 iconKey 时构建直接报错（"职业条会缺图"），
并且每个键都过一遍 `useIcon(...)` 登记——这样"界面会拼出来的地址这一批必须登记过"
那条反向卡口会一起管到宏这一页。

客户端拼的是 `oss.iconUrl(batch, iconKey)` → `assets/icons/class_warrior.jpg`，
图标本身早就在素材层里（M02-1 那批，`app/img/icons/class_*.jpg`），**这一轮没有新增任何图片上传**；
公网直取三个抽验都是 `200 / image/jpeg`（class_warrior 2,106 B、class_druid 2,239 B、class_paladin 2,635 B）。
`icon-cell` 自带兜底：图取不到时显示职业名首字，不会留空格子。

索引因此从 4.0 KB 长到 5.4 KB（预算 24 KB，余量还很大）。
m01 那条判据同步加硬：不只是"九个 chips"，而是**九个 chips 每个都带得出 http 图标地址**——重跑到 **106/106 通过**。
