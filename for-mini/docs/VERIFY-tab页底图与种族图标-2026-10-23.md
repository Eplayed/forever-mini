## 三、本轮抓到并修掉的一个真 bug：底图把名单糊住了

先按 `position: fixed` 写，实拍发现图钉在屏幕中间、中段名单压在亮云图上；改成 `position: absolute`
锚在页面顶部。**改完 DOM 量着一切正常，屏幕上名单却整片不见了**：

- 同一页"有底图 / 撤掉底图"两张截图，`boundingClientRect` 读回来文字位置一模一样（第一条都在 100pt）；
- 像素上一段段数字对过去：撤掉底图那张有 15 段亮字，有底图那张只有 2 段。

原因在 CSS 绘制顺序：**非定位元素会被 `z-index:0` 的定位层盖住**。只给 `.wrap` 加 `z-index`
抬的是"整页相对页面根"，不是"内容相对它自己的那两个底图层"。
首页本来就是靠 `.fg { position: relative; z-index: 1 }` 浮起来的，新加的两页没抄这一层。

修完复测：两页各 15 段亮字，位置逐段对得上。

这条落成两道门禁：① 静态查"每个定义了 `.pagebg` 的页面必须有自己的 `.fg`"；
② 跑真页面时三页各做一次"有底图 / 无底图"的名单区亮字像素比对，差超过 6% 就红。

## 四、暗夜精灵：实测过才动，没动别人的

官方 CDN 今天直接打状态码：`race_nightelf_male` / `race_nightelf_female` / `race_night_elf_male` /
`race_darnassian_male` **四个候选全 403**（官方 CDN 的 403＝没有这个文件），对照组 `race_human_male` 200。
所以 `races.json` 里那条 `iconKey: null` 是对的，不是漏填。

用的是库里本来就有的 `src/img/art/races/night-elf.webp`（128×128 客户端种族头像，
2026-10-12 那批转存、`art.json.races` 有它、manifest 早记过来源，网页种族页一直在用）——
**没有为它新开任何素材授权**。

分发层 `raceEntry()` 的取图顺序定成三层并写进注释：官方 CDN 的 `iconKey` →
`art.json.raceIcons`（10-20 单独授权那张插件天裔小图）→ `art.json.races`（本站已在库的 128 头像）。
顺序不能反：反了会把另外 8 个种族的官方 CDN 图标全换成第三方转存，那是往红线上踩。

## 六、没验到的（要人过一遍）

1. **真机 `<image>` 认不认 OSS 默认域名的 `Content-Disposition: attachment`**——老问题，
   本轮底图还变大到 95 KB，真机不过关就是硬门槛。三个修法（绑自定义域名 / 换 CDN / 转 base64）没拍板。
2. **三页共用一张图好不好看**：我只按"top 居中 + 沿用首页那层 0.88 压暗"做了，
   副本页与职业页信息密度不同，要不要各换一张或压得更暗，得站主在浏览器里看一眼。
3. **暗夜精灵那张清晰度会和另外 8 张不一样**（128 客户端头像 vs 56 官方 CDN 图标）。
   要不要 10 个种族统一换成 `art/races/` 那套，是口径选择（更清晰，但主值就从官方 CDN 换成第三方转存）。
