## 判定

**BLOCKED（需要真机）／A 未通过 —— 提示词 B、C 暂不发。**

两条独立结论：

1. **这台机器的微信开发者工具跑不起 xr-frame**：连官方文档里那个"只有相机、清屏色是绿的"最小场景
   都拿不到 `bind:ready`，画布只有一块黑。所以**模型能不能画，在模拟器里根本问不出来**。
2. **原件这份 GLB 在微信端注定读不出来（静态判定）**：基础库自带的 glTF 加载器对
   `extensionsRequired` 的策略是"不认识就直接抛 `[GLTF]required extension "x" not supported."`"，
   而 `EXT_texture_webp` 在 3.17.0 与 development 两份基础库包里**一次都没出现**
   （同一张扩展表里 `KHR_texture_transform` 有 12 处命中）。
   → 就算 xr-frame 起来了，这份声明了 required WebP 扩展的原件也会抛错。

按任务书口径：开发者工具跑通最多只算 `SIMULATOR_PASS`，这里连它都没过；
真机未验，**不写 PASS**。

## 2. 探针怎么搭的（三条配置事实，缺一条就"静默不工作"）

- 页面 `for-mini/pages/model-probe/index.*` 只做宿主；场景在**自定义组件**
  `for-mini/pages/model-probe/scene/index.*` 里，组件 json 必须写
  `{"component": true, "renderer": "xr-frame"}`。页面 json 里写 `renderer` **不生效**，
  `<xr-scene>` 会退化成一个空盒子且零报错。
- `for-mini/app.json` 需要 `"lazyCodeLoading": "requiredComponents"`（官方社区答复与多份独立教程同一条）。
- **`packOptions.ignore` 里不能加 `pages/model-probe`**：页面还在 `app.json` 的 pages 里却被排除出包，
  整个小程序会直接起不来（`getCurrentPages()` 空）。样本目录 `tmp-model` 可以 ignore，页面不行。
- 探针要验的两份文件放在 `for-mini/tmp-model/`（已进 `packOptions.ignore`，不进发布包）：
  原件与 PNG 候选，页面顶部一键切换；页面上还有"重建场景（退出重进）""转 ±60°"两个动作。
- 场景配置：相机 `position="0 1.2 2.4"`、`target` 在 `0 1 0`、`near 0.1 / far 200`、
  `camera-orbit-control=""`（手指拖动转视角就靠它）、一盏环境光 + 一盏平行光。

## 4. 兼容候选（A4 分支）：只换贴图编码，几何逐字节照搬

工具：`python3 wow-forever-web/tools/derive-glb-textures.py --file img/models/real/hunter-alliance.glb --out … --format PNG`

脚本先核三件事才动手：文件在 `art.json.bisRealModels` 登记里、`placementVerdict=PASS`、
源文件 SHA 与登记一致——任一不符直接退出，不许拿未登记的模型转候选。
改动只有一处：每张内嵌 WebP 解码后重编码为 PNG、`images[].mimeType` 改 `image/png`、
`textures[].extensions.EXT_texture_webp.source` 搬回标准 `source`、删掉 `extensionsUsed/Required` 里那一项。
顶点、索引、材质参数、节点、accessor 一律不动（脚本末尾自己跟源文件比一遍）。

| 项 | 值 |
| --- | --- |
| 产物 | `for-mini/tmp-model/hunter-alliance-png.glb`（临时目录，不进包） |
| 字节 | **982,480 B**（源 405,940 B，**2.42 倍**） |
| SHA-256 | `46d8e7cc0bd1f707e201998d01ad06562f526af094baaa108d91e293b26a278c` |
| 等价性证明 | accessor 32 项元数据逐项一致；几何 bufferView **0 处**字节不同；10 张贴图 **逐像素全等**（RGBA 数组相等）；`meshes/nodes/materials/accessors/samplers` 的 JSON 段与源完全相同；图片头 `RIFF` → `\x89PNG`；候选不再声明任何 required 扩展 |

**这条对提示词 B 的直接影响**：若 76 份都要走 PNG，体积从约 35.3 MB 涨到约 **85 MB** 量级
（单份 405,940 → 982,480 B）。要么改用 JPEG 候选（体积小得多，脚本 `--format JPEG` 支持），
要么把"每套一份"改成"每阵营一份共享身体"。这笔账在真机结论出来之前不决定。

**一处撞车要报备**：同一套"拆 GLB → 重编码内嵌贴图 → 重写 bufferViews"的管线，
`tools/optimize-bis-glb.py`（另一条会话在做，方向相反：把贴图**压成 WebP** 给网页省流量）里已经有一份。
两条方向共用一份解析迟早飘，合并成一条命令（`--texture-format webp|png|jpeg`）是该定的事；
本轮不擅自改别人手上的脚本，先把两份并存的现状记在这里。

## 5. 要站主做的真机验证（这一步我做不了）

1. 开发者工具里点「预览」或「真机调试」，用手机微信扫码。
2. 打开页面 `pages/model-probe/index`（临时页，没有入口，可在真机调试里直接输路径）。
3. 看四件事，逐条回传：
   - 顶部状态文字：`准备加载 / 场景就绪，取模型中 / 加载中 N% / 加载成功：贴图都在 / 半成功… / 失败…`
   - 出现"失败"时，把「失败原文」那一整段抄回来（尤其是 `[GLTF]required extension …` 这类话）
   - 默认那份（原件 · WebP 贴图）能不能看到人；点「候选 · PNG 贴图」后能不能看到人
   - 手指在画面上左右拖动，人物会不会转；点「重建场景（退出重进）」后还能不能再次加载
4. 两台都要试（至少一台 Android、一台 iOS）——xr-frame 在两端走的内核不一样。
5. 结果判定口径：只有真机看到"帽子 / 双肩 / 胸与披风纹理 / 枪的位置"都对，才记 `PASS`；
   模拟器过只记 `SIMULATOR_PASS`。

## 6. 没验到的

- **真机一切未验**（本机没有可自动化的真机通道；`SIMULATOR_ONLY` 都不成立，因为是失败而非仅缺真机）。
- iOS/Android 的 WebGL2 与显存差异、拖动帧率、退出重进的显存释放。
- `<xr-asset-load>` 走网络时的域名/HTTPS 与真实 AppID 真机行为（本轮用的是包内本地路径，
  没测到"从 OSS 拉 GLB"这条路——那是提示词 B 的事）。
- PNG 候选在真机上是否真能加载（模拟器无判别力，见上）。
