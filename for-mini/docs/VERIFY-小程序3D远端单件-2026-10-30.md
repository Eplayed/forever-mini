## 2. 扫码预览工程：包内一份模型都没有

B1/B2 的分工是"先证明取法，再证明整批"。所以这次的隔离工程 `xr-probe-remote/` **不含任何 GLB**：

```

  https://poe2-all-class.oss-cn-hangzhou.aliyuncs.com/wow/beta/v1/assets/models/real/hunter-alliance-44747dcb05cb.glb
```

- 生成器自查：产物里出现任何 `.glb` 就直接报错（怕"包内还留着一份"演成远端成功的假证据）；烘进去的地址必须真的出现在页面里；每个生成的 js 过一遍 `node --check`。

- 工程 `pages[0]` 就是探针页（扫码直接落这一页），`packOptions.ignore` 是空数组，AppID 与正式小程序同一个（`wxfd9a2b985a6cedc3`），`urlCheck: false`。预览码：`for-mini/docs/screenshots/xr-probe-remote-2026-10-30/qr-远端单件.png`（约 25 分钟过期，重跑上面那条 + `cli preview` 就能再出）。

页面这次多了两档（真源 `for-mini/pages/model-probe/`，`app.json` 里那条临时路由没进首页、也不发给玩家）：

- **④ 远端 HTTPS**：把这条 https 地址**直接交给 `xr-asset-load`**——这就是 B3/C 要用的取法。
- **⑤ 先下载再加载**：先 `wx.downloadFile` 落到本机临时路径，再把临时文件交给场景——④ 失败时的备胎。两条路**各自一条结论**，谁成谁说，不许互相冒充。

## 4. 给站主的四步（扫码前后）

1. **先确认这台手机的开发版能出网**：小程序后台 → 开发管理 → 开发设置 → 服务器域名，`downloadFile` 与 `request` 合法域名里要含 `https://poe2-all-class.oss-cn-hangzhou.aliyuncs.com`；没有的话先在手机上开**开发版调试**（扫码后进小程序 → 右上角胶囊 → 开发版调试），否则第一拦是白名单、跟 xr-frame 无关。
2. **扫①空场景**：画面应是那一格绿（`0.4 0.8 0.6`）。不绿/不 ready，就还是 xr-frame 本身起不来，后面两档不用测。
3. **点④**：等状态从"从远端取"变成网格/贴图计数。要留的证据：人物是否出现、贴图是否有、帽子/肩/胸/披风/枪的位置、画面上那行 `当前文件` 是不是那条 https 地址、`失败原文` 框里的完整错误。
4. **点⑤、再点"重建场景（退出重进）"**：⑤ 那行会打印 `downloadFile：HTTP 200 · 字节 · 毫秒 · wxfile://…`，这是与 ④ 独立的一条结论；④⑤ 各成功一次后，用手指左右拖动（转人物）、再点重建看能不能复载。每台设备都记：机型、微信版本、基础库版本（页面顶部那行有）、截图。

判据分档，别互相顶包：

| 现象 | 说明的是 |
| --- | --- |
| ① 不 ready | xr-frame 在这台设备/这版基础库起不来，与 OSS 无关 |
| ④ 报"不在合法域名列表" | 域名配置问题，不是格式问题；此时⑤也会同样失败，先修门票 |
