## 1. 这一页现在是怎么表现的

进配装页：中间那一栏还是**职业原画**，一个模型请求都不发。多了两颗按钮：
「查看 3D」（真实模型，走远端）和原来的「看占位模型」（本站自拼的 2D 人台，那句"不是游戏里的样子"照旧留着）。
两种模式**互斥**，不同时出现——两块画面叠在一起玩家看不出在看哪个。

点「查看 3D」后依次发生：

1. 取 `wow/{env}/v1/bis/models/index.json` 那一份独立清单（与开关同一档可变对象，`max-age=60`；一分钟内切套切阵营不再重复取）。
2. 按当前 `setId + faction` **精确匹配**一条，然后过三道闸：
   - `placementVerdict` 必须是 `PASS`；
   - 清单里的 `dollSnapshot` 必须与**当前套装这一阵营的 doll 逐格**（部位/格号/物品 ID）相同；
   - 文件名里那 12 位哈希必须就是 `pngSha256` 的头 12 位（客户端没法给下载回来的 GLB 算哈希，但这一条能拦住改过的清单）。
3. 三道全过才把 https 地址交给组件，组件挂上后 xr-frame 才真的去下载那**一件**。

任一闸不过 → 回职业原画 + 一句「3D 暂不可用」＋具体原因（"这一套没有登记的真实模型"/"逐格没对上，不借用别的套装"/"位置没通过核对"）。
**没有任何一条路径会去取别的套装的模型**：这一层不接受"最接近的那一条"这种写法。

只有当前这一件真的画出来（网格数与贴图数都核过），下方才出现那句
「游戏角色与装备的静态预览，拖动可旋转」，并带上种族/体型与网格·贴图计数；
加载中途显示进度文案，失败立刻收回原画。

## 2. 用哪条加载方法（B2 已验的那一条，没换参数）

`for-mini/components/bis-3d/` 这份 xr-frame 场景组件是把 B2 那台 Android 真机验过的场景标记**原样**搬过来：
同样的 `<xr-asset-load type="gltf">`、同样的相机位置 `0 1.2 2.4` / target `0 1 0`、同样的清屏色与两盏灯、
`camera-orbit-control` 负责手指拖动旋转。参数一改就不再是"那条已被证实的方法"。

组件 `index.json` 必须是 `{"component": true, "renderer": "xr-frame"}`，`app.json` 保留 `lazyCodeLoading: requiredComponents`
（2026-10-30 实测：页面 json 里写 renderer 不生效，`<xr-scene>` 只会变成一个空盒子且零报错）。

**只有一个可拖动预览**：没有近战/远程切换、没有正/背按钮，BiS 清单照旧列全装备（战士那一套 16 行、属性合计 4 行没变）。

## 3. 拆与重建（切套不能留旧画面）

`teardownModel()` 做两件事：**`_seq` 自增** + 把 `modelOn/modelSrc` 清空（组件随之卸载、场景销毁）。
所有在飞的回包（清单回包与组件的 status 事件）落地前都先比 `_seq`，号不对直接丢。

- 切职业、切套装：都经过 `loadSet()` → 先 `teardownModel()`。
- 切阵营：`pickFac()` 先 `teardownModel()`（阵营换的是另一条登记，不能沿用旧场景）。
- 离开这一页：`onUnload()` → `teardownModel()`，不把 xr 场景留在后台。

## 5. 契约测了什么（29/29）

新增 `wow-forever-web/tools/mini-bis-model-test.js`：假 `wx`（可控网络与 storage）+ **B1 那份真清单**（76 条），
纯逻辑跑，不打网络、不碰 bucket、不往 `for-mini/` 写东西。覆盖：

- 正常命中：hunter/alliance 拼出的就是那条 https 地址；一分钟内切套不再取清单。
- 不许冒充：不存在的 setId、写错的阵营值 → `ok:false` 且没有 url，不会"挑一条相近的"。
- 名单变了就拦：**少一件 / 多一件 / 换物品 ID / 换格号** 四种都拦下；只换行序不误拦（不能因为排序把能用的模型关掉）。
- `placementVerdict` 不是 PASS → 拒绝；文件名哈希段与 `pngSha256` 脱钩 → 拒绝。
- 路径防穿越：`assetDir` 改成 `../../etc/`、`file` 带 `../`、带 `?x=1`、不是那个形状 → 一律拼不出地址。
- 同一 `setId+faction` 出现两条 → 拒绝（不"取第一条"）。
- 契约与结构：`schemaVersion` 比客户端新、`formatVersion` 不是 `glb-png-v1`、`product` 不对 → 整份拒用，不当半份可信。
- 断网：有缓存照旧给同一件并标 `cache`（不谎称实时），缓存超过 60 秒那一档要标 `stale`；没缓存就明说"取不到模型清单"。
- 清单 404 → 走失败分支。

## 6·5 第一次真机回件改判了的那件事（2026-10-30 17:00）

站主第一次扫回来的是这句：**「3D 暂不可用：一个贴图都没建出来（白模）」**（战士·PvE·部落）。
当场查下来这条**判错了**，两件事叠在一起：

1. 那份文件本身没问题：`warrior-horde-298657ed26bf.glb` 里 11 个材质**全部**带 `baseColorTexture`，
   20 个面片引用的也都是带贴图的材质（本地直接解 GLB JSON 数的）。
2. 组件能报出"网格数"，说明远端下载、GLB 解析、实例化**都过了**；是我读贴图的那条 API
   （`material.getTexture('u_baseColorMap')`）在这台设备这版基础库上没读到东西，量到 0 就判成失败，
   并且**立刻把画面收回原画**——肉眼这个主证据被我自己抹掉了，只剩我一把错尺子的读数。

改法（这一条比"修对 API"更要紧）：**量不到贴图不等于失败**。现在分三档——

- `ok`：网格在、每张都数到贴图 → 才说那句「游戏角色与装备的静态预览，拖动可旋转」。
- `geometry`：网格实例化了、贴图数到 0 或不全 → **画面留着**，下面一行黄字写
  「画面已经出来了：网格 N 个已实例化，贴图本站数到 M 张」，并把 `gltf / mesh[0] / material`
  三层的**真实字段名**一起打出来（下次照它改准，不再猜），同时明说"看着是白模请截这一行给我"。
- `bad`：结构真没起来（取不到 xr 运行时 / 没有 hero 节点 / 没有 GLTF 组件 / 0 个网格 / 资源报错）→ 才回原画。

贴图读取也改成多路试：`getTexture` / `textures.*` / 直接属性 / `getUniformValue`，
名字试 `u_baseColorMap`、`u_baseColorTexture`、`baseColorMap`，并记下**是哪条路读到的**（`@via` 进日志）。
m01 加了一条反例钉住这个行为：**"贴图尺子量空了"不许把画面藏掉、也不许冒充成功那一句**。

## 6·6 判据再改一次：量不到网格也算"已显示"（2026-10-30 17:21）

站主用**同一个探针页**去取配装页当时取的那一份（`warrior-horde-298657ed26bf.glb`），
回件是一张截图：画面里是**带贴图的兽人**（护甲、肩、靴、武器花纹都在），
而同一屏的数字写着 `网格 0 个 · 有贴图 0 个 · 无贴图 0 个 ｜ GLTF=true version=0`。

两件事同时成立，结论就只有一个：**这台设备上 xr-frame 在 `bind:loaded` 那一刻还没把网格列表交出来**
（`version=0`），我却把"数到网格"当唯一的成功判据——于是把一个正常画面判成"白模失败"并收回原画。
设备元数据（截图里读到）：机型 `25098PN5AC` · Android 17 · **基础库 3.17.6** · 微信 8.0.79。

现在的判据（这一条比"修对字段名"更根本）：

| 状态 | 触发 | 界面 |
| --- | --- | --- |
| `ok` | 重试后数到网格且每个网格都有贴图 | 画面 + 那句 caption + 网格/贴图计数 |
| `shown` | 资源 `loaded` 且没报错，但网格/贴图没数全 | **画面留着** + 同一句 caption + 一行"本站数到网格 N / 贴图 M，量不全以肉眼为准"和读到的字段名 |
| `bad` | 取不到 xr 运行时 / 没有 `hero` 节点 / 没有 GLTF 组件 / 资源或场景报错 | 回职业原画 + 「3D 暂不可用」＋原文 |

量之前先按 150 ms 重试最多 12 次（网格是晚一帧才有的）。探针页那份场景组件同步改了措辞，
不再写"失败：一个贴图都没建出来（白模）"。m01 里那条反例改成喂 `shown`，
判据从"不许藏画面"升级成"**量不到也算已显示**"。
